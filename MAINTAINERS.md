# Maintainers

Deep Monkey Studio is stewarded by the owner of [fatasia/bim-studio](https://github.com/fatasia/DeepMonkey-Studio). This file identifies responsibilities; repository permissions remain the authority for who can merge or publish.

## Responsibilities

| Role | Responsibility | Public contact |
| --- | --- | --- |
| Project Steward | Direction, maintainer appointments, governance and license policy | [@fatasia](https://github.com/fatasia) |
| Maintainers | Triage, technical review, releases and security response | The relevant Issue or Pull Request |
| Reviewers | Review the affected module and verify evidence | The relevant Pull Request |

No additional named maintainers are listed yet. Contributors can work on any module; an assignment or review request does not grant merge rights.

## Becoming a maintainer

A contributor can request a maintainer role through a public governance Issue describing their contributions, proposed scope and availability. The Project Steward reviews the request, records the decision and updates this file when appointing someone. Access should cover only the agreed responsibilities.

Maintainers should identify another reviewer when a change exceeds their expertise, disclose conflicts of interest and avoid approving their own changes. Before stepping back, hand over active reviews, release work and private reports to the Project Steward. Remove inactive access and update this roster as part of the handover.

See [governance](GOVERNANCE.md) for decision authority, [the maintainer handbook](docs/maintainer-handbook.md) for routine work and [security policy](SECURITY.md) for private reports.
