## 1. 实例变换管线：Float64 → GPU 的全部精度降级点（审计项 1）

生产链：作者 Three 层级（f64）→ RenderPacket 实例 f64 矩阵 → localizePacket（f64 减法+fround）→ `packInstanceBatches`（f32 打包）→ GPU buffer → WGSL（f32 顶点变换）。逐点列出：

| # | 降级点 | 位置 | f64→f32 方式 | 大坐标下是否有害 |
|---|---|---|---|---|
| D1 | 作者实例矩阵 | `ThreeProjectionBridge.ts:288`（`Float64Array.from(resolvedTransform)`） | 无（保持 f64） | 否 |
| D2 | 浮动原点平移 | `cameraRelativeCoordinates.ts:38-39`（`localFloat(t - origin)` = fround+0.001 预算） | fround | **无害且有益**：把平移从 1e6 量级压到 ≤±1750，量化误差 1e-8～1e-9（实验 A） |
| D3 | 实例打包 | `instanceTransform.ts:6-9`（`packTransform` 对 16 分量逐个 `Math.fround`，行 27–32 写入 `Float32Array`） | fround | 定位后平移 ≤±1750，ulp ≤ 1.2e-4 ✓；**若绕过 backend 直喂 `PbrRenderer`**（公共导出可达），1e6 平移误差 5e-3、1e7 误差 0.4（实验 A） |
| D4 | 法线矩阵（逆转置） | `instanceTransform.ts:13-23`（对**已 fround 的 3×3** 求逆转置再 fround，行 19–21） | fround | 与平移解耦（平移不进 3×3），最大角误差 8.5e-7°（实验 C）✓ |
| D5 | GPU 上传 | `packetBufferStaging.ts`（staging Float32Array → `writeBuffer`） | 原样 f32 | 同 D3 |

| D7 | WGSL 顶点变换 | `pbrShader.ts:91`（`out.world = f32(dot(row,p))`）、行 92（`clip = f32(VP*world)`）、行 95（viewDepth） | 着色器 f32 | 定位后 world 局部小量 ✓ |

**结论**：实例变换主链路（D1→D8）在大坐标下**设计正确**——定位先行，f32 只接触局部小量。前提是宿主必须经 `DeepWebGpuBackend`；直接消费公共导出的 `PbrRenderer` 且传世界系包/视图时无任何拦截（`renderPacketValidation.ts:12-14` 的 `finiteFloat32` 只查有限性不查量级），此为合同缺口而非代码缺陷。

## 2. 相机矩阵：灾难性消除（审计项 2）

- `cameraMath.ts:11-19` `lookAt`：基向量 x/y/z 由**方向**构建（平移无关），平移列 `-dot(x, eye)`（行 17）在 f64 计算后**一次性 f32 存储**——大 eye 下该存储误差即灾难性消除源头（`W=1e6` 误差 9.3e-3、`1e7` 误差 0.157，实验 B-2），随后 `VP*world`（`cameraMath.ts:35-41` `multiply`，f32 逐项累加）把 `~1e6` 的项相消，f32 误差直接进入近处几何的 clip 坐标。
- **定位路径下已消解**：`updatePbrFrameUniforms`（`pbrFrameUniforms.ts:55-57`）收到的 `view.eye` 是 backend 定位后的局部 eye（|eye| ≤ 750+1000），平移列量级 ~1e3，f32 误差 8e-6，相对 2 单位视距误差 0.0004%（实验 B-2 末节）。
- 反事实量化（若不经定位，实验 B-1，1920×1080 / fov45° / 同一世界点）：

| W | 视距 | 无定位绝对位置误差 | 0.01 细节还原误差（无定位） | 有定位绝对误差 | 有定位细节误差 |
|---|---|---|---|---|---|
| 1e5 | 2 | 3.9e-9 px | 7.7e-2 px | 3.9e-9 px | 9.1e-9 px |
| 1e6 | 2 | 0 px（该配置凑整侥幸） | **2.01 px（细节全毁）** | 0 px | 2.5e-8 px |
| 1e7 | 2 | **137.1 px** | **2.01 px（细节全毁）** | 2.5e-7 px | 5.6e-8 px |

- `multiply`（`cameraMath.ts:35-41`）f32 累加：定位坐标下每项 ≤ 数百，误差 ≤ 1e-4 量级 ✓（实验 B 各"有定位"列已含该误差，仍 ≤2.5e-7px）。
- **结论**：视图矩阵灾难性消除风险已被浮动原点**结构性消解**；残余风险仅为"绕过 backend 的旁路消费"（见 §1 结论）。

## 3. 风险点清单（按严重度）

### R1【高】光源不在浮动原点定位合同内
- **证据链**：光源以**作者世界系**进入渲染——`threeWorldLights.ts:166`（`positionWorld: worldPosition(source)`，来自 Three light matrixWorld）；`DeepWebGpuBackend.localizeView`（`cameraRelativeCoordinates.ts:30-32`）**只换 eye/target，不换 lights**；`pbrRenderer.ts:489,512` 用**局部** `worldToView` 变换**世界系**光位：`transformWorldLightsToView(sceneLighting.clustered, frameState.worldToView)`（`worldLights.ts:82-114`，行 88/93/102 `transform(worldToView, light.positionWorld, true)`）。
- **后果**：视图空间光位系统性偏移 `-R·frame.origin`（每轴可达 ±1000 量级）→ Forward+ 聚类点光/聚光/面积光照明位置错位（照明出现在错误物体上/丢失）。
- **同级问题**：局部聚光阴影相机直接用世界系光位（`localSpotShadowSelection.ts:88` `lookAt(light.positionWorld, ...)`；绘制却在 `localSpotShadowRuntime.ts:151-152` 用**局部**实例数据）→ 阴影投影视锥体与几何错开 origin 量级 → 大坐标+非零原点帧内聚光阴影图整体失效；authored 方向光阴影矩阵为宿主世界系 4×4（`authoredDirectionalShadow.ts:16`，采样 WGSL `pbrShader.ts:99` `deepAuthorShadowCoordinate(out.world /*局部*/)`）→ 同类错位。
- **量化**：偏移量 = 当前帧 origin（1000 的整数倍，每轴），实验 A 证明该量级下 f32 本身不是问题——问题是**两个坐标系相乘**。触发条件：相机离原点 >750（`REBASE_DISTANCE`，`cameraRelativeCoordinates.ts:12`）且场景含点光/聚光/面积光/authored 阴影。
- **结论**：定位合同覆盖了"几何+相机"，漏了"光源"。修复方向（供参考，本次不改码）：`localizeView` 同步平移 `lights.points/spots/areas.positionWorld` 与 authored 阴影矩阵平移列。

### R2【高】CPU 拾取命中点以局部坐标系出域（世界语义丢失）
- **证据链**：`StudioDeepWebGpuBridge.ts:486` 射线原点先 `backend.worldToRenderLocal(origin)`（✓ 与 GPU 数据同系）；`picking.ts:170` 命中点按 `ray.origin(局部) + t·dir` 计算 → **hit.point 是渲染局部坐标**；`StudioDeepWebGpuBridge.ts:499` 直接 `new THREE.Vector3(...hit.point)` 当**作者世界坐标**返回——`backend.renderLocalToWorld`（`DeepWebGpuBackend.ts:437`）**全仓生产代码零调用**（grep 证据）。
- **消费面**（`viewerEnginePointer.ts`）：行 248 `best = deep.hit`；行 328 指针信息 `world: toValue(hit.point)`（显示错值）；行 371-374 原语放置 `position = hit.point.clone()`（放置位置偏移一个 origin，即 ±1000 量级）；标注/剖切同链路。距离、实例身份不受影响（刚体平移不变量）。
- **量化**：偏移 = 当前帧 origin（实验设置 origin=[1000,0,0] 时命中点 x 系统性差 1000）；小场景（origin=[0,0,0]）无症状，属**潜伏缺陷**。
- **拾取数学本身**：`picking.ts` 全程 Float64Array f64（行 105-107、194-220 Möller–Trumbore），误差唯一来源是实例数据的 f32 量化（与 GPU 同源 D3/D5）：仿真显示无定位时 1e7 下距离误差 0.25（三角形被量化推出射线），定位后误差回到 f32 局部精度（≤1.2e-4）✓。

### R3【中高】簇级 LOD bake 在世界系 f32 进行（定位是"事后补救"）
- **证据链**：`buildClusterLodAuthorStaging.ts:102-112` 用实例**世界变换**（`m[12..14]`，1e6+）把网格几何合并到世界系，行 119 `Float32Array.from(mergedVertices)` ——**f32 量化发生在世界坐标上**；随后 `clusterLodBake.ts:74-106` `simplifyByVertexClustering` 在该 f32 世界坐标上聚类抽稀；`DeepWebGpuBackend.ts:679-692` 才做 `localizeClusterLodStaging`（fround+0.001 预算）——此时精度已不可逆丢失（预算校验的对象是"已 f32 的值"，恒通过）。
- **量化**（实验 A 外推）：世界坐标 1e6 处 f32 ulp=0.0625 → bake 顶点携带 ≤3.1e-2 单位量化噪声（约 3cm），远超坐标 profile 的 0.001 预算；1e7 处 ulp=1.0 → LOD 顶点量化到 1 米网格，抽稀聚类在 1m 网格上进行，细节层级失真。
- **触发条件**：opt-in（`g1-cluster-lod=1`）+ 大坐标场景。**结论**：合并展开应在减去帧原点之后、f32 化之前进行（顺序反了）。

### R4【中】CSM 阴影矩阵：定位下安全；1e6 硬上限是定位必要性的 fail-closed 证据
- CSM 规划输入为**局部** eye/target（`pbrRenderer.ts:529` ← `localView`），规划数学全 f64（`cascadedShadowPlanner.ts:23-34`，texel 对齐行 99-107），矩阵经 `cameraMath.multiply` f32 存储（行 31-34）。定位下：阴影 VP 平移列量级 ~1.3，f32 ulp 1.2e-7，亚纹素抖动 ≈0%（实验 D）。
- 世界系反事实曲线（2048 阴影图、500 覆盖、texel=0.0366）：eye.x=1e4 → 0.04% 纹素；5e5 → 2.67%；1e6 → 5.34%；**>1e6 直接 `RangeError: Invalid camera eye`**（`cascadedShadowPlanner.ts:6` `MAX_DISTANCE=1_000_000`、行 114-117）。
- **结论**：`(a)` 大坐标场景 CSM 依赖定位（世界系 >1e6 连规划都无法进行，fail-closed 正确）；`(b)` 接近 1e6 的世界系调用有 5% 纹素级抖动——定位后归零。当前生产路径已满足，无需改动；该上限应视为"定位合同"的强制边界写进宿主文档。
- 接触阴影为方向向量口径（`contactShadowUniform.ts:16-20`），平移不变 ✓，不受 origin 影响。

### R5【低中】重定基帧触发 cameraCut，TAA/motion 历史每 ~1000 单位重置一次
- 证据：`cameraFrameHistory.ts:100-106` `jumped()` 以局部 eye 距离判定（>0.35·extent 即 cut）；重定基使局部 eye 跳变 ±(0~2000) → 恒触发 cameraCut → `previousViewProjection = current`（行 53-55），该帧 motion vector 归零、TAA 历史清空。
- 后果：大场景巡航时每跨过 1000 单位（约每秒数次，取决于速度）出现一次时间抗锯齿/SSR 收敛重启（一帧闪烁）。非错误值，是体验级风险；设计上或可用"重定基时平移 previousViewProjection 平移列"消除，供后续评估。

### R6【低】地面网格与径向渐隐锚定局部原点
- 证据：`pbrShader.ts:165-166` `fract(world.xz / 2.4 - 0.5)` 与 `exp(-length(world.xz) * 0.06)` 中 `world` 是**渲染局部**坐标。
- 量化（实验 E）：重定基步长 1000，`1000 mod 2.4 = 1.6` → 每次重定基地面网格图案跳变 66.7% 单元宽；渐隐圆心随帧原点平移（相机远离世界原点后，"中心亮、边缘暗"的地面渐隐圈跟着相机走）。
- 后果：视觉级（网格纹理跳格 + 渐隐圈漂移），非几何错误。修法方向：网格相位用 `frame origin` 对 2.4 取模补偿。

### R7【信息/正面确认】法线重建与大平移完全解耦
- `packTransform` 法线矩阵只由 3×3 计算（`instanceTransform.ts:13-23`），平移分量不参与；非均匀缩放+剪切+1e6 平移下最大法线角误差 **8.5e-7°**（实验 C）。拾取侧同口径（`picking.ts:223-230` M⁻ᵀ·n）✓。

## 4. 量化实验汇总（纯 Node 数值仿真，脚本已清理）

**实验 A：相邻实例/平移分量的 f32 量化（有无浮动原点）**（`fround` 精确复现 D2/D3）

| 世界坐标 x | f32 ulp | 相邻差异 Δ | 无定位保留值 | 有定位保留值 |
|---|---|---|---|---|
| 1e6 | 0.0625 | 0.01 | **0（合并）** | 0.0100000000（误差 2e-9） |

**实验 B：view 矩阵灾难性消除 → NDC/像素**（真实 `lookAt/perspective/multiply` + WGSL 逐运算 f32 仿真；1920×1080、fov45°、near 0.1 / far 4000）

- lookAt 平移列 f32 存储误差：W=1e3 → 8.3e-6；1e5 → 3.8e-3；1e6 → 9.3e-3；1e7 → 0.157（ulp(|t|)=6.25e-2 / 1.0）。
- 近处几何相对误差（2 单位视距）：W=1e6 → 0.465%；W=1e7 → **7.86%**。
- 像素级后果见 §2 表格：无定位在 1e6+ 下 0.01 单位细节（近距 2.01px）**完全丢失**、1e7 绝对位置偏 137px；定位路径全部 ≤2.5e-7px。

**实验 C：法线重建**：见 R7。

**实验 D：拾取与 CSM**
- 拾取距离：无定位 W=1e7 命中 t 误差 0.25（三角形被 f32 量化推离射线）；定位后 0（f64 数学 + 局部小量）。

**实验 E：地面网格**：重定基 1000 → 图案相位跳 1.6/2.4 单元（66.7%）。

## 6. 结论

1. **大世界浮点精度的核心工程（浮动原点 `scene-local-coordinates-v1`）已存在且在几何+相机主链上正确工作**：定位后 1e6/1e7 场景的实例平移误差 1e-8～1e-9 单位、像素误差 ≤2.5e-7px、法线误差 8.5e-7°，均远低于可感知阈值；反事实（无定位）数据（0.01 细节在 1e6 全毁、1e7 位置偏 137px、CSM >1e6 直接抛错）证明该机制是**必要**的。
2. **真实缺口不在"矩阵数学"而在"合同覆盖面"**：光源族（R1）与拾取命中点出域（R2）两个高危缺陷都是"坐标空间从一个子系统漏到另一个子系统"的一致性问题，而非 f32 精度本身；簇级 LOD bake（R3）是"先 f32 后定位"的顺序错误。
3. 建议后续（不属本次只读范围）：R1/R2/R3 各开修复项；补 1e5+ 坐标的端到端回归样本（现状核查第 5 步确认缺失）；在 `renderPacketValidation` 或宿主文档中把"必须经 `DeepWebGpuBackend` 进入 `PbrRenderer`"写成显式精度合同。
