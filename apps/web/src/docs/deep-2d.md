# Deep 2D

Deep 2D 是 Deep 引擎的二维渲染层：同一份二维显示列表合同描述矩形、路径、渐变这类二维内容，由 Deep Native 在 wgpu 上直接绘制，目标是让 Native 发布物的二维层不再借道浏览器。作者在编辑器里搭的二维页面仍由 Web 组件渲染；Deep 2D 按设计属于 Native 宿主，浏览器（TS）端没有 deep2D 渲染通路，这一点在[引擎能力矩阵](/docs/engine-capability-matrix)里逐行如实登记。

## 视觉三命令

Native 端的绘制词汇包含三件视觉命令：线性与径向渐变、圆角矩形、箱阴影。圆角与阴影用解析 SDF 在片段级求值，不依赖离屏模糊；旧版实心填充的字节布局保持兼容，已有的显示列表不需要迁移。三命令有真 GPU 读回对拍证据，对拍内部零分歧。

## 组件布局引擎

宿主用组件树声明内容：行、列、换行与主轴、交叉轴对齐由 flex 布局引擎求解；布局结果不生成新命令，而是让每个叶结点直接产出矩形几何，进入既有渲染管线。圆角卡片、渐变标题栏、图标与文本占位的整页 flex 排布有逐像素对拍证据。

## 动态路径填充

路径填充分静态与动态两路，分路是运行时自动决策，没有用户开关：静态路径沿用 CPU 细分加缓存；滑动窗口（8 帧）内内容变更达到 3 次的路径自动转到 GPU 的 stencil-then-cover 填充，支持 nonzero 与 evenodd 两种填充规则。能力限定在填充域：描边仍由 CPU 展开，边缘为硬边，与既有静态路径管线一致。

## 宿主怎么用

Native 宿主在 deep2d 上下文里挂组件树、声明样式，布局求解与视觉命令的产出对宿主是自动的；验证入口见 Native 便携包（[Deep Engine](/docs/deep-engine#native-便携包)），显示列表在引擎分层中的位置见[引擎借鉴与设计理念](/docs/engine-design-influences)。Web 宿主需要等效视觉时继续使用现有二维组件，不要假设 TS 端能消费 deep2D 视觉命令。

能力边界以[引擎能力矩阵](/docs/engine-capability-matrix)为准；三行能力当前都是 Native 端完整可用、Web 端按设计缺席，不接受“浏览器里也能跑 deep2D”的表述。
