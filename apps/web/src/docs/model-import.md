# 模型导入与格式选择

先用一个小模型验证几何、单位、材质和构件信息，再导入整套项目。文件能上传只证明传输完成，模型“可使用”才是进入场景编辑的起点。

## 选择输入格式

GLB 适合携带几何与材质交付，单文件便于定位缺失资源。glTF 可能引用外部缓冲与贴图，应确保依赖完整。需要 BIM 构件树和属性时优先验证 IFC 或对应转换链的元数据结果。

STEP、DWG、RVT 等工程格式使用各自的转换路径。RVT 依赖匹配版本 Revit 的 Windows Worker；DWG 依赖 LibreDWG 或部署提供的转换器。专业格式先查看系统能力和真实样本结果，再安排批量导入。

格式版本、依赖和支持边界以仓库[转换插件与格式支持](https://github.com/fatasia/DeepMonkey-Studio/blob/HEAD/docs/converter-plugin-and-format-support.md)为准。

## 上传并检查处理结果

1. 确认当前项目，在“项目资源”上传模型。
2. 等待上传与转换结束；失败时保留任务诊断，确认转换器是否就绪。
3. 预览模型，检查整体尺寸、朝向、材质和外部贴图。
4. 插入三维场景后使用适应全部，检查构件树、属性和拾取结果。
5. 保存并重新打开场景，确认资源引用和实例外观恢复正确。

不要通过改文件后缀绕过格式检查。重复失败时用能复现同一问题的最小文件定位，并保留导出软件与版本信息。

## 单位、原点与层级

模型过大、过小或偏离视野时，先核对源文件单位和原点。合并多个专业模型前统一坐标约定；不要仅靠缩放视图掩盖实际尺寸错误。

随机抽查已知尺寸的构件和两个楼层的位置。测量值、构件名称、层级和元数据应与源工程一致；几何正确但属性丢失时，应单独记录元数据问题。

## 材质与性能

贴图缺失时检查资源路径和导出依赖；模型整体发白时先区分材质缺失、灯光设置和实例颜色覆盖。保留原始资源，按[资源管理](/docs/resource-workflow)在实例级调整外观。

大模型先测载入时间、交互响应和内存占用，再决定简化几何、压缩贴图或拆分模型。性能记录应注明设备、浏览器、模型规模与渲染后端；不同条件下的帧率不直接比较。

## 提交导入问题

报告包含源格式与版本、导出器、处理阶段、诊断信息以及脱敏后的最小样本。客户工程不可公开时先制作等价的小样本。提交流程见[社区与支持](/docs/community)，发布前继续执行[交付自检](/docs/server-publish#交付前自检)。
