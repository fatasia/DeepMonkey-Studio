# 常见问题

这里汇总安装、编辑与交付中容易混淆的问题。遇到具体错误，先按[故障恢复](/docs/troubleshooting)定位。

## 是否必须安装桌面客户端

Web 与 API 可以独立运行。Windows 桌面客户端额外提供本地工作台和桌面集成，源码构建还要多装几样工具。先用[安装与首次启动](/docs/getting-started)里的 Web 方式验证需求，再决定是否需要桌面端。

## 是否可以完全离线

文档和已经准备好的场景资源可以离线使用，桌面端的本地工作台也支持本地编辑；内置的工业格式解析同样在本机完成，不需要联网转换。外部 AI、远程数据、摄像头和在线发布仍然需要对应的服务。首次安装依赖和下载模型要在断网之前完成。

## 新建场景为什么自带几个对象

新建场景时“初始内容”默认是“示例本体”：一个底座、一根立柱和一个点击热点，点热点会聚焦并给出提示，让你进入画布就能看到效果。对象名称里都带“示例”二字，选中后直接删除即可。想从零开始，新建时选“空白场景”。

## 保存后为什么发布页没有变化

保存更新的是草稿，发布更新的是运行版本。完成预览和体检后再次发布，再打开链接验证。如果你用的是下载的 Windows 客户端，它是某个发布版本的快照，需要重新发布并重新下载，见[预览、体检与发布](/docs/server-publish#下载单场景-windows-客户端)。发布版本与草稿的区别见[项目、资源与发布版本](/docs/core-concepts#草稿-预览与发布)。

## 换服务器后为什么看不到原项目

服务器地址决定访问哪一套项目数据，本地工作台也有自己的存储，切换连接不会自动搬迁内容。先回到原来的位置确认项目还在，再通过 `.bimproject` 项目包导出和导入，不要急着新建同名项目来对比。

## 为什么模型能上传却不能显示

上传、格式识别、转换和可渲染是几个不同的阶段。先看处理诊断，再核对转换器、外部贴图、源文件版本和单位，具体步骤见[模型导入与格式选择](/docs/model-import)。

## 为什么 RVT、DWG 没有内置支持

工业格式走的是自研或开源、随包内置、本地离线的路线，不依赖商业 SDK、云转换或源软件。JT 的 9.5 和 10.3 版本、X_T 的部分文件已经有内置解析，但 RVT 和 DWG 的内置解析链还没有完成。部署方自备的外部转换器可以作为可选路径，但不计入内置能力。现阶段建议提供方把文件另存为 IFC、STEP 或 GLB，范围见[模型导入与格式选择](/docs/model-import#选择输入格式)。

## 模型提示“资产修订陈旧”怎么办

说明项目资源里有比场景引用更新的修订。先看新修订是否符合预期，再决定“更新到最新版本”，或者“保持当前”暂不处理。已经发布的版本不会因此改变，见[资产有新修订时](/docs/resource-workflow#资产有新修订时)。

## 为什么数据连接成功但图表没有值

连接测试并不检查全部业务字段。继续运行数据集，检查字段、行数和空值，再运行流水线并检查组件绑定。尤其要确认数字字段没有被转成带单位的字符串，单位应当在展示层处理。

## AI 助手里的“对话”和“执行任务”有什么区别

“对话”用来提问、查数据和生成可审阅的草稿，助手不会自己修改项目。“执行任务”则让助手按你写的目标调用能力，分“只出计划”“逐次确认”“自主执行”三种方式，写入和控制类操作必须经过确认或授权，并且要有执行后的验证证据。两者在面板顶部切换，详见[使用工业 AI 助手与视觉能力](/docs/ai-workflows)。

## 为什么助手好像忘了前面说的话

对话很长时，为了控制上下文预算，只有最近几轮会发给模型，较早的轮次不参与本次回答，面板会提示被省略的轮数。需要保留的前提，请在新的问题里再写一遍。

## 为什么视频能播放但没有识别结果

监控播放和视觉 AI 是两个独立的任务。检查识别任务有没有启用、模型是否就绪、采样是否在运行，再看识别记录和诊断。识别模型被停用，不代表视频源离线。

## Three.js 和 Deep 的画面一样吗

两边共用同一份显示合约，默认的色调映射、曝光和阴影参数一致，实际画面也经过对拍：在对拍用的标准材质矩阵和方向光阴影场景里，两边已经达到肉眼无法分辨的程度，但抗锯齿边缘和 IBL 反射仍有已知差异，半透明叠加在容许范围内。后期效果也不是每个后端都支持，比如体积雾只在 Deep WebGPU 下完整生效。详见[Deep Engine](/docs/deep-engine#与-three-js-的显示一致性)。

## WebGPU 和 Native 是否支持同一套能力

两者有独立的运行合同和验证范围。WebGPU 后端共享编辑器状态；Native 发布则需要确认资源、二维组件、脚本和数据能力是否都能交付。诊断里出现缺失或降级的项目，应在发布前处理。

## 文档与实际界面不一致时以哪个为准

应用内文档跟随当前构建，仓库默认分支上可能已经有下一版的改动。反馈问题时请附上应用版本、提交号和文档标题；发行说明和对应版本的源码可以用来复核行为。也欢迎按[开发与贡献](/docs/contributing)直接修正文档。
