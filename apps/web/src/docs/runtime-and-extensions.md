# 选择运行方式与扩展能力

平台把编辑、运行和交付分开：作者在 Web 或桌面工作台编辑，使用者只打开已发布内容。开始项目前先选运行方式，避免把本地草稿、在线项目和发布版本混为一谈。

## 选择工作方式

- Web 工作台连接当前服务器，适合使用项目数据、AI、工业任务、团队账号和在线发布。
- 桌面端启动后先进入“选择工作方式”。“本地工作台”不需要服务器地址，SQLite 和文件存储都在本机，可以创建、编辑和保存 2D、3D 与脚本，支持数据源、AI、Native / Android 发布，也能导出项目包；“连接企业服务器”则使用团队共享的项目和数据。两者的编辑、转换与发布入口一致，区别在数据存在哪里。外部 AI、远程数据和在线视频仍然依赖各自的服务是否可达。
- 项目可以通过 `.bimproject` 在本地和服务器之间双向迁移，数据源的凭据需要在目标环境里重新配置。
- 发布浏览页只运行已冻结的版本。可以分别选择 WebGL、WebGPU 优先、云渲染，或只读的 Windows 场景客户端，浏览的人看不到任何编辑能力。

桌面端提示“上次服务器当前不可用，本地工作台仍可正常使用”时，可以直接进入本地工作台。切换到另一台服务器前，先保存并导出本地项目；服务器地址改变不会自动迁移项目数据。

## 使用基础能力

核心 Web 编辑、2D / 3D、脚本、数据编排和本地场景浏览由仓库锁定的运行时提供。项目按根目录许可证公开源码，第三方组件遵循各自许可证。开发人员可在仓库根目录启动：

```bash
pnpm install --frozen-lockfile
pnpm studio start web
```

需要同时启动桌面客户端时使用 `pnpm studio start client`。启动、关闭、重启、状态检查与生产部署都通过同一个 `pnpm studio` 入口完成。核心开发要求 Node.js 24 与 pnpm 11；普通安装包用户不需要安装 Node.js 或 Python。

产品菜单中的“开源项目致谢”用于查看直接依赖和许可证；精确版本及分发说明以发行包内 `THIRD_PARTY_NOTICES.md` 为准。新增依赖前应重新运行依赖与许可证审计，不能只根据项目首页判断可商用性。

## 可选适配器与内置能力的边界

工业格式、几何处理和仿真的核心能力由随包内置的自研或开源组件完成，在本机离线运行，不依赖外部商业 SDK、云转换服务或源软件的授权。第三方开源依赖在逐文件审计、固定版本后随包交付，许可证义务见“开源项目致谢”，不需要用户另行购买授权。

Unity 资源、厂商控制器或专用求解器这类专业环境，可以通过可选的适配器接入。适配器只返回统一的资源、场景对象或 Study 证据，不会另建一套项目、权限和发布体系。使用前在系统能力页核对三个状态：适配器已配置、运行探针通过、目标格式或任务已用真实样本验证。只声明了格式、却没有可用 Provider 时，任务会停在等待状态；文件扩展名被识别并不代表模型可用。

部署方自备的外部转换器（例如把 DWG 转成 DXF 的 LibreDWG 命令，或依赖 Revit 的历史 Worker）属于可选路径，不计入内置能力，也不会成为内置格式的验收依据。目前 RVT 和 DWG 都没有随包内置的解析链，细节见[模型导入与格式选择](/docs/model-import#选择输入格式)。不启用这些外部路径，不影响 GLB、glTF、IFC、FBX、STEP、DXF、OpenUSD，以及内置的 JT 和 X_T 子集。
