# 实时全局光照

直接光（灯光、太阳）之外，还有光在表面之间反射形成的间接光。Deep 的实时全局光照由三层组成：探针 GI 负责缓存与采样环境及场景辐射，SDF 光照烘焙为静态场景补上精确遮蔽，SSGI 在屏幕空间补一次表面间反弹。三层可以叠加，职责不同，不会重复计光。除探针 GI 外，各层默认关闭，用地址栏开关启用；全部三层都只在 Deep WebGPU 下生效。逐项双端状态见[引擎能力矩阵](/docs/engine-capability-matrix)。

## 探针 GI（默认通路）

打开“环境与全局灯光”面板，在“灯光”里开启“全局光照”开关并调节强度。开启后，引擎按级联探针网格捕获场景辐射（一跳，复用软件 BVH 射线后端），着色时用探针结果替换环境光的均匀项；辐射方向分 standard（16 方向）与 high（32 方向）两档。关闭开关或没有真实辐射源时回退到 IBL 环境光，不会出现全黑体积。

边界：Deep Native 发布端支持单层探针网格随运行包消费，多层级联与 GPU 烘焙编排的 Native 通路尚未接线；探针捕获按预算逐帧推进，场景大改后需要若干帧才收敛。这个开关属于场景灯光设置，随场景保存。

## SDF 光照烘焙（opt-in）

打开三维编辑器时在地址栏加 `sdf-gi=1`，引擎会对静态场景烘焙 SDF 距离场，用天光圆锥追踪计算遮蔽，并更新探针的球谐记录，烘焙出的探针场物化为主渲染的采样纹理。烘焙在 GPU 上进行，真机实测约 6 万格的距离场稳态烘焙约 4.4 毫秒（CPU 同式约 585 毫秒）；场景修订变化后自动重新烘焙，“光照烘焙”工作台面板可以观察烘焙计数与产物规模。画面上的收益是角落与接触处比纯环境光更暗、更有层次，静态室内、走廊和厂房这类遮蔽关系固定的场景受益最大。

边界：此开关默认关，关闭时引擎不构建 SDF GI 运行时，帧逐位不变。Web 端的变化检测目前覆盖探针域内子域而非全场景。Deep Native 端已移植同一套 SDF 烘焙、天光追踪与探针更新核，并与 Web 权威参考做了位级对拍和 RTX 4060 真机 GPU 门，但生产渲染帧循环的接线属后续切片——在能力矩阵上登记为“验收通路”，不要把它当作 Native 运行时能力来依赖。

## SSGI 屏空间漫射（opt-in）

打开三维编辑器时在地址栏加 `ssgi=1` 开启屏幕空间全局光照：半分辨率下对每个像素做一次余弦半球采样，取可见表面的入射光，再以加性方式合成回全分辨率帧；输出位置在反射和时域抗锯齿之前，时域噪点由 TAA 顺带平滑。它补的是“近处表面互相反弹”这一段，典型收益是彩色地面给墙面和墙角染上环境色。

边界：屏空间方法看不到视锥外和被前景遮挡的反弹体，屏幕边缘有衰减；深色表面反弹弱是物理正确而不是缺陷。默认关，关闭时渲染链不构建该通道，帧逐位不变。

## 三层怎么配合

- 探针 GI 与 SSGI 叠加是合法且常见的组合：探针结果在着色器内替换环境光项，SSGI 是后链加性层，只补表面间反弹，叠加不会双重计光。
- 开启 `sdf-gi=1` 后，烘焙出的探针场接管主渲染的探针采样，逐帧捕获停驱；关掉开关即回到逐帧捕获。
- `sdf-gi` 与 `ssgi` 是地址栏开关，不写进场景数据，刷新或切换渲染器后回到默认状态；想让遮蔽关系长期生效，使用探针 GI 开关或后续版本的烘焙发布能力。

开启方式与边界如有变化，以[引擎能力矩阵](/docs/engine-capability-matrix)的登记为准；画面口径与对拍方法见[引擎性能与画质基准](/docs/engine-benchmarks)。
