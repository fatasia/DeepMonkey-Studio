# 引擎能力矩阵

本页是引擎能力的公开清单:渲染管线、全局光照(GI)、阴影、光线追踪、Deep 2D、后处理、大场景管线、材质、设备恢复与格式支持,逐行给出 Studio(Web)与 Native(Rust)两端的状态与文件证据。

页面内容由内置能力登记表在运行时生成,不是手写文案:渲染能力行来自双端能力协商登记表,格式支持行来自模型格式能力目录。登记表中的任何状态变化都会直接反映到本页;每行携带登记表里的仓库文件证据,可追溯到具体实现。

## 如何读状态

每个能力按支持档与原因码展示:完整可用表示该端语义达到能力定义;可用 · 需开启表示实现完整但默认关闭(opt-in),开启即得完整语义;降级表示范围或档位低于能力定义,原因写在证据里;验收通路表示仅有验收或参考实现,不是运行时通路;规划中表示该端尚未实现;依赖平台 API 表示受底层接口缺席限制,与实现无关;宿主专属表示该能力按设计只属于某类宿主。

格式支持行使用独立口径:生产可用要求代码实现之外还必须通过生产样本验证;可用(样例验证)表示已有样例级证据;开发中与规划中表示尚未交付;不支持表示明确排除的范围。格式行同时给出导入/导出方向与内置/可选范围。

## 证据与登记纪律

证据列是仓库内文件路径(可带符号与说明后缀),指向当前真实实现;状态与证据必须同步更新,任一端落地新能力时必须同时登记双端状态,单端登记会被对拍测试判定为清单漂移。物理能力尚未建立带文件证据的双端公开登记表,按诚实条款本页不为其虚构行,登记表建立后此处会自动展开。

想要了解各项能力的实现细节,可以继续阅读本分类下的引擎设计、基准与 SDK 文档。
