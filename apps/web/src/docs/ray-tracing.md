# 光线追踪

Deep 的光线追踪在 Web 端以帧内联 BVH（compute 着色）实现，目前覆盖三类用途：方向光 RT 阴影、万灯直接光（ReSTIR）和反射通道；Native 端另有基于硬件 Ray Query 的方向阴影管线。除注明外，这些能力都是 opt-in 默认关，打开三维编辑器时在地址栏加对应开关启用，不改变场景数据。逐项双端状态见[引擎能力矩阵](/docs/engine-capability-matrix)。

## 方向光 RT 阴影与自动选路

地址栏加 `ray-traced-shadows=1` 开启。开启后渲染器构建 RT 资源与管线变体，方向光阴影从级联阴影贴图换成逐像素遮挡射线。射线走两级加速结构（场景级 TLAS 加网格级 BLAS），细杆、栅格这类薄结构不再受阴影贴图分辨率限制。

开启后并不是每帧都跑 RT。渲染器按帧做混合调度，自动在 RT 通道和级联通道之间切换：

- RT 控制器没有就绪（场景几何尚未供入加速结构）时回级联，不会静默假开。
- 自适应质量把阴影档降到性能档时回级联，优先卸掉全屏射线调度。
- 档位在边界抖动后的滞回冷却期（约两秒）内保持级联，避免在两个通道间来回振荡。
- 其余情况走 RT。

选路只决定本帧用哪个通道，阴影数值语义不变。Deep Native 端另有硬件 Ray Query 的方向阴影管线族，目前只覆盖静态不透明批次，失败时回退栅格化，与 Web 的 compute 实现属不同实现档。

## 万灯直接光（ReSTIR）

地址栏加 `mega-lights=1` 开启万灯路径。本地灯不超过 64 盏时仍走既有簇光路径，帧逐位不变；超过预算后才切换到 RIS 随机采样：每像素抽取一组候选灯做时域加空间复用，最终只对着色的“胜者”灯做遮挡判定。胜者可见性是一条真实遮挡射线，被挡住乘零；空间复用按源像素传递可见性，这是 ReSTIR 直接光照的通行做法。面积光单场景上限一批扩到 64 盏。

边界与保护：灯数超过 65535 直接拒绝；声明了 IES 配光的灯在没供给配光表时拒绝参与，不会算出错误光强。真机帧时门为 5000 盏灯、1080p 下 RIS 计算的 p95 不超过 20 毫秒。起步档的表面法线由深度差分恢复，材质响应先走中性档，完整表面数据的接入属后续切片。

## 反射通道

反射通道提供一次反弹的 closest-hit 命中与镜面 GI：命中点辐射由主方向光加环境项合成，结果在屏幕空间反射合成之后做屏外填充——SSR 屏内没有命中的像素，用 RT 命中结果替换 IBL 高光回退；SSR 命中的像素逐位透传。引擎侧的帧通道、填充与真机对拍门已经就绪；编辑器产品桥还没有把这个参数接进特性快照，在 Studio 里暂时开不到它，当前面向用 Deep Engine SDK 自建宿主的接入方，在渲染器特性里显式开启。该通道需要与 SSR 一起使用；二次反弹与灯池跨域复用属后续切片。

## 开启与排查

- 三个地址栏开关可以单独使用，也可以组合；关闭即回到原路径，帧逐位不变。
- 开关不生效时，先确认地址参数拼写，再在“渲染引擎设置”面板里导出诊断，查看特性快照与逐通道读数。
- 画质与性能的量测口径见[渲染性能诊断](/docs/engine-performance)，接入方式见[Deep Engine 独立 SDK](/docs/deep-engine-sdk)。
