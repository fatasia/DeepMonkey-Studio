# 项目、资源与发布版本

理解内容归属后，再决定在哪个页面操作。一个项目承载业务范围；应用把二维页面、三维内容、数据和行为组织成可交付的场景。

## 项目与应用

项目是场景、资源、数据连接和工业任务的上下文。切换项目后，先核对顶部项目名称，再创建或修改内容。应用内“二维 / 三维 / 脚本”是同一份设计的不同工作区。

二维页面负责布局和信息呈现，三维场景负责空间内容。页面中的三维场景实例用于连接两者；双击实例可以继续编辑三维内容，无需另建一个项目。

## 资源与实例

资源是可复用的模型、图片、视频、环境或材质。实例是资源在当前场景中的一次使用，拥有自己的位置、名称、外观和绑定。

例如同一个泵模型可以放置两次：两台泵使用相同的几何资源，但各自关联不同的设备数据。修改实例颜色不会改写公共模型；删除资源前则要检查所有使用位置，删除时系统会列出受影响的场景。

资源本身也会有新的修订，比如重新导入或参数化修改之后。场景记录的是它引用的修订号，资源出了新修订，项目资源页会提示“资产修订陈旧”，由你决定更新还是保持当前，不会在背后自动改动场景。操作见[资源管理](/docs/resource-workflow#资产有新修订时)。

## 连接、数据集与流水线

连接描述如何访问数据库、接口或设备。数据集描述读取哪些字段与记录。流水线在数据集上完成过滤、计算和输出。场景绑定把输出字段映射到对象属性或组件显示。

例如设备连接读出温度，数据集返回设备编号与温度列，流水线筛选异常设备，二维组件显示数量，三维对象显示状态。每一级都应先独立测试，再接到下一级；见[数据中心](/docs/data-pipeline)。

## 草稿、预览与发布

草稿是正在编辑的内容。保存用于持久化草稿，预览用于检查当前设计，发布用于建立独立运行版本。保存成功不代表已发布，发布成功也不能替代浏览端的实际检查。

修改草稿后，发布端要通过再次发布才能得到更新。恢复历史发布会建立新的发布记录；撤回发布关闭运行入口并保留当前草稿。版本操作见[预览、体检与发布](/docs/server-publish)。

## 本地工作台与服务器

桌面本地工作台与服务器项目使用不同的存储位置。填写或更换服务器地址不会自动迁移本地内容；需要转移时先保存并导出项目包。

备份也要区分范围：服务器备份覆盖数据库和对象存储，不能替代浏览器本地草稿或桌面本地项目的备份。运行形态见[运行方式与扩展](/docs/runtime-and-extensions)。

## 能力状态与工程证据

“格式已识别”“适配器已配置”“资源可使用”“任务有验证结果”是不同阶段。只有扩展名识别时不能推断几何可渲染；只有仿真图表时不能推断现场设备已验证。

Deep WebGPU 是编辑器里可以切换的渲染后端，Deep Native 是独立的发布运行时目标，两者验收范围不同。选择前先看[Deep Engine](/docs/deep-engine)和渲染引擎面板里的能力诊断。
