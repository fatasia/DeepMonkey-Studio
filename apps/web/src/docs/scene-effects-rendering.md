# 三维效果、环境与物理光照出图

这篇文档讲三维编辑器里影响“看起来怎么样”和“动起来怎么样”的几组设置：模型动画的根运动、火焰粒子、体积雾、物理的固定步长，以及离线的物理光照出图。每一节先说它解决什么问题，再说怎么用，最后写清边界。几种渲染器的差别见 [Deep Engine](/docs/deep-engine)。

## 模型动画与根运动

很多角色或设备动画（行走、转身、移动小车）把位移和旋转烘焙在根骨骼上。直接播放时，模型是在原地做动作，还是真的沿着动作走出去，由“根运动”开关决定。

选中带动画的模型，在右侧检查器的“模型动画片段”里可以选片段、设置“自动播放”和“播放方式”（播放一次或循环播放），也可以用上一帧、播放 / 暂停、停止并回到开头、下一帧和时间条逐帧检查。打开“根运动”开关后，片段里根骨骼的平移和旋转会被应用到模型实例上，右侧同时显示累计的位移和转角。这是给预览和摆位用的，随时可以撤销：点“复位根运动位置”，模型就回到开启之前的位置和朝向。

开关不可用时，鼠标悬停会说明原因：模型已锁定、模型没有可播放的动画，或者当前片段没有根骨骼的平移轨道，因此没有可抽取的位移。

使用时注意：

- 根运动会真实改动实例的位置和朝向。面板在存在已应用位移时会提示“含根运动位移，保存前建议复位”，忘了复位就保存，漂移后的位置会被一并存下来。
- 复位之后再切换开关。如果先关闭开关、没有复位，再重新开启，系统会把漂移后的姿态当作新的起点，复位就回不到最初的位置了。
- 旋转以实例的原点为轴心。开关状态只在当前会话里有效，不会写进场景。

## 火焰图层

火焰图层是一个很轻的粒子效果，适合给设备、烟囱、告警点加上火焰或热气，不需要另外建模。

选中模型或基础体，在检查器的“高级表现”里找到“火焰图层”，点“启用”。可调的参数有：

- 颜色、强度、高度和密度。
- 粒子上限：单个发射器最多使用多少粒子。
- 混合：“叠加”适合火焰和发光，粒子之间没有先后顺序，开销最低；“透明·排序”适合烟和半透明的热气，每帧按相机距离由远到近排序后再绘制，画面更干净，开销也更高。
- 三条曲线：尺寸、不透明度和热度色，分别描述粒子从出生到消失的过程中如何变化。热度色从偏暗的余烬色经基础色过渡到高光色。不改曲线时使用默认的火焰形态，也就是淡入、中段最亮、尾部消散。曲线编辑器支持拖动控制点、用方向键微调、点击空白处加点、双击或按 `Delete` 删点，还有预设和“恢复默认”，每条曲线最多 16 个关键点。

粒子数量是有预算的。单个发射器的粒子数取“80 × 密度”和“粒子上限”中较小的一个，整个场景的火焰粒子总量上限是 1024。面板里“本发射器”和“场景预算”两行读数显示申请量和实际绘制量；超出场景预算时会出现提示“超出场景粒子预算：申请 X，实际绘制 Y（Z%），已按比例降级”。降级只是缩小实际绘制的数量，不会报错，也不会重建几何。想保住重点位置的火焰，就调低其他发射器的密度。

旧场景里已有的火焰图层不需要迁移，新增的曲线、混合和上限都是可选项。使用 Deep WebGPU 渲染时，逐粒子的尺寸变化暂时以曲线的平均值作为整体尺寸，WebGL 下是逐粒子变化的。

## 体积雾

普通的场景雾只是让远处的表面逐渐变白。体积雾则是让光线穿过一团有厚度的介质，因此能出现光柱、受光面更亮的雾团，更像真实的空气感。

打开“环境与全局灯光”面板，在“后处理”里启用“体积雾”。可调的参数有：

- 雾采样步数：越高越细腻，也越耗性能。
- 雾密度和高度尺度：决定雾有多浓、向上多高后变淡。
- 各向异性：控制光线主要向前散射还是向各个方向散射。
- 散射反照率：取值 0 到 1，默认 0.82。数值越低，雾对光的吸收越多，画面偏暗；越高，散射越强，雾显得更白更亮。
- 体积光开关和体积光强度：在有明确光源的地方做出光柱。

体积雾只在 Deep WebGPU 下完整生效。Deep Native 用的是受限的 8 步屏幕空间积分，不使用散射反照率；Three WebView 发布时会降级成普通的作者雾，发布检查里会有提示。开启体积雾后，它会替代原来的表面雾。目前介质没有独立的雾色参数，散射出来的颜色由主光决定。

## 物理的固定步长

物理模拟如果每帧按显示器刷新的时间推进，同一个场景在不同电脑、不同帧率下就会得到不同结果，调试起来很难复现。Studio 的物理宿主因此以固定的 60 Hz 步长推进：每帧累计流逝的时间，换算成整数个物理步，不足一步的余量带到下一帧。

带来的结果是，同一个初始状态在 30、60、144 帧每秒下，同一个步号的轨迹完全相同，帧率抖动也不会造成某一帧突然多走或少走。机器卡顿时一帧最多补 12 步（相当于 0.2 秒），超出的部分会被丢弃并计数，避免越补越卡。

行为脚本的 `onFixedUpdate` 同样是 1/60 秒的固定步长，每帧最多补 5 步。不过脚本和物理目前各自使用独立的时钟，并不保证逐步对齐；需要严格同步的逻辑，不要假定两边的步号相同。物理渲染也没有做帧间插值，高刷新率下刚体看起来是按 60 Hz 一格一格移动的。

## 物理光照出图

实时画面为了保持帧率，光照是近似的。需要一张接近真实光照的静帧，比如用于方案汇报，可以用“物理光照出图”：它在 CPU 上做多次光线弹射的路径追踪，不断累积样本，噪点随样本数增加而减少。

在三维编辑器顶部点“导出场景”，选“物理光照出图”，打开对话框：

1. “照明模式”选“物理光照 · 当前场景”（使用场景里的灯光和环境）。“方向光参考 · 环境关闭”和“白炉参考”用于检查灯光或能量是否正确，不用来出最终图。
2. 选分辨率。每档分辨率会估算内存，超出预算的档位会被禁用并说明原因。
3. “样本上限”从 256 到 65536 可选，选最高的 65536 会很久。“种子”决定随机序列，同一场景、同样设置和种子，结果可以复现。出图使用场景的默认视角。
4. 点“开始积累”。状态依次显示“编译场景”“积累中”，达到逐像素 2% 的噪声门限后变成“已收敛”。累积过程中只要修改了场景，状态会变成“场景已修改 · 积累已清空”，需要重新开始；取消后内存会被释放。
5. 没有等到收敛时，可以点“停止并保留”，状态为“尚未收敛 · 可保存预览”，用“保存预览”导出当前结果。只有“已收敛”之后才能点“导出 HDR”。

导出的文件是 Radiance 格式的 `.hdr`，保存线性辐亮度，同时生成同名的 `.json` 回执，记录样本数、噪声水平、是否收敛、是不是预览，以及 HDR 文件的 SHA-256，方便以后核对这张图是怎么来的。对话框里的预览为了便于查看使用了 ACES 色调映射，HDR 文件本身不含色调映射；编辑器的辅助网格、屏幕后处理效果和实时 GI 增强都不会写入。

边界：这是 CPU 参考实现，只出静帧，速度远不及实时渲染，大分辨率和高样本数要等很久；它不是发布运行时的一部分，也不替代 GPU 路径追踪。对话框里的并行线程和 PNG 导出还在验收，请不要把它们当作已支持的能力来依赖，以当前版本的界面为准。

## 默认开启的质感层

Deep WebGPU 下有一组不需要作者开启的质感层，它们决定接地、边缘和明暗的基本观感：

- 屏幕空间环境光遮蔽：在缝隙和交叠处加暗，默认开。
- 接触阴影：物体与地面接触处的小范围暗影，分三档质量，默认开。
- 时域抗锯齿与空间域边缘抗锯齿：前者用帧间历史平滑边缘和噪点，后者独立于时域历史在显示域处理边缘，两者默认开。
- 自动曝光与 ACES 色调映射：按环境亮度估计曝光，无可靠亮度来源时回退固定启发式，当前曝光值在帧指标里披露；色调映射与编辑器共用一份显示合约。
- 暗角与作者色彩分级：在“环境与全局灯光 → 后处理”里调节，色相、饱和度、亮度、对比度、色温、色调六通道与暗角参与出图。

这些层的双端可用性不同：接触阴影、环境光遮蔽、时域抗锯齿和自动曝光目前只在 Deep WebGPU；暗角在 Deep Native 是可选档（默认关）；Native 的 FXAA 与自动曝光目前是验收通路，尚未接入出片链。逐项状态见[引擎能力矩阵](/docs/engine-capability-matrix)。

## 全局光照与光线追踪

直接光之外的间接光与光追能力单独成篇：探针 GI、SDF 光照烘焙与 SSGI 的分工和开启方式见[实时全局光照](/docs/realtime-gi)；方向光 RT 阴影的自动选路、万灯直接光（ReSTIR）与反射通道见[光线追踪](/docs/ray-tracing)。它们默认关闭，用地址栏开关启用，不会改动场景数据。
