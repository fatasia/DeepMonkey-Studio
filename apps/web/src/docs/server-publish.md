# 预览、体检与发布

预览检查的是当前草稿；发布则把当前内容冻结成独立的运行版本，之后继续修改草稿不会影响已经发布的内容。项目场景卡把“预览”“编辑”“发布”“版本历史”“复制”“重命名”放在最显眼的位置，不常用的操作收在“更多”里。

## 在项目页预览

点场景缩略图或“预览”按钮就能直接预览，不用先进编辑器。预览时重点看这几件事：

- 首屏构图、二维比例、三维相机和文字是否清楚。
- 二维点击、筛选和页面跳转，三维对象的选择、动画和脚本事件。
- 数据的更新时间、空值，以及断流和重连时的提示。
- 图片、视频、实时监控、空间音频和 Unity 资源能不能按预期加载。
- 缩放窗口时有没有遮挡、裁切或点不到的控件。

发现问题回到编辑器改。二维、三维和脚本共用同一个应用上下文，不需要复制场景。

## 交付前自检

点项目场景页的“展开开发流程”，会看到“数据 → 资产 → 设计 → 联动 → 脚本 → 仿真 → 校验 → 发布”八步，标着“必需”的步骤全部完成后才算具备发布条件。“智能发布体检”会列出断链或无效引用，每一项都指向对应的场景和修复入口；“交付校验”给出必需项和建议项，必需项通过后点“进入发布”。

发布前至少完成：

1. 所有模型和媒体资源都是“可使用”状态，没有断链或失效版本。资源提示“资产修订陈旧”时，决定是更新还是保持当前，见[管理资源并插入 2D / 3D](/docs/resource-workflow#资产有新修订时)。
2. 数据集、流水线、字段和目标对象都还在，并且成功预览过。
3. 脚本已经应用并试运行，停止、重新运行和场景重载后没有遗留错误。
4. Plant、PPR 或机器人任务用到的结果可以复现，缺失的证据已经明确记录。
5. 预览走通了关键操作路径，发布体检没有阻断项。

## 发布运行版本

在场景卡点“发布”，对话框里有四组选项：

- 选择交付方式：WebGL 固定使用 WebGL 2 本地渲染，兼容面最广，也最适合嵌入其他系统；WebGPU 在设备支持时启用高级渲染管线，不支持或画质无法保持等价时回退到 WebGL 并显示原因；云渲染由服务端 GPU 出图，适合超大场景和低配终端，需要稳定的网络和管理员配好的云渲染 Worker，没配置时会提示“需要管理员先完成云渲染配置”。
- 性能策略：“高画质”严格使用作者设定的效果，性能不足时只给出诊断；“极速模式”在低配终端持续卡顿时可以自动启用，优先减轻阴影、后处理和刷新压力，恢复后自动退出。两者都不会改写模型几何和纹理。
- 浏览工具栏：选“显示”，访客可以用适应全部、漫游、测量、剖切、爆炸和场景信息；选“隐藏”适合展厅、嵌入页和纯观看，场景里作者设置的交互照常运行。
- 发布方式：“仅发布”只生成网页版本；另外两项会在发布后下载 Windows 客户端，见下一节。

选好后点“发布”。成功后在场景卡的“更多”里点“查看发布版”，或者“复制发布链接”，打开验证。

对话框里写明“发布不会覆盖草稿”。发布后仍然可以继续编辑草稿，内容有变化时用“重新发布”更新运行版本，原来的链接继续指向当前有效的发布版本。

## 下载单场景 Windows 客户端

单场景客户端适合不填服务器地址、网络不稳定，或者现场只需要浏览的交付。它从某个精确的已发布版本生成，固化该场景实际引用的模型、贴图、环境和品牌资源，沿用发布时的渲染策略和工具栏设置。

在发布对话框的“发布方式”里选：

- Three WebView：构建独立的 Windows 客户端，发布完成后浏览器直接下载 EXE。需要管理员在服务端配置好 Three WebView 通用启动器，没配置时下载会失败并提示启动器不可用。
- Deep Native：服务端编译并验证 Native 窗口，通过后下载 Windows 原生运行包。

文件名取“品牌设置”里的应用名称，没设置时是 `DeepMonkey Studio.exe`。生成客户端需要登录，并且账号对该项目有访问权限，只读角色没有这个权限。打包过程有进度，也可以取消；失败时界面会给出原因并允许重试，已经发布的网页版本不受影响。

这个客户端是只读浏览器，不是完整编辑客户端换了个名字。它只带场景浏览入口和只读接口，没有项目管理、二维 / 三维编辑器、脚本编辑器、保存、发布、AI 和数据配置。外部数据连接的密码、令牌和请求头不会写进包里，部署到现场后需要在运行环境里重新配置；`sim:` 仿真连接可以直接随包运行。

运维人员也可以用命令行从已发布版本生成并校验冻结包，步骤见 [Deep Engine](/docs/deep-engine#构建只读场景客户端)。无论哪种方式，校验只检查资源摘要、只读入口、能力集合和网络策略，不能替代在干净 Windows 机器上做一次真实的安装、升级和卸载验收。

## 版本、撤回和再次发布

场景卡上的“版本历史”会把已发布版本和当前草稿区分开，并可以查看差异范围、恢复旧版本。恢复会生成一条新的发布记录，不会抹掉原有历史。

“更多”菜单里有“查看发布版”“复制发布链接”“撤回发布”“开启 / 关闭云渲染”和“删除场景”。撤回发布只关闭公开的运行入口，不删除当前草稿；需要时再用“重新发布”恢复。复制场景用卡片上的“复制”。

遇到断链、空画布、数据或脚本异常，按[故障恢复](/docs/troubleshooting)处理；完整的起步流程见[从项目到首个可发布场景](/docs/dashboard-scene)。
