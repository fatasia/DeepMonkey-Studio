# 在看板中使用图片、视频和实时监控

图片、普通视频和实时监控是三种独立组件。图片与视频可以上传到项目资源后复用；实时监控通过项目媒体服务把摄像头协议转换为浏览器可播放地址。监控播放不依赖视觉 AI。

## 添加图片或普通视频

1. 在项目资源上传图片或 MP4/WebM 视频。
2. 进入二维编辑器，从“资源”拖入“图片”或“视频”。
3. 在内容面板选择项目资源，也可以填写管理员策略允许的 HTTPS 地址。
4. 设置填充方式。需要自动播放的视频应保持静音；浏览器通常会阻止带声音的自动播放。

删除仍被页面引用的资源前，发布检查会显示失效引用。设计态、预览态和发布态应引用同一个资源 ID，不把临时本地文件路径写进应用文档。

Deep Native 当前支持打包进发布物的静音 MP4：连续播放、循环、cover/contain/fill、播放/暂停、进度条拖动和键盘 seek。Space/Enter 切换播放，左右键前后移动，Shift 加大步长，Home/End 跳到首尾。非静音视频会在发布检查中明确显示 `audio-output` 不可用；远程 URL 不会伪装成离线资源。正式发布前仍应在目标 Windows 设备检查 codec、窗口缩放和长时间播放。

## 添加实时监控

1. 在视觉中心或媒体源管理中添加 RTSP、RTMP、SRT 或 HLS 地址。
2. 等待媒体服务返回可播放状态；RTSP/RTMP/SRT 会转换为 HLS，浏览器不会直接播放这些摄像头协议。
3. 在二维编辑器拖入“监控”组件，选择已建立的媒体源。
4. 进入预览，检查首帧、实时状态和断流恢复，再执行发布检查。

监控组件默认静音自动播放。断流时组件保留明确的“正在重连”或失败原因，不使用静态截图伪装在线画面。跨域、混合内容、媒体格式不支持和媒体服务离线应显示不同诊断。

## 与视觉 AI 共用视频源

同一个媒体源可以同时用于看板播放和视觉识别任务。视觉任务只读取经过授权的源引用、采样帧和告警规则；停用或删除视觉任务不会停止看板监控。删除媒体源前必须先显示所有看板和视觉任务引用。

视觉告警可以通过场景绑定高亮三维对象，也可以写入 Data Hub 后驱动二维状态组件。告警框、置信度和原始事件仍由视觉运行时提供，聊天模型只能解释，不能修改检测结果。

## 发布前检查

- 图片加载成功，比例和裁切符合目标大屏。
- 普通视频在无用户手势时能以静音方式播放；需要声音时检查目标类型，Deep Native 当前会阻断音频输出。
- 真实 HLS 监控源出现首帧；断开源后出现诊断，恢复源后自动重连。
- HTTPS 页面没有引用 HTTP 媒体；媒体服务和对象存储跨域策略正确。
- 视觉 AI 插件停止后，看板监控仍持续播放。
