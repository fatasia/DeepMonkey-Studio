# Code of conduct

Deep Monkey Studio expects technical collaboration to stay direct, evidence-based, and respectful.

## Expected behavior

- Discuss the work and its effects rather than attacking the person.
- Give reproducible evidence for defects and concrete reasoning for design objections.
- Accept correction, disclose uncertainty, and update claims when evidence changes.
- Respect privacy, security embargoes, licenses, and confidential information.
- Keep review focused; do not use status, access, or repetition to silence a good-faith technical concern.

## Unacceptable behavior

Harassment, threats, targeted insults, discrimination, sexualized attention, doxxing, deliberate exposure of secrets, impersonation, spam, and knowingly misleading technical or security claims are not acceptable in project spaces.

## Enforcement

Report conduct concerns privately to the repository owner or a maintainer through the repository host's private contact mechanism. Include links or evidence and state whether immediate action is needed. Do not publish private personal details to prove a report.

Maintainers may edit or remove content, lock a discussion, issue a warning, restrict participation, revoke repository access, or permanently ban a participant. Enforcement considers severity, impact, pattern, intent, and correction. A maintainer named in a report must not decide that report alone; the Project Steward appoints another reviewer where possible.

This code applies to Issues, Pull Requests, reviews, Discussions, release channels, project events, and public representation of the project.
