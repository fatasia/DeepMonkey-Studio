# 平台总体架构

Deep Monkey Studio 把模型、设备数据和智能服务组织成可编辑、可发布的工业应用。创作层负责表达业务，兼容层连接图形生态，基础平台提供渲染、数据处理和任务执行。

![平台总体架构](../apps/web/public/docs-assets/generated/platform-architecture-gold.png)

## 创作与扩展

2D 编辑器组织看板、图表、媒体和页面交互；3D 编辑器组织模型、材质、灯光、相机与 BIM 操作。脚本编辑器通过事件和 `studio` API 连接对象行为与数据变化。插件在宿主支持的扩展点提供面板、场景能力和格式转换。

这些入口共享项目、资源和应用上下文。用户从二维页面进入三维编辑，再配置脚本，不需要维护三套独立工程。

## 图形与资源兼容

Unity 集成承载 WebGL 内容、消息交互与资源版本。Three.js 场景桥把宿主场景对象、相机、材质和渲染状态投影到对应后端。它们连接现有图形资产与平台场景合同；数据查询和模型调用通过各自的服务接口执行。

## 四个基础平台

| 平台 | 职责 | 主要输出 |
| --- | --- | --- |
| 图形引擎 | WebGPU / Native 渲染、PBR、阴影、LOD、资源流送与 Deep2D | 场景画面、运行包与渲染诊断 |
| AI 中台 | 工程问答、看板生成、视觉识别、模型接入与能力发现 | 可审查草稿、识别记录与结果证据 |
| 数据中台 | 连接器、数据集、流水线、字段映射与接口发布 | 可测试的数据输出和场景绑定 |
| 大模型 Harness | 上下文装配、任务编排、工具调用、写入审批、预算与断点恢复 | 有执行记录和验证结果的任务 |

AI 中台组织面向用户的智能能力；Harness 管理任务如何调用工具、等待审批、恢复执行并检查结果。模型回答与工具执行结果分别记录。

## 接入、交付与治理

BIM/CAD/glTF 模型、设备协议、消息流、数据库、视频源和模型服务进入对应处理链。场景完成预览和体检后，可发布 Web 运行版或按目标生成版本化交付包。

身份认证、项目授权和凭据隔离覆盖服务调用；发布体检、版本追溯和健康诊断支持交付与维护。图中按职责组织能力，具体可用范围取决于版本、后端与部署配置。
