# Industrial Studio 产品体验收敛规划

状态：执行基线 v1<br />
日期：2026-09-02<br />
适用分支：`dev-studio`

## 1. 目标

把 Industrial Studio 从“模块和按钮基本齐全”收敛为真正可连续完成工作的工业数字孪生产品。验收不看功能数量，重点看用户能否从项目进入，找到资源，完成 2D/3D/拓扑编辑，连接数据，编写行为，预览并发布，而且每一步都知道当前状态、下一步和失败后的恢复方式。

本规划是后续 UI、交互与流程优化的执行入口。原有技术升级计划继续保留为架构背景，但产品体验工作的优先级、批次和验收以本文为准。

## 2. 产品原则

1. 任务优先：页面首先服务用户任务，不为展示功能而占空间。
2. 单一心智模型：项目、场景、页面、资源、对象、数据产品、行为脚本各有唯一含义。
3. 上下文不丢失：2D、3D、拓扑、脚本之间切换时保留当前项目、页面、场景、选中项和视图状态。
4. 渐进呈现：常用动作直接显示，高级能力按选择和任务展开。
5. 原始资源优先：模型、图片、材质和模板保留原始视觉；主题色只用于交互状态。
6. 所见即所得：预览、缩略图、编辑画布和发布结果使用同一份数据与渲染规则。
7. 无死按钮：可见动作必须可执行，暂不可用时给出原因和解决入口。
8. 可恢复：保存、撤销、失败、断线、重载和运行错误均有明确状态与恢复路径。
9. 可验证：每一项改动都要有自动化断言、真实浏览器截图和关键路径操作证据。

## 3. 明确不在本阶段

- 多人协作、评论、负责人、审批中心和审批流。
- 开发、测试、生产多发布环境。
- 私有化安装、升级、备份、回滚和审计导出。
- 为追求竞品外观进行像素级复制；只复用成熟的信息架构和交互规律。
- 轻 3D 方案不考虑。查看端性能通过真实三维的分级加载、LOD、按需渲染和明确降级提示解决，不建设预渲染图片式轻 3D 分支。

高风险动作只做当前用户的一次就地确认，不引入负责人、队列或流程状态。

### 4.1 已重新实测的运行态

- 项目管理、资源中心、数据中心、视觉中心、智能运营、模型优化、设置、文档。
- 2D 编辑器、3D 编辑器、脚本分屏/悬浮/隐藏、拓扑 2D/2.5D。
- 2D 三维组件双击进入 3D、左右面板收起、场景目录 Ctrl 多选、编组、右键操作。
- 资源中心加载 1,510 个模型/环境/材质资源，2D 资源 156 个，工业预制体 78 个。
- 数据中心已形成“接入数据 → 处理逻辑 → 发布接口”的主链，处理区包含数据集、过滤、输出和运行结果。

截图证据位于 `test-output/current-ui-audit-2026-09-02/`。后续每批次沿用同一目录规范，禁止引用历史版本截图作为当前结论。

- 统一品牌名 Industrial Studio 与第三版 Logo。
- 项目页场景卡常用动作外置，卡片支持预览、编辑、发布、复制链接和重命名。

- 3D 场景目录已改为单行、支持多选、编组、拖入拖出和右键批量操作。
- 3D 已有统一资源入口；资源插入、代理显示和场景保存链路存在。
- 脚本编辑器已嵌入工作区，支持分屏、悬浮和隐藏。
- 拓扑 2.5D 已使用等距网格、层高和节点阴影，不再是简单倾斜 2D。
- 拓扑属性已有名称、类型、坐标、层高、数据绑定和扩展属性。
- 资源缩略图与 2D 预览已开始保留原始或语义颜色，不再全部套系统金色。
- 源文件硬上限 800 行、发布级验证和多组浏览器门禁已经存在。

## 6. 竞品规律与采用边界

### 山海鲸

采用：项目缩略图随保存更新；资源中心作为独立发现入口；编辑器围绕资源、画布、属性形成稳定三栏；数据连接覆盖文件、API、WebSocket、数据库和物联网协议；常见任务有连续教程路径。

不采用：把协同、私有云和部署体系带入当前阶段；把所有能力同时塞入首屏。

### ThingJS

采用：脚本与场景上下文绑定；代码、预览和运行诊断在同一工作区；脚本窗口可分屏、悬浮、隐藏；错误能回到具体脚本位置。

不采用：单独复制其视觉皮肤或把脚本编辑器变成另一个孤立产品。

### Unity

采用：Hierarchy 负责层级与选择，Inspector 只负责当前上下文；库资源可拖入层级或视口；多选、拖拽、重命名、快捷键和右键指向同一命令；检查器允许扩展字段。

不采用：把游戏引擎全部专业概念暴露给数字孪生业务用户。

### 图扑、帆软、西门子类平台

采用：拓扑/SCADA 的节点、端口、连线和数据状态清晰分层；报表与数据绑定强调字段结构、预览和错误诊断；工业操作页先给状态、风险和动作，再给工程细节。

采用前必须在 Industrial Studio 当前任务中证明价值，不新增只用于演示的模块。

### 轻 3D 决策

轻 3D 不进入产品路线，不做预设相机帧、热区或图片式三维替代方案。低配终端优先通过真实三维资源分级、LOD、流式加载、按需激活和性能诊断解决，确保编辑与查看共享同一对象语义。

## 7. 分批执行路线

### 批次 0：冻结规则与消除低级错误（P0）

目标：先统一产品语言和基础交互，不让后续模块继续各自生长。

- 建立术语表、导航层级、按钮等级、状态文案和面板行为规范。
- 全局统一“资源”“设置”“确认”等文案，清除本阶段排除项。
- 修复图标按钮名称、表单标签、场景树键盘行为、焦点可见性和标题层级。
- 统一返回、关闭、Esc、浏览器后退和未保存修改处理。
- 将颜色、间距、字号、行高、圆角、阴影、状态色收敛到设计令牌。

验收：静态术语扫描无冲突；核心页无无名控件；键盘可完成导航和选择；1280×720、1440×900、1920×1080 无遮挡或横向溢出。

### 批次 1：项目管理与资源闭环（P1）

用户故事：作为项目编辑者，我希望从项目页看清最近场景状态并直接预览或继续编辑，不进入多余管理页。

- 项目页首屏只保留项目切换、搜索/筛选、新建/导入和场景卡。
- 开发流程收为单行续作提示，可展开查看，不占默认版面。
- 场景卡缩略图来自最近保存或发布结果；常用动作外置，低频动作进入更多。
- 资源中心加入最近使用、收藏、项目资源和来源/许可筛选。
- 从资源浏览页进入编辑器时带入插入目标和当前场景，避免“只浏览不能使用”。

验收：3 次点击内打开目标场景；卡片动作不误触；1,500 项资源搜索首屏反馈小于 300ms；资源插入后可撤销。

### 批次 2：统一编辑器壳层（P1）

用户故事：作为编辑者，我希望在 2D、3D、拓扑和脚本间切换时不丢上下文，并随时收起无关面板。

- 固定顶部顺序：返回/项目上下文 → 模式 → 当前对象/名称 → 历史 → 预览/发布/保存。
- 左右面板均可独立收起和恢复，并记住当前用户布局。
- 统一单选、多选、空选、右键、拖拽、删除、撤销、保存反馈。
- 统一底部状态栏，只显示数据状态、选中数量、联动状态、缩放或场景统计。
- 建立跨模式上下文对象，保存页面、场景、选中项、视口和脚本目标。

验收：2D→3D→脚本→2D 往返后页面、选择和视口保持；所有命令可从菜单和快捷键到达；无重复保存入口。

### 批次 3：2D 编辑器产品化（P1）

- 左侧保持“页面与图层 / 资源”两种任务，不恢复多余第三层导航。
- 页面与图层使用单行紧凑树；支持搜索、Shift/Ctrl 多选、编组、拖层级和右键。
- 资源按业务任务、图表、报表、媒体、控件、3D/GIS 分类，最近使用优先。
- 每个资源缩略图使用真实结构、语义颜色和示例数据，不用同一占位图。
- 右侧严格按空选=页面、多选=批量、单选=资源实例属性切换。
- 样式、数据、交互、动画分组，常用项默认展开，高级 JSON 或脚本按需出现。

验收：新用户能在 5 分钟内完成“插入图表→绑定数据→配置交互→预览”；页面信息不与实例属性同时出现；多选批量操作可撤销。

### 批次 4：3D 与拓扑编辑深化（P1）

- 场景目录补全 treeitem 语义、键盘选择、批量属性和保存选择操作名称。
- 3D 资源使用真实缩略图或类别差异化预览；插入后自动聚焦并打开关键属性。
- 颜色调整区统一色相、饱和度、亮度、对比度、透明度、重置和原始材质切换。
- 拓扑节点库支持搜索、折叠、最近节点和拖入；属性检查器支持 Schema 驱动扩展。
- 2.5D 保持等距规则，层高只影响空间关系，不改变文字可读性；连线交叉和标签避让必须可读。

验收：Ctrl 多选、编组、拖入拖出、右键、撤销全部实测；拓扑节点/边/扩展属性保存重载一致；100+ 节点仍可平滑编辑。

### 批次 5：脚本与数据开发闭环（P1）

- “挂载到”改为可搜索选择器，按场景/页面和对象/二维资源分组，同名项显示上下文。
- 脚本列表、代码、运行日志、错误定位和资源引用保持同屏；分屏宽度可拖动并持久化。
- 数据连接采用向导：类型 → 地址/凭据 → 测试 → Schema → 保存。
- 数据处理采用线性主路径和高级图模式双层体验；节点显示输入/输出 Schema、样例和错误。
- 发布接口包含路径、方法、参数、样例响应、鉴权提示、试调用和复制调用示例。

验收：数据库首次接入、字段清洗、样例运行、REST 发布全程不需要离开数据中心；连接失败、SQL 错误、字段变化和接口冲突都有恢复说明；脚本运行错误可一键回到行列并修复重跑。

### 批次 6：视觉、智能运营与 AI 收敛（P2）

- 视觉任务明确输入源、模型、规则、三维绑定、运行状态和输出记录。
- 智能运营首页改为“风险/异常 → 建议动作 → 证据 → 模型详情”，不先展示工程参数。
- 不同运营场景使用同一任务壳层，避免维护、调试、电池、物流、能耗各写一套布局。
- AI 只生成草稿、解释和建议；任何写入先显示差异并由当前用户确认。

验收：每个模块至少有一条真实输入到可验证输出的主路径；0 数据、部分数据、断线、模型不可用和权限不足均有明确状态；界面不出现审批队列或多环境概念。

### 批次 7：质量门禁与发布证据（持续，最终收口）

- 拆分接近 800 行的组件，首批处理 `SceneBehaviorPanel.tsx`、`DashboardWorkspace.tsx`、`App.tsx`、`TopologyEditorPanelView.tsx`、`OperationsCenter.tsx`。
- 为每个核心用户旅程建立稳定的浏览器用例，不只断言页面出现。
- 加入无障碍、控制台错误/警告、响应式溢出、资源加载性能和保存恢复门禁。
- 每次改动先跑聚焦测试；每个批次结束跑 Web 全量；最终跑 `pnpm verify:release`。

验收：无可控控制台错误或警告；源文件不超过 800 行，新增复杂文件目标小于 400 行；发布级验证全绿；最终截图和测试报告来自相同提交状态。

## 8. 核心测试矩阵

| 旅程 | 必测 happy path | 必测失败/恢复 | 证据 |
|---|---|---|---|
| 项目→场景 | 搜索、预览、编辑、复制链接、重命名 | 空项目、重复名、预览失败 | DOM 断言 + 截图 |
| 2D→3D→2D | 双击进入、返回保持上下文 | 场景缺失、加载失败 | E2E + 状态快照 |
| 场景组织 | Ctrl/Shift 多选、编组、拖动、右键、撤销 | 锁定、无效拖放、删除恢复 | E2E + 重载验证 |
| 资源插入 | 搜索、筛选、插入、调色、撤销 | 缩略图失败、资源损坏 | E2E + 视觉回归 |
| 脚本 | 选目标、编辑、运行、日志、悬浮/分屏 | 编译错、运行错、目标删除 | Worker 测试 + E2E |
| 数据 | 连接、Schema、处理、运行、发布、试调用 | 凭据错、超时、SQL 错、Schema 漂移 | API + E2E |
| 拓扑 | 插节点、连线、2.5D、数据绑定、扩展属性 | 循环/断边、无数据、保存冲突 | 单元 + E2E |
| 视觉/运营 | 输入→模型→结果→场景/建议 | 无源、模型失败、数据过期 | API + E2E |
| 发布 | 预览、发布、复制链接、重新发布 | 校验失败、版本不一致 | 发布门禁 + 截图 |

## 9. 每批次 Definition of Done

- 用户故事和 Given/When/Then 验收已写入测试或审计记录。
- 新旧术语、空态、错误态和恢复态都已核对。
- 相关单元/组件/API 测试通过。
- 真实浏览器按至少三个桌面分辨率走完主路径。
- 键盘操作、焦点、控件名称和颜色对比通过。
- 无新增控制台错误或产品可控警告。
- 截图、日志和测试报告保存到带日期的证据目录。
- 代码大小、类型检查和格式检查通过。
- 未把“不在本阶段”的能力偷偷带回界面或文案。

## 10. 执行顺序与变更纪律

严格按批次 0 → 1 → 2 → 3 → 4 → 5 → 6 推进，批次 7 贯穿全程。一个批次未通过 Definition of Done，不进入下一个批次。

每次只处理一个可验证的用户旅程。先记录当前截图和失败证据，再修改，再跑聚焦测试与浏览器复测。禁止仅凭代码存在就判断功能可用，也禁止用旧截图证明新版本。

当前第一执行项：完成批次 0，统一术语、设置入口、确认语义、返回规则和编辑器基础无障碍；随后重新跑项目管理与编辑器主链，形成第一份稳定基线。
