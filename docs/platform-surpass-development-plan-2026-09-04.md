# 全面超越开发展计划（新一轮范围冻结）

状态：规划 v1（2026-09-04 用户定义新轮范围，GLM-5.3 规划）
适用分支：`dev-studio`
与并行轮次的关系：夜间极致优化轮（`nightly-extreme-optimization-plan-2026-09-04.md`）继续打磨既有体验；本轮新增能力开发。两者共用门禁体系，互不阻塞。

## 1. 用户决策记录（2026-09-04）

用户原话归纳，七项能力纳入计划：

1. 数据语义层、填报/打印（中国企业刚需）。
2. 素材与模板数量和质量、深度。
3. ThingJS 生态（公开 SDK/API 体系）。
5. Unity 性能（数字孪生负载下持平）。
6. 差异化路径：Web 原生协作、秒级预览、数据+AI+看板一体闭环、Study 证据链。
7. AI 模块能力升级。

载体优先级：**最高——2D 编辑器、3D 编辑器、脚本编辑器、数据中心；其次——AI 与西门子仿真（Plant/PS/PD Lite 深化）。**

本轮取代总计划 §28.1"不再新增功能域"的旧冻结；§28"明确不再执行"排除清单（Docker、Babylon、UE5、移动端、完整 OLP/PLM、认证人体工效、厂商控制器矩阵、8 小时 WebGPU soak 等）**继续有效**，本轮不触碰。

## 2. 批次计划（S1→S7，按依赖排序）

> 2026-09-04 用户追加最高优先级反馈：核心编辑器与数据中台**交互逻辑**不达标，学习 ThingJS/山海鲸/帆软。据此插入 EX 交互批次（`docs/editor-interaction-benchmark-2026-09-04.md`）：S1-001 之后、S1-002 之前先做 EX-001（2D 画布交互）→ EX-002（字段拖拽绑定+数据面板）→ EX-003（联动/钻取交互）；S1-002/S1-003 直接按 EX-002/EX-003 的新交互实现，同一面板不做两遍。EX-004~EX-007（3D/脚本/素材模板/数据中台向导）与 S3/S4/S5 插排。

### S1 数据语义层（数据中心，最高优先，先行）

FineBI 级语义能力的可交付子集，是 S2/S6 的地基。

- 语义模型：数据集 → 字段 → 指标（度量）/维度/计算字段/层级，集中管理、版本化、可检索。
- 组件自动联动：同一语义模型的看板组件默认联动（点选过滤其它组件），可关闭、可手动配置联动关系。
- 钻取：指标 → 明细 → 原始记录路径，钻取目标可配。
- 级联参数：参数组件按语义层级级联（省→厂→车间→设备）。
- 2D 数据绑定升级：绑定面板按语义模型呈现而非裸字段。
- 验收：真实连接器数据集上完成"建模型 → 绑定 → 联动 → 钻取 → 级联"全链浏览器门禁；语义模型保存/恢复/迁移有测试；AskData 改走语义层（S6 依赖）。

### S2 填报与打印（2D 编辑器 + API，最高优先）

FineReport 核心场景的可交付子集。

- 填报组件：输入框/下拉/日期/表格编辑，绑定语义字段与写入目标。
- 写回链路：填报提交 → API 校验 → 数据源写入（SQL/REST），含权限、乐观锁与冲突提示；与既有"草案—确认—撤销"模式一致。
- 打印版式：2D 页面声明打印分页/页眉页脚/缩放，打印预览所见即所得。
- 导出：PDF、Excel（含数据表格）、图片，导出与发布浏览同渲染规则。
- 验收：填报→写回→再查询闭环 E2E；打印/导出与屏幕渲染一致性对比；空值/校验失败/写回冲突有明确状态。

### S3 素材与模板深度（2D/3D 编辑器，最高优先）

从"数量门槛"到"行业深度"。

- 行业深度包：按行业（电力、水务、化工、汽车、烟草、物流等）成套交付 2D 模板+3D 预制体+示例数据，每套可预览、可编辑、可绑定语义模型、可发布，不做空壳。
- 质量线：模板必须通过"打开→改数据→发布"三步真实工作流验证；3D 预制体参数/动作/数据端口齐全；缩略图真实反映结构。
- 数量目标：行业深度包 ≥10 套（每套 2D 模板 5-10 页 + 匹配 3D 资产）；外部 GLB 发布门槛流程不变。
- 用户资产：上传、收藏、最近使用、项目内复用形成闭环（部分已有，补齐）。
- 验收：每套深度包有浏览器走查记录与发布产物；门禁断言真实可编辑而非骨架。

### S4 公开 SDK 生态（脚本编辑器，对标 ThingJS，最高优先）

- `studio.*` 公开 API 版本化合同：对象/场景/数据/动画/交互命令，TypeScript 类型完整，破坏性变更走主版本。
- 开发者文档：文档中心新增 SDK 参考 + 可运行样例库（每样例可一键插入脚本编辑器运行）。
- 插件流程：打包、清单、安装、启用/禁用、版本兼容矩阵、故障隔离（plugin-runtime 基础上补产品化交互）。
- 验收：第三方视角仅凭文档完成"样例 → 修改 → 运行 → 打包插件 → 安装到另一项目"；兼容矩阵有自动化测试。

### S5 Unity 级性能（3D 编辑器/viewer，最高优先）

数字孪生负载下的性能与保真度，不做游戏引擎。

- 大模型：分块/流式加载、LOD 分级、按需激活；首帧可交互时间预算（如 ≤5s/亿三角面量级，以真实夹具定标）。
- 长任务消除：主线程 >50ms 任务清单化治理，加载/解析进 Worker。
- 交互帧预算：编辑器操作（选择、拖拽、剖切、爆炸）P95 帧时间门禁；空闲按需渲染降帧。
- 规模：10k+ 对象 instancing 压力夹具与门禁。
- 保真：后处理/XR 画质矩阵在 WebGL/WebGPU 双后端一致性证据（继承既有 SSIM/PSNR 方法）。
- 验收：以上各项进入 `benchmark:render-engines`/product-browser 门禁数字，不回退。

### S6 差异化闭环（跨编辑器+数据中心，最高优先，依赖 S1）

- 秒级预览：编辑 → 预览切换 ≤2s 目标（不重建产物），发布浏览与预览同链路。
- 数据+AI+看板一体：AI 看板生成/修改改走语义层；AskData 结果一键落看板组件；AI 结论可追溯到数据集与查询指纹。
- Study 证据链扩展：2D 看板数据快照与 Study 结果互链（运营中心首屏 → 证据 → 工作台往返）。
- Web 原生协作（分期）：一期=在线状态、项目/场景编辑锁、变更通知；二期=轻量实时协同（评论与选区共享）；完整 CRDT 共编不在本轮。
- 验收：预览延迟门禁；AI 生成看板走语义层且可撤销；协作一期在在线门禁中有并发冲突用例。

### S7 AI 升级与西门子仿真深化（二级优先）

- AI：Provider 升级（GLM-5.3 等新模型接入与能力协商）、语义层感知的 AskData、AI 脚本生成质量评测集、工业 Agent 任务编排深化。
- 仿真：Plant/PS/PD Lite 在既有边界内深化——更多离散事件元素、机器人轨迹编辑体验、PPR 变更影响分析；统一 Study 谱系不变。
- 验收：AI 评测集通过率门禁；仿真聚焦测试扩充且不回退。

## 3. 执行模型：白天出规格，夜间照规格实现

- 白天（GLM-5.3/GPT-5.6）：为每个批次任务写实现规格——目标、触碰文件、合同/类型定义、测试计划、验收命令、风险与回滚点。规格存 `docs/specs/<批次>-<任务>.md`。
- 夜间（GLM-5.3-Flash 免费时段）：按规格实现 + 写测试 + 跑聚焦门禁；规格外发现的问题按夜间方案 §7 三档规则处理。**夜间可以新增功能代码，但仅限规格内任务；规格未覆盖的一律记录不展开。**
- 每批次完成定义：规格验收全过 + 相关门禁绿 + 总账回填 + 浏览器证据。

## 4. 排序与依赖

S1 → S2 →（S3/S4/S5 可并行插排）→ S6 → S7。
S1 是 S2、S6 的硬依赖，必须最先闭环；S3/S4/S5 相互独立，按夜间产能轮转；S6 依赖 S1 与 S5 的预览性能基础；S7 永远排后不抢占一级载体产能。
