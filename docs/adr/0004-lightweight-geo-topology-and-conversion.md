# ADR-0004: 保留轻量 GIS、独立拓扑与通用转换插件

## Status

Accepted

## Context

iTwin Studio 需要城市地图底板、轻量 GIS、工业拓扑和多种资源导入能力，但产品仍要求简洁、高效和低耦合。如果把地图、拓扑、转换全部塞进二维画布或三维引擎，会形成巨大编辑器；如果按飞渡式重型地理平台建设，又会引入 3D Tiles、倾斜摄影、地形/点云生产和复杂运维。

## Decision

- 保留独立 `Map/Geo`、`Topology` 与 `Converter` 模块，通过 Studio Core 的稳定 ID、命令和 `InteractionFlow` 与二维、三维协作。
- 轻量 GIS 支持在线/离线底图、XYZ/WMTS/WMS 栅格服务、GeoJSON 点线面、标记/轨迹/区域、基础热力、坐标转换和 `GeoAnchor`。
- 同一个 `MapProvider` 适配层服务二维地图组件和三维底图层；地图密钥、版权、离线范围和缓存策略只在服务器配置。
- `TopologyDocument` 独立保存节点、端口、边、分组、布局和数据绑定；通过 `TopologyViewportWidget` 嵌入二维页面，并可绑定三维对象。
- `ConverterPlugin` 统一声明输入/输出类型、配置 schema、执行环境、版本和资源上限；任务提供进度、取消、日志、超时、重试、缓存和失败清理。
- 2026-08-26 范围修订：Parasolid `.x_t/.x_b` 与 JT `.jt` 不进入产品支持范围，删除对应入口与 Provider 骨架；转换能力集中于已能持续验证的常用格式。
- Tauri 最终阶段使用受限 sidecar 运行本地转换；此前 B/S 使用服务器隔离 Worker。首批只迁移现有真实转换能力，不承诺内置所有格式。
- 不建设 3D Tiles、倾斜摄影、海量地形/点云、城市级三维流式加载和通用空间分析平台。

## Non-Functional Requirements

- 底图或地图 Provider 不可用时，页面、拓扑、三维模型和项目保存保持可用。
- 坐标系必须显式记录；WGS84、GCJ-02、BD-09 与项目局部坐标使用黄金样本验证。
- 相同输入哈希、转换器版本与配置产生可复用的确定性产物。
- 转换任务可以取消、超时和失败清理；插件只能访问任务声明的输入、输出、文件和网络能力。
- 1000 节点、2000 边拓扑基准中，平移、缩放和选择 p95 低于 100 ms；自动布局在 Worker 中执行且可取消。
- 离线瓦片缓存有项目/Provider 配额、清理策略和版权元数据，不能无限占用客户端或服务器磁盘。

## Consequences

### Positive

- 满足城市底图、工业空间定位、工艺/网络拓扑和多格式资产接入。
- 地图、拓扑和转换故障不会污染场景编辑核心。
- 二维、地图、拓扑和三维通过统一实体 ID 双向联动。
- 新格式可以独立交付，不需要修改编辑器主包。

### Negative

- 增加三个清晰模块及相应测试，产品范围和维护成本高于完全不做。
- 国内地图坐标、版权、离线缓存和第三方密钥需要部署治理。
- 原生转换插件仍有供应链和资源消耗风险，需要签名、隔离与配额。

### Neutral

- 拓扑拥有独立编辑模式，但可以作为组件嵌入看板；地图作为二维组件和三维图层，不新增一级编辑器。

## Failure Modes

| Failure | Impact | Mitigation |
| --- | --- | --- |
| 地图服务离线/限流 | 底图空白 | 缓存、备用 Provider、明确降级状态，不阻塞其他编辑 |
| 坐标系配置错误 | 地图与三维错位 | 显式 CRS、转换预览、控制点校准和黄金样本测试 |
| 转换器崩溃/超时 | 单个资产导入失败 | 隔离进程、资源限额、取消、清理和可重试任务 |
| 恶意转换插件 | 文件或网络越权 | 签名、白名单、最小文件/网络权限和审计 |
| 拓扑自动布局耗时 | 编辑器卡顿 | Worker、取消、增量结果和规模预算 |

## Alternatives Considered

**完全删除地图、拓扑和转换平台**：拒绝。无法覆盖城市底图、工业流程网络和真实项目格式接入。

**建设完整重型 GIS/大场景平台**：拒绝。3D Tiles、倾斜摄影、地形/点云和空间分析超出当前产品边界。

**把拓扑做成普通看板图层**：拒绝。端口、连线、自动布局和大规模选择需要独立文档与编辑交互。

**允许转换插件直接运行在浏览器主线程**：拒绝。原生格式、资源消耗和故障无法安全隔离。
