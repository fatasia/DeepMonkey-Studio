# Dev Studio M0–M9 整体评估与整改门禁

评估日期：2026-08-25。分支：`dev-studio`。

## 结论

当前工程已经形成 2D/3D/Data Hub/模型转换/拓扑与轻量地图/插件/发布/Tauri 与云渲染协议/M8 仿真/M9 文档的可运行骨架，自动化测试、类型检查和生产构建基线稳定。它还不能被诚实地定义为“完整超过 ThingJS、FineBI/帆软、山海鲸、51WORLD 与 Unity”：M0–M9 的方向和若干纵向切片已落地，但产品深度、真实云渲染、WebGPU 对等性、持续浏览器验收和大型项目性能证据仍有明显缺口。

旧项目和旧场景无需兼容，但旧版已存在的业务能力不得下降。后续重构以原生 `ApplicationDocument` 为唯一事实源，删除双轨数据模型，不保留兼容包袱。

## 已验证基线

- 全仓库现有自动化基线为 478 项测试，覆盖 desktop、contracts、docs runtime、Data Hub、scene、server、studio core、API、web、插件和 Factory Flow；本次变更完成后必须重新执行全量测试、类型检查和生产构建。
- 使用真实浏览器完成项目创建、场景创建、默认进入 2D、进入/返回 3D、WebGPU/WebGL2 切换、4K 看板尺寸保存与恢复、临时项目删除。
- 2D 在 1920×1080、1440×900、1280×720、980×720 未发现文档级溢出或关键按钮越界；3D 在前三档通过，980×720 首轮发现顶部工具坞末项越界，改为响应式换行后复测 22 个工具按钮均位于视口内。
- 空场景 WebGPU/WebGL2 烟测只证明两种后端能初始化和持续渲染，不能用于性能排名；正式方法见 [渲染性能基准](./rendering-performance-benchmark.md)。
- 本机有 RTX 4060 Laptop GPU，但没有可用 Unity Editor；尚未产生公平的 Unity 对照结果。

## P0：发布前必须解决

1. **唯一事实源与原子保存**：三维仍存在旧 `SceneSnapshot` 与 `ApplicationDocument` 双路径，场景和应用分步保存可能出现部分成功。迁移为 ApplicationDocument 原子保存后删除旧编辑路径。
2. **真实浏览器质量门禁**：建立 Playwright 主流程、固定分辨率截图、布局几何、console/pageerror、网络失败和键盘可达性检查；CI 不再只依赖组件测试。
3. **排版与可读性**：当前样式中大量 7–9 px 正文字号。建立最小字号/行高/token 门禁，并逐页校正信息密度、截断、空态和缩放。
4. **真实云渲染**：当前 `RemoteRenderSession` 主要是控制面状态机，没有完整 GPU Worker、硬件编码器、WebRTC 媒体、输入 DataChannel 与资源回收证据。必须做到已发布版本一键启停；只有真实首帧和内容哈希探针通过才能显示已开启。
5. **WebGPU/WebGL2 功能对等**：WebGPU 仍是实验路径，后处理与 XR 等能力不完全对等。按功能矩阵和 R1–R5 工作负载决定默认后端，能力缺失时可解释地回退 WebGL2。
6. **大型包与启动性能**：当前 ViewerEngine、Worker、Rapier 和主包过大，`App.tsx`/`ViewerEngine.ts` 体积过于集中。按路由/能力懒加载，建立 chunk、首屏、显存和场景切换预算。
7. **脚本安全**：普通发布只允许 Worker 沙箱与公开 Scene SDK；主线程 `AsyncFunction` 只能作为管理员签名的可信扩展路径，并显示权限、预算和审计信息。

## P1：形成主流产品竞争力

- 3D：补齐可扩展 Hierarchy/Inspector、对象组件、撤销历史、可保存布局、时间线/Profiler、专业相机与大模型诊断；保留 BIM 构件/空间/剖切/视觉联动优势。
- 2D：补齐跨组件筛选、钻取、级联参数、模板、表格与图表高级配置、条件格式和可视化联动诊断；持续验证用户自定义分辨率与大屏适配。
- 媒体：图片、普通视频和实时监控必须在 2D 设计/预览/发布路径一致可用；统一媒体源可同时被看板播放和视觉任务引用，但视觉插件故障不得中断监控播放。
- Data Hub：区分“已安装可运行”和“目录中可选”连接器；普通问数走受控语义计划，不以任意 SQL 生成为主入口。
- 多场景：通用层级节点只声明父子关系、场景/页面目标、进入相机和 `focus/replace/additive` 策略；恢复每节点相机、筛选、选择与面板状态，加载失败时父场景保持可见。
- M7 桌面：补安全令牌、OAuth 回调、本地恢复点、上传续传、安装/更新和服务器地址迁移的真实端到端证据。
- 模型：x_t 采用可安装转换 Provider 并在 UI 显示能力/状态；JT 无可靠 Provider 时明确不支持，不做假入口。
- AI：保留现有 BIM 问答和视觉中心，以统一上下文/证据/路由协议接入 AskData 与预测维护；专业工作台不被泛聊天替代。

## P2：成熟度提升

- 完善文档内容、API 示例、断链/版本 CI、错误深链和无障碍语义。
- 增加行业无关的通用多场景模板，以及独立的工业物流成熟案例；案例资源必须许可清晰并可离线复现。
- 建立错误预算、崩溃恢复、性能趋势、插件兼容矩阵和发布回滚演练。

## 最终验收矩阵

| 轴 | 核心证据 |
| --- | --- |
| 页面与交互 | 1920/1440/1280/980、4K、自定义尺寸无错误排版；主任务可连续完成；键盘/空态/失败态通过 |
| 稳定性 | 全量测试、浏览器 E2E、保存故障注入、崩溃恢复、20 次场景切换和 8 小时运行 |
| 本地性能 | 同资产/画质下 WebGPU、WebGL2、Unity 的帧时间、显存、首帧与画质对照 |
| 云渲染 | 与 Unity Render Streaming 同 GPU/编码器/网络矩阵比较输入到画面延迟、冻结帧、画质、并发和成本 |
| 可编程性 | 锁定 Three.js 能力矩阵；常用能力编辑器可配，复杂能力公开 SDK 可写，底层能力签名扩展可装 |
| 能力不下降 | BIM/模型/场景/看板/图片/视频/实时监控/数据/视觉/拓扑/地图/发布能力清单逐项回归；不验证旧文件兼容 |

“超过 Unity/ThingJS/帆软/山海鲸/51WORLD”只能按上述具体工作负载和体验指标分别下结论，不使用空场景 FPS、功能数量或未接媒体的状态机代替产品证据。
