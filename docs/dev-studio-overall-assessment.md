# iTwin Studio M0–M9 整体评估与整改门禁

评估日期：2026-08-28。分支：`dev-studio`。

> 本文保留 2026-08-28 的阶段性评估和差距判断；最终验收数字、默认折叠交互和当前门禁结果以 [产品体验与发布闭环报告](./release-closure-2026-08-31.md) 为准。

## 结论

当前工程已经形成 2D/3D/Data Hub/模型转换/拓扑与轻量地图/插件/发布/Tauri、真实单节点云渲染、M8 仿真和 M9 文档的可运行纵向切片，自动化测试、类型检查和生产构建基线稳定。它还不能被诚实地定义为“完整超过 ThingJS、FineBI/帆软、山海鲸、51WORLD 与 Unity”：差距已从“功能入口缺失”转向专业编辑深度、低代码分析、公开 SDK、WebGPU 对等性和产品级交互门禁。

旧项目和旧场景无需兼容，但旧版已存在的业务能力不得下降。后续重构以原生 `ApplicationDocument` 为唯一事实源，删除双轨数据模型，不保留兼容包袱。

## 已验证基线

- 全仓库自动化基线为 783 项测试，覆盖 desktop、contracts、docs runtime、Data Hub、scene、server、studio core、API、web、云渲染 Worker、插件和 Factory Flow；当前 `pnpm verify:release` 已串联全量类型检查、源码体量门禁、测试、生产构建、API import smoke、包体预算、生产包 QA 隔离、确定性浏览器验收和真实在线主流程门禁。
- 已有固定分辨率浏览器回归记录覆盖项目创建、场景创建、默认进入 2D、进入/返回 3D、WebGPU/WebGL2 切换、4K 看板尺寸保存与恢复、临时项目删除；本地 JSON/对象存储在线闭环已经自动化通过。当前产品目标是单机/私有化部署，不把多节点和高并发容量作为 P0；仍需持续执行断网恢复、保存保护、Worker 崩溃、备份回滚和短时稳定性门禁，不能把本机闭环描述成完整部署验收。
- 新增 `pnpm gate:product-browser`：使用显式测试构建变量生成与正式代码同优化级别的确定性验收包，在 1440×900、1366×768、1024×768 三档 Chrome 视口完成 2D 编辑态→运行态切换，并以真实 `ViewerEngine`、120 个对象和固定相机完成 WebGL/WebGPU 三维渲染、1440→1024→1440 Resize 及同一引擎内 20 次场景清空/重建。console/pageerror、请求失败、页面级溢出、关键区域不可见、小于 9.5px 的界面文字、小于 24px 的可点击目标、P95/P99 帧时间、Long Task、CLS、对象数量和几何/纹理资源增长均进入失败条件。2026-08-29 当前用例通过；本轮 WebGPU/WebGL P99 为 28.2/21.5ms，Draw Call 为 123/122，WebGPU 强制 GC 后 20 次切换堆增量约 2.3MiB。门禁真实销毁 GPUDevice 后已自动降级 WebGL，并恢复 120/120 个对象，错误计数为零。WebGPU 仍保持实验后端，继续以正式工作负载、同画质截图、短时资源回落、设备丢失和恢复验证决定逐场景签署。原始报告和截图写入忽略版本控制的 `test-output/product-browser/`，正常生产包另由 `pnpm gate:production-artifact` 阻断 QA 入口或夹具泄漏。
- 新增 `pnpm gate:online-flow`：以临时本地数据目录启动生产 API 和正常生产 Web 包，真实执行登录、新建项目、8 步交付导航及刷新恢复、创建设备 GeoJSON 方盒与模型标签、打开简化 AI 助手、创建 2D/3D 应用、通过生产 UI 上传轻量 glTF、等待转换、加载到三维场景、保存、刷新恢复、检查场景任务菜单与对象检查器三视图、执行三维删除/撤销/重做、返回 2D 浏览、发布和公开地址读取，同时通过同源 WebSocket 实时链路。当前 12 个流程节点、10 个真实页面审计、2 组键盘导航审计和 4 项故障检查均通过；保存接口被注入 503 时，本地副本先完成 IndexedDB 事务落盘，刷新后可恢复，恢复时暂停自动保存，人工复核保存后清除副本。12 个设备方盒与 12 个标签保存后仍存在，删除设备会同步删除标签且撤销可一起恢复；AI 面板不包含审批队列，旧版本保存返回 409 且不会覆盖当前稿；除预期 503 资源错误外，意外 console/pageerror/request failure、页面溢出、低于 10px 的业务文字和低于 24px 的常规点击目标均为零，未登录项目访问返回 401，非法模型格式返回 415。测试后删除临时数据，不接触用户数据库。
- 2D 在 1920×1080、1440×900、1280×720、980×720 未发现文档级溢出或关键按钮越界；3D 在前三档通过，980×720 首轮发现顶部工具坞末项越界，改为响应式换行后复测 22 个工具按钮均位于视口内。
- 2D 左侧已形成“页面 / 组件 / 图层”三种任务视图，组件素材库提供视觉缩略图、搜索、行业模板和插入反馈；3D 左侧采用单层场景对象清单，模型、灯光、基础元素、测量和标注并列，批量组织与导入按需打开。脚本工作台可挂载场景、三维对象或二维组件，并已将真实 Monaco 加载纳入在线门禁。
- 3D 视口工具由 22 个同权图标重构为高频动作与三个任务菜单；对象检查器拆为概览、数据、行为三种上下文。菜单边界、Escape 返回、检查器三视图切换已进入真实在线门禁。场景主目录进一步取消“对象/空间”分栏和模型→楼层→空间三级树，模型、灯光、基础元素、测量、标注与空间同层呈现，BIM 构件仅在用户主动展开模型时显示。工具坞、扁平对象清单、对象材质/PBR/特效、环境、灯光、后处理、物理、XR、剖切、视口状态、标注/空间检查器与结果清单均已抽离；当前全仓源码执行单文件不超过 800 行的硬门禁，`App.tsx` 490 行、`ViewerEngine.ts` 41 行、`DashboardWorkspace.tsx` 701 行，门禁不设豁免。
- 空场景 WebGPU/WebGL2 烟测只证明两种后端能初始化和持续渲染，不能用于性能排名；正式方法见 [渲染性能基准](./rendering-performance-benchmark.md)。
- 本机有 RTX 4060 Laptop GPU 和有效 Unity Personal 许可证。2022.3.62f1、6000.0.52f1 已完成真实 WebGL Bridge 构建及平台 ZIP 回灌；2021.3 受旧 Licensing Client batch 兼容问题影响，6000.3 按当前范围不考虑。上述是接入兼容证据，不是公平渲染性能结论。

## P0：发布前必须解决

1. **唯一事实源与原子保存**：三维仍存在旧 `SceneSnapshot` 与 `ApplicationDocument` 双路径，场景和应用分步保存可能出现部分成功。迁移为 ApplicationDocument 原子保存后删除旧编辑路径。
2. **真实浏览器质量门禁**：登录、真实项目创建、2D 编辑/浏览、真实 glTF 上传与转换、3D 加载/保存/刷新恢复、发布和公开读取已落地；管理中心和三维工作区连续 12 次 Tab 均触达 12 个不同控件且焦点可见。保存 503 与本地恢复闭环已经成立；P0 仍需补角色权限矩阵、对象存储/WebSocket/GPU/Worker 故障恢复和真实大型工程资产，不能只依赖轻量确定性夹具。
3. **排版与可读性**：2D 工作台已修复背景图片控件错位，提升核心字号与点击目标，并在 1180px 以下收起属性栏；管理中心和三维工作区已把关键文字与点击目标纳入至少 10px/24px 在线硬门禁，并统一键盘焦点样式。其余二级页面仍存在历史 7–9px 声明，必须逐页迁移后才能宣称全平台完成。
4. **云渲染生产化**：单 Worker 已完成 Chromium 场景、硬件编码探测、WebRTC 媒体、输入 DataChannel、发布作用域、RTP 证据与资源回收闭环，并通过 Worker 单测；P0 聚焦单会话故障回退、断线恢复和资源释放，不建设多节点调度，也不把多会话并发压测作为本轮发布门槛；未获得真实媒体证据时仍不得显示已开启。
5. **WebGPU/WebGL2 功能对等**：WebGPU 仍是实验路径，后处理与 XR 等能力不完全对等。按功能矩阵和 R1–R5 工作负载决定默认后端，能力缺失时可解释地回退 WebGL2。
6. **大型包与启动性能**：已建立首屏/Viewer/后处理/参数化工作台/Worker/WASM 预算并通过，且完成多轮模块拆分；仍需在统一资产与真实浏览器环境补齐显存、场景切换、百万对象与长稳数据，不能仅凭构建体积宣称达到 Unity 级性能。
7. **脚本安全**：普通发布只允许 Worker 沙箱与公开 Scene SDK；主线程 `AsyncFunction` 只能作为管理员签名的可信扩展路径，并显示权限、预算和审计信息。

## P1：形成主流产品竞争力

- 3D：单层场景对象清单、任务化工具坞、上下文检查器和 100 步有界撤销/重做已经落地；下一步补齐对象组件、可保存布局、时间线/Profiler、专业相机与大模型诊断，并继续拆分状态编排；保留 BIM 构件/空间/剖切/视觉联动优势。
- 2D：已具备双轴组合图、堆叠/图例/数值标签、交叉表/分组汇总/总计、条件格式、文本/日期/多选/级联筛选、图表多层钻取与返回、点击写入共享联动参数，以及商业化组件素材入口；下一步集中补拖放/收藏/最近使用、联动诊断、更多可授权素材与高级报表布局，并持续验证用户自定义分辨率与大屏适配。
- 媒体：图片、普通视频和实时监控必须在 2D 设计/预览/发布路径一致可用；统一媒体源可同时被看板播放和视觉任务引用，但视觉插件故障不得中断监控播放。
- Data Hub：区分“已安装可运行”和“目录中可选”连接器；普通问数走受控语义计划，不以任意 SQL 生成为主入口。
- 多场景：通用层级节点只声明父子关系、场景/页面目标、进入相机和 `focus/replace/additive` 策略；恢复每节点相机、筛选、选择与面板状态，加载失败时父场景保持可见。
- M7 桌面：补安全令牌、OAuth 回调、本地恢复点、上传续传、安装/更新和服务器地址迁移的真实端到端证据。
- 模型：RVT 与 Parasolid X_B 使用可选工业转换链路；JT 已增加 9.5/10 小端 TriStrip/TopoMesh v1 内部子集，命中时把最高精度 LOD0 统一为 GLB，并保留 LSG 层级、属性、材质与检查证据；9.5/10.3 各一份真实样本通过，不等于跨版本生产兼容。X_T 已增加 V24.1 单体共轴旋转体内部子集，严格签名之外明确拒绝。源文件仍保留用于审计和复转。
- AI：保留现有 BIM 问答和视觉中心，以统一上下文/证据/路由协议接入 AskData 与预测维护；只读问答直接返回，可逆项目写入只做一次摘要确认，不建设审批中心，专业工作台不被泛聊天替代。
