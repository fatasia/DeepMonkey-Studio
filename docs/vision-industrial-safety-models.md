## 已提供接入模板

| 场景 | 推荐输入 | 标签/输出 | 工程建议 |
| --- | --- | --- | --- |
| 工业表面缺陷 | 单张产品图 | scratch、dent、crack、burr、contamination、missing_part、wrong_part | 必须用目标相机、光源和产品样本训练；通用权重只能演示 |
| 工业异常检测 | 单张产品图 | normal、anomaly | 适合少缺陷样本；Anomalib/PaddleX 导出后接入，热力图需专用输出适配器 |
| PPE | 视频帧 | helmet、no_helmet、vest、no_vest | 结合人员跟踪和区域规则，连续多帧确认 |
| 火焰/烟雾 | 视频帧 | fire、smoke | 视觉告警与烟感、温感做联合确认，降低蒸汽、焊花误报 |
| 吸烟 | 视频帧 | person、cigarette、smoking | 小目标检测后按人员 ID 聚合，多帧确认 |
| 打架、睡岗、跌倒 | 连续视频 | fighting、sleeping、falling | 单帧只做候选筛查；生产方案使用跟踪、姿态或视频时序模型 |
| SOP 操作规范 | 连续视频 | operator、hand、tool、workpiece、fixture、missing_part、wrong_part | 检测结果进入步骤状态机，判断步骤完成、漏步、逆序、超时和越权操作 |

## 推荐技术路线

1. 目标/状态检测：沿用当前 ONNX Runtime + DirectML，负责人物、工具、部件、缺陷和烟火候选框。
2. 连续帧确认：按摄像头和人员 ID 保存短时间窗口，使用连续帧阈值、冷却时间和区域规则抑制误报。
3. 行为识别：打架、跌倒和复杂 SOP 使用姿态关键点或视频分类模型，不把单帧检测结果直接当最终结论。
4. SOP 状态机：将识别标签映射为 `待开始 → 进行中 → 已完成/漏步/逆序/超时`，规则与具体工位绑定，而不是硬编码在模型中。
5. 三维联动：告警携带摄像头、工位、设备和场景对象 ID，复用现有高亮、定位、看板和事件能力。

## 商业化筛选原则

- Apache-2.0/MIT 且模型卡、权重、数据来源明确：可以作为默认下载预设，并在第三方声明中保留来源。
- AGPL/GPL 权重：不默认打包进闭源商业发行；需要履行对应开源义务或取得商业授权。
- 代码许可证宽松但训练数据标注为“仅学术研究”：不作为商业默认权重。
- 来源不明、没有模型卡或没有权重许可证：只提供自有模型接入模板。

例如公开的 PCB 缺陷 ONNX 明确采用 AGPL-3.0，并声明商业使用需要 Ultralytics Enterprise License，因此未纳入默认预设。PaddleDetection/PP-Human 代码为 Apache-2.0，但部分公开行为样例数据注明仅限学术研究，相关能力适合作为工程参考，商业项目应使用自有现场数据重新训练。
