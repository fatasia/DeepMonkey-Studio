## Design Read 与实现

对标西门子工业产品的明确状态、图标 + 文字 + 语义色编码和可操作故障反馈；保留工作台现有层级，用 `styles/base.css` 的表面、边框、文字、accent、warning 令牌，不新增配色体系。

Siemens Element 的状态模式使用清晰图标、简短标题、解释和解决动作。本批采用其信息结构，但没有把真正空数据和读取错误混为同一状态，也不声称复制了 Process Simulate 的具体界面。[Siemens Empty state](https://element.siemens.io/components/status-notifications/empty-state/) 错误显示保留 HTTP 状态用于排查，不把原始服务器异常正文暴露给用户。[Siemens Error Reporting](https://developer.siemens.com/guidelines/api-guidelines/rest/error.html)

- `managerDirectoryRequest.ts`：每个目录一个可取消请求事务，重复调用合并，generation 与当前身份检查拒绝迟到响应。失败只记录稳定状态与合法 HTTP 状态码，不调用空数组提交或无限重试。
- `useManagerDirectoryController.ts`：统一已有三条目录读取，项目列表完成时读取最新 URL 项目；场景按当前身份/项目加载，场景就绪后加载管理页应用目录，避免初始化时同一应用目录重复读取。
- `useAppNavigationController` / `useAppSceneSyncEffects`：只迁移上述三个目录 effect；已有项目定时刷新、非管理页文档加载、场景 apply、数据/拓扑导航均保留。
- `AppViewBindings` → `SceneManager`：最小类型化状态接线；切换管理页 tab 时保留尚未加载成功的 URL 项目 ID。兼容原有不注入目录状态的静态夹具。
- `ManagerDirectoryStatus`：加载使用静态卡片骨架；错误持续显示，唯一主要动作是重试。真正成功的无项目状态引导新建项目，有项目但场景数组为空才引导新建场景。
- 同一项目上次成功读取的数据保留时，失败状态明确标注“可能不是最新版本”；跨项目旧数组清空且新项目未就绪时不能显示为成功空态。失败或加载中的主内容操作被遮换为状态面板，不诱导创建。
- 项目管理菜单点击操作即关闭；`submitProjectDialog` 清除上次失败提示，并使用 pending ref 防止写请求尚未返回时二次提交。失败保留项目名称，只有用户再次明确提交才执行下一次写入。现有 F1 发布 busy 保护保持。
- r6 截图复查确认真正空场景页的工具栏和中央空态存在两个主创建按钮。后续最小修正仅按原始 `scenes.length` 调整工具栏按钮层级：真空时改为次要，中央“新建第一个场景”保留唯一主操作；有场景但筛选无结果时，工具栏仍为主操作。导入及两个创建入口能力不变，不新增样式或颜色。此修正已完成源码和聚焦测试，浏览器证据等待 r7。

每个最终组合核验：

- 0 非预期 pageerror / console 问题。故障注入产生的 503、401、connection-reset 浏览器诊断单独记录在 `expectedFaultConsole`，没有将它们抹掉后宣称绝对零 console。

## 单主动作与品牌对比度终验

r7 `read-recovery-AhNRoy` 两轮4组退出0，工具栏创建降为次要、中央创建保持主动作，二者真实点击均打开新建弹窗且Esc取消无写。但最后悬浮截图暴露暗色下主按钮白字黄底，不能只凭创建动作通过宣称颜色合格。

根因是 `.scene-manager-page .button:hover` 将文字改为当前主题强文字，而主按钮 hover 仅重设背景；原固定深色字也不适合深色品牌。先声明并在 `base.css` 增加 `--on-accent` 及其深/浅中性令牌；`documentBranding` 按品牌相对亮度选择对比更高的黑/白文字，不改变作者品牌色、数据或存储。manager 原规则同时覆盖 idle/hover，实色背景保持品牌色，避免混白后令对比再次下降。沿同族接入通用主按钮、场景卡主按钮、2D 顶栏主按钮；浅强调面板与用户画布不套用实色文字规则。

r8 两个品牌各两轮双主题：`read-recovery-yMhdLv`（默认金色）与 `read-recovery-lOKOKh`（紫色）共8组退出0。真鼠标双击只一次GET、键盘子目录重试、所有失败恢复和写保护仍过；中央主按钮 idle/hover/focus 均默认金色 **9.716:1**、紫色 **6.441:1**。root亲审两个主题的最终空目录与旧r7悬浮失败图，不用测试报告绿代替截图。后续通用弹窗/场景卡/2D同族改动的r9相邻证据由最终交接补记，不混称r8覆盖了更晚源码。

机制依据：[W3C Contrast Minimum](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) 要求普通正文至少4.5:1，包含hover和focus文字；本产品的中性文字选择和保持实色背景是实现取舍，不代表完成全站WCAG审计。新增颜色令牌不另建平行设计体系，仍以base.css为唯一颜色来源。
