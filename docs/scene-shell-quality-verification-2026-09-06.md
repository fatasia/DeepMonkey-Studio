# 3D 作者壳层资产目录与顶部导航验收（2026-09-06）

## 范围与对标

本批仅处理 3D 作者壳层的模型/灯光目录、构件搜索与顶部模式导航主题；不改原场景、模型材质、灯光颜色、存储配置或账号。遵循 design-taste-digitaltwin 的 Design Read → 既有令牌 → 实现 → 截图亲审 → 同族复核流程。

对标 [Unity Hierarchy 官方说明](https://docs.unity3d.com/Manual/Hierarchy.html) 的对象目录、父子层级与场景显隐管理原则。具体的“常用显隐/锁定常驻，次级操作 hover/focus-within 展开”是本产品针对窄侧栏的设计选择，不宣称 Unity 使用完全相同的 CSS 或交互。工业信息密度采用西门子式克制原则，不能把当前范围的改善写成整个平台已超过竞品。

颜色仅用 `base.css` 的 `--text-strong / --text / --surface-1 / --surface-2 / --line-strong / --accent / --accent-soft`；沿用既有 12px 控件字号。视口场景本身的背景、材质和对象颜色保留作者设置。

## 真实问题与修复

1. 基线 `camera-framing-yU31Lj/light-980-explicit-load.png`：模型名称与“主方向光”在浅色表面上近白，搜索框和顶部残留深色，当前三维模式文字对比不足。已亲审截图，未测得基线精确比值，不伪造数值。
2. `scene-workspace.css` 中上述文字、输入和构件层级的固定深色/浅字改为既有主题令牌；`studioWorkspacePolish.css` 的顶部表面、模式按钮、保存按钮与面板入口同族同步。
3. 原次级按钮 `opacity:0` 仍占行宽，使名称仅剩“平…”。改为常用显隐/锁定保持可见，非活动次级动作 idle 不占宽，hover 和 focus-within 同时展开；活动动画/碰撞状态保留可见，触屏保持动作可见。
4. 首轮截图发现展开操作后名称仍被挤短。实际 computed style 证明公共可读性规则把局部 `min-width:100px` 覆盖为 `28px`；980px 展开时按钮只有 56px。初次提高选择器仍不足，原因是公共 `:is()` 中多重 `:not([type])` 把整个规则的特异性抬高。最终在 `accessibilityReadability.css` 原通用 28px 基线规则仅排除 `.asset-main`，由作者壳层明确给出 100px 最小宽、28px 最小高；不重复堆叠类名、不改变其他控件触达基线。门禁新增展开状态宽度断言，不能只检查静止状态。
5. r5 紫色键盘截图发现焦点仍呈金色；单组只读采样 `scene-shell-theme-OlWIrs` 确认 outline 为 `rgb(227,181,79)`、当前 `--accent` 却为 `#6750a4`。根因是 `interactionPolish.css` 既有全局 focus-visible 规则硬编码两处颜色。原地改为 `var(--accent)` 与 `var(--accent-soft)`，不再为每个页面新增覆盖层；静态回归与真实浏览器 outlineColor 对比当前品牌色的断言已补，r6 两轮复查通过。
