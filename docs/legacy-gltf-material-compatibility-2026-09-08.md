# 旧版 glTF 材质兼容核验 · 2026-09-08

状态：已完成。旧 `KHR_materials_pbrSpecularGlossiness` 的原始预览、浏览器优化、项目素材保存、API 派生、3D 场景插入、保存刷新以及历史场景直接加载均已通过隔离实测；原 GLB 字节和 SHA 未改。

## 根因与实现

三个真实 source-b 样本把颜色/贴图放在已废弃但必需的 SG 扩展中，当前 Three `GLTFLoader` 会忽略它而显示白模。解决方案复用 glTF-Transform 4.4.2 官方 `metalRough`，不自行重写着色算法：

- 先读取 JSON/GLB JSON chunk，只在材质实际使用旧扩展时动态转换；仅在 extras 或文本中出现扩展名不会命中。
- `CompatibleGLTFLoader` 统一接到优化器预览、ViewerEngine 与 URDF 嵌套 glTF；现代模型保持原快速路径。
- API 优化与输出审计注册官方扩展集；旧 SG 输出转换为 metal/rough，现代 WebP/IOR/specular 派生保持字节不变。
- 未知 used/required vendor 扩展在重写前明确拒绝，禁止静默丢材质；原上传文件从不覆盖。
- 转换保留 alpha、双面、UV/texture transform、extras 与署名。只有纹理、无 geometry buffer 的合法 glTF 会补输出容器 buffer。

- Web 兼容/优化聚焦测试 10 项通过；API 材质/审计相关 4 文件 20 项通过。

原预览与优化图逐张核对：油泵的红漆、锈迹、文字与背面贴花恢复；输送机的蓝色支架、橡胶带、马达与底脚恢复；钢厂原资产本身是灰色低模和彩色火焰，不把低素材质量误判为兼容失败，也不因此批准该素材。

历史场景门禁最初把 `.model-tree-item` 当 `.asset-row` 双击，产生等待不存在子元素的伪失败；修正为等待已恢复的场景实例并执行真实“适应全部”后，暗/浅两轮保存与刷新通过。该修正只在门禁脚本，不改产品来迁就测试。

## 反馈与性能边界

官方迁移可能为每个材质生成 specular/roughness 纹理。钢厂 17→83 张，油泵 3→4，输送机 5→6；这是兼容成本，不宣称显存优化。油泵 2.53 MB→2.84 MB 时，产品现已显示“体积增加”而不是错误的“减少 0%”。

项目级后验收包括：不同 GPU/驱动、任意第三方混合扩展、超大材质集合、共享纹理去重与长期释放。官方 SG→metal/rough 是标准近似，不保证旧渲染器逐像素一致。
