## GLM 已修复项独立复核（用户最新追加）

GLM 的“已完成”不直接视为当前验收结果。依次复核：分屏拖动闪帧、更多菜单裁切、云能力权限/不可用提示、二级页签高度、2D 缩略图差异、优化器导入/字号/流水线/相机保留；再复核其余已完成能力中的脚本 DevTools 真调试、Agent 恢复、SQL 写回与 Shader 真实画面。优先复现旧问题、验证根因和失败/恢复路径；有效能力不重复建设，证据不足保留为本轮待验收。

## 一、结论先行

当前最需要处理的不是继续横向堆功能，而是修通三个基础闭环：**一键启动后服务真实可用、编辑器关键路径没有阻断、项目与数据边界可信**。在此基础上，再做资源全类型闭环、参数化建模重构、2.5D 拓扑重构、告警语义与钻取向导，最后扩展 SIM 深度。

原“未完成任务”中有两项已经完成，应立即移出开发排期：

- **脚本真调试已完成**：产品提供“DevTools 调试当前脚本”，真实断点、Step into/over/out、调用栈和 Scope 由 Chrome/Edge Worker DevTools 承担；8 组 CDP 门禁命中断点并读取变量。它不是 Monaco 内嵌调试器，但已经满足“真断点/真单步”。证据见 [`EX-006-author-devtools-debug.md`](specs/EX-006-author-devtools-debug.md)。
- **Agent 恢复已完成**：checkpoint 已持久化，等待输入、等待审批和可重试失败均能由新实例恢复；页面也能恢复上次运行。后续仅进入整体验收，不再单列实施任务。

另外，旧计划中的 **SQL 受控写回、Shader Workbench 轻量版、云渲染 Worker 随栈启动能力**均已有实现。云渲染当前 404 是公开地址/路由缺陷；“随栈启动”也仍是可选参数，尚未达到用户要求的默认一键全服务启动。这两点必须与“能力未做”区分。

## 三、代码复核依据

### 3.1 云渲染 404 是地址模型错误

- Worker 明确定义了 [`GET /viewer/:id`](../apps/cloud-render-worker/src/server.ts#L38) 和 WebRTC 信令路由。
- 会话返回地址由 [`publicOrigin`](../apps/cloud-render-worker/src/sessionManager.ts#L131) 拼接。
- 本地启动器却把 [`CLOUD_RENDER_PUBLIC_ORIGIN` 设置为 API origin](../scripts/start-local.mjs#L139)。API 的 [`cloudRenderRoutes.ts`](../apps/api/src/cloudRenderRoutes.ts) 只提供 `/api/cloud-render/*`，没有 `/viewer/:id` 代理，因此会得到用户看到的 Fastify 404。

推荐采用一个稳定公开入口：API 代理 viewer 页面及其信令到 Worker。这样浏览器只依赖一个可配置外部 origin，也避免把内部 Worker 端口暴露成发布合同。若当前部署拓扑不允许代理，再退回为 Worker 独立公开 origin，但不能继续混用两者。

### 3.2 服务离线不是观测卡片误报

[`serviceObservability.ts`](../apps/api/src/serviceObservability.ts) 分别探测 Node-RED `1880` 和 MediaMTX `9997`。仓库已有 `apps/node-red`、`tools/mediamtx/mediamtx.exe` 与配置文件，但 [`start-local.mjs`](../scripts/start-local.mjs) 没有管理这两个进程，云 Worker 也仍是 opt-in。因此“离线”与启动脚本行为一致。

### 3.3 导出文字与诊断浮层是确定性 UI 问题

[`SceneWorkspaceMoreMenu.tsx`](../apps/web/src/components/SceneWorkspaceMoreMenu.tsx) 直接把 `RendererDiagnosticsPanel` 放在“更多”浮层中；[`SceneExportMenu.tsx`](../apps/web/src/components/SceneExportMenu.tsx) 在 `compact` 模式隐藏文字。这里不需要再做需求探索，直接按独立弹窗和完整菜单项修复。

### 3.4 参数化建模与 2.5D 的问题在产品模型，不只在样式

- 用户最新指定参考 **AIGC 平台**。现有安装板、支架、隔套与 OpenCascade 内核保留，产品入口改为描述/样例 → 生成预览 → 参数调整 → 保存资源；参考 Zoo 的对话修改和 Sloyd 的文本、模板、参数调节流程，不再以传统 CAD 特征树作为首屏主线。[Zoo Design Studio](https://zoo.dev/docs/zoo-design-studio/features/ml-ai)、[Sloyd](https://www.sloyd.ai/)。
- 拓扑 2.5D 当前在 [`topologyEditorRuntime.tsx`](../apps/web/src/components/topologyEditorRuntime.tsx) 中主要通过坐标倾斜和高度偏移生成；缺少区域、楼层、分组、路由层与遮挡关系。可参考 AntV G6 的 node/edge/combo 状态模型与 X6 的画布、吸附、缩放能力，但第一阶段复用现有数据模型和 SVG 渲染即可，无需为了“像竞品”立即换图库。[G6 元素模型](https://g6.antv.antgroup.com/en/manual/element/overview)、[X6 画布能力](https://x6.antv.antgroup.com/en/tutorial/basic/graph)。

## 四、下一步执行计划

各批次按依赖排序。一个批次只有满足验收条件才结束，不以“页面能打开”或“接口返回 200”代替业务闭环。

### 批次 A：运行底座和脚本编辑器止血（P0）

#### A1. 修通云渲染公开入口

1. 为 API 增加受控的 viewer HTML 与 offer/answer 代理，或明确配置独立 Worker origin；会话返回地址必须与实际路由一致。
2. 保留会话令牌、过期、版本不可变和发布权限检查，禁止用无鉴权静态路由绕过现有合同。
3. 验收：创建会话后访问返回的 `viewerUrl` 得到真实页面；offer/answer 成功；错误令牌、过期会话、Worker 重启分别得到明确状态；局域网/配置化 HTTPS origin 不被写死。

#### A2. 默认一键启动流程、视频和云渲染

1. `pnpm studio start web` 与客户端主启动路径默认拉起 Node-RED、MediaMTX、cloud-render-worker；提供显式精简启动参数供开发调试。
2. 每个子进程有独立日志、端口占用说明、健康等待和超时错误；只清理本次启动器拥有的进程，不误杀用户自行启动的实例。
3. 验收：冷启动后流程节点目录可读、MediaMTX 控制 API 健康且样例流可播放、云渲染 viewer 可访问；Ctrl+C 后子进程无遗留；已有外部实例时复用或明确拒绝，不静默抢占。

#### A3. 修复脚本新建工作流

1. 先用真实浏览器录制“进入脚本页→新建→编辑→展开左右面板”的路由、网络、组件 mount 和 Monaco marker 变化，确定所谓刷新发生在哪一层。
2. 消除新文件首行的错误 marker；诊断必须绑定当前文档版本和正确行偏移，旧文档结果不得污染新文件。
3. 修复左右面板的命中区、层级、折叠状态和持久化；鼠标与键盘都能操作。
4. 验收：双主题、1440/980 两轮真实浏览器；新建过程中 URL 和应用根节点稳定、草稿不丢、第一行无伪错误、两侧面板均能连续开合；真实语法错误仍能准确标行。

### 批次 B：产品边界和界面骨架（P1）

#### B1. 清理错误能力入口

- 删除 [`externalConverterCatalog.ts`](../apps/api/src/externalConverterCatalog.ts) 中“Parasolid XT 工业转换”和“JT 装配与 PMI 转换”的外部转换器注册、观测卡和对应配置提示。
- 不删除已有 X_T/JT 文件识别、结构检查或安全导入代码；它们与未配置的外部转换服务不是同一能力。
- 验收：界面、API catalog、配置示例均不再出现两个转换器；已有格式探测回归通过。

#### B2. 解除智能运营与 IoT-NB 的项目耦合

1. 从运营 UI、专用 API 路由、合同 source 枚举和 AppData 自动发现中移除 IoT-NB 品牌逻辑。
2. 迁移既有记录：保留数据与来源说明，将 `iot-nb` 映射为通用 `external-import`；不跨目录继续读另一个项目的活动项目或位置数据。
3. 加仓库级隔离门禁，阻止 `bim-studio` 重新直接导入或扫描 IoT-NB 模块/数据目录。
4. 验收：新环境和已有数据环境各一次；运营页面无 IoT-NB 文案/入口/隐式数据，历史导入记录仍可读，迁移可重复执行且不重复生成数据。

#### B3. 统一编辑器标题栏与更多菜单

1. 建立共享标题栏骨架：返回/项目上下文、编辑器模式与标题、保存/运行/发布/更多；2D、3D、脚本只注入各自合法动作。
2. 渲染诊断改为有标题、关闭、焦点管理和 Esc 行为的独立 modal；“导出场景”显示文字并继续进入已有导出选项。
3. 浏览页工具图标随同一图标语义表替换，避免单独造样式。
4. 验收：三编辑器双主题、1440/980/最小支持宽度两轮；标题、返回、状态和主操作位置稳定，弹窗不被画布或更多菜单裁切，焦点可回到触发按钮。

### 批次 C：资源和 AI 可验证闭环（P1）

#### C1. 所有资源可浏览、可上传

建立唯一能力矩阵，覆盖：

| 类型 | 浏览方式 | 上传验收 |
|---|---|---|
| 3D 模型 | 独立模型预览、包围盒/单位/材质信息 | 格式、大小、解析状态、缩略图和失败原因 |
| 图片 | 灯箱、缩放、原始尺寸/色彩信息 | 图片格式与像素限制 |
| 视频 | 原生播放器、时长/编码信息 | 进度、转码/不支持编码说明 |
| HDRI/环境 | 全景或环境球预览、曝光/旋转试用 | HDR/EXR 校验与失败回滚 |
| PBR 材质 | 球体/平面切换、贴图通道检查 | 成组贴图映射、缺失通道提示与命名修正 |

统一上传进度、取消、重试、哈希、来源和许可元数据；“有缩略图”不算完成“可浏览”。验收包含每类成功样例和一个真实坏文件，项目资源页与公共素材库使用同一预览合同。

#### C2. AI 模块一键测试样例

1. 建共享 `AI sample manifest`：能力 ID、输入 fixture、前置条件、是否需要真实模型、预期断言、超时和 reset。
2. 首批覆盖平台助手、AskData、2D 草案、脚本 AI、工业 Agent、参数化 AI、运营/维护 AI；每个模块只登记样例，不复制运行器。
3. 运行结果显示输入、provider/model、工具调用、耗时、断言和错误；没有供应商配置时给出可执行的本地确定性样例，不能伪造“模型成功”。
4. 验收：一键创建隔离测试上下文、运行真实链路、显示通过/失败并可清理；生产项目数据不被修改；相同 seed 的确定性样例结果稳定。

#### C3. 共享告警语义组件

统一 `normal/running/idle/warning/alarm/offline` 状态、阈值/枚举绑定、确认状态和定位动作。视觉同时使用颜色、图标、文字三重编码；3D 复用现有扩散环/辉光，拓扑复用节点/路径状态，2D 复用状态组件。验收以同一条模拟遥测驱动三种视图同步变化，并验证告警确认和定位，不新增一套只会播放的特效。

### 批次 D：重做两个方向错误的工作区（P1）

#### D1. 参数化轻量建模重构

产品定位收敛为**参数化零件生成器**，暂不声称完整 CAD：

1. 采用 AIGC 工作区：左侧输入描述/示例与生成记录，中间大幅 3D 预览，右侧可编辑尺寸；特征与数据绑定按需展开，全部使用 `base.css` 设计令牌。
2. 先复用现有 DSL 和几何内核，以真实样例缺口决定补充特征；不为覆盖 CAD 功能表而堆功能。保留命名参数、单位、表达式和引用，生成结果必须可继续调参。
3. 参数变更触发显式重生成；失败时定位到具体特征并保留最后成功结果；加入 undo/redo 和版本差异。
4. 固定模板改为起始样例。保存同时产生可交换 STEP 和平台可直接浏览的 GLB/预览产物。
5. 验收：至少用安装板和支架两个样例完成“改参数→重生成→失败修正→保存→资源页浏览”；浅/深主题与三宽度两轮视觉闭环。

明确不做：完整草图约束求解、装配约束、认证级 CAD 内核替代、完整 OLP。这些会吞掉当前闭环而没有对应用户价值证据。

#### D2. 拓扑 2.5D 重构（图朴为主要参考）

1. 以区域/园区、楼层、网络域或工艺段生成真实分层平面；高度来自数据语义，不由随机阴影制造。
2. 节点保持面向用户的清晰 billboard，状态色+图标+文字；用 group/combo 表达设备组，支持折叠、聚焦和路径高亮。
3. 路由使用正交/贝塞尔规则，跨层连接有明确上升/下降节点；非关联路径在聚焦时降噪。实时流才播放方向动效，告警才显示呼吸/扩散。
4. 加 fit、cursor zoom、minimap、层级过滤和选中对象上下文；接入批次 C 的共享告警语义。
5. 验收：在真实中型拓扑数据上完成定位告警、追踪上下游、折叠组、切层和返回全局；双主题三宽度两轮截图，不能以空白演示数据验收。

### 批次 E：作者效率与仿真纵深（P2）

#### E1. 一键钻取向导

复用现有场景层级、相机飞行、楼层剖切与返回栈：识别园区→建筑→楼层→设备，列出无法匹配节点供作者修正，生成相机预设/过渡/裁切/面包屑，支持预览、应用为草稿和一次撤销。验收用一个层级完整场景和一个脏命名场景，验证生成、人工修正、设备告警定位与返回路径。

#### E2. SIM 连续 AGV 与多域轨道

1. 在已有 Plant Lite 上增加有向网络、多 AGV 任务队列、路段预约/时间窗、避让、堵塞与死锁检测、充电/装卸资源排队。
2. “多域”先定义为 AGV、输送线、机器人/工位之间的事件交接和共享资源约束，不做连续刚体动力学。
3. 输出可复现 seed、时间线回放、吞吐/在制品/等待/利用率/冲突指标及证据；场景路径和仿真网络使用同一标识映射。
4. 验收：多车正常调度、冲突、死锁与恢复、跨域交接四组场景；重复 seed 结果一致；大规模基准满足已定义帧率和计算时限。
