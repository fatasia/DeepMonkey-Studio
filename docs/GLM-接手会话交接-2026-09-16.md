## 关键陷阱与纪律(踩过的坑,勿重复)

1. **python3 不可用**(exit 49 静默失败)——本仓库用 Node(.mjs);源码编辑优先 Edit 工具,
   批量替换用 node 单行脚本(注意 bash 转义,含 `&` 的 Rust 泛型会被 shell 吃掉,
   此时改用写临时 .mjs 文件执行)。
2. **golden 必须随代码同步再生**:P0-01 链路的三个 golden
   (`dashboard-content-{v1,source-v1,runtime-v1}`)由
   `generateDashboardContentGolden.mjs`/`generateDashboardRuntimeGolden.mjs` 产出。
3. **整形式 fallback 陷阱**:cosmic-text 遇缺失家族静默 fallback,
   `family_exists` 才是家族可用性判据(有测试锁定,勿改回成形判据)。
4. **GPU 单车道**:真实窗口测试前确认无其他 GPU 任务;EXE 被并行构建改变时重记 SHA。
5. **EBUSY 隐患仍在**:生成 PNG 直写 `apps/web/public/docs-assets/generated/` 会打挂
  Web watcher——生成物放 test-output 或 Vite watch 排除,未实施(等用户确认路径)。
6. **暂存纪律**:绝不 `git add .`;共享文件(app.rs/main.rs/lib.rs/mod.rs)的 diff 混多会话
  改动,native 包已整体暂存(依赖闭包不可拆),其余包按域分批。
7. **测试辅助函数借用陷阱**:`bus.submit(command(&mut bus,…))` 双重可变借用编译不过;
   测试里用先构造后提交,或 `command_at(id, revision, key, payload)`(见 behavior_ir_tests)。
8. **HEAD 自洽抽查方法**:`git stash push --include-untracked` → 跑目标包测试 →
   `git stash pop`。用于确认提交后的树不依赖工作树残留(本会话靠它抓到跨包 fixture 缺失);
   pop 前若测试进程异常退出,先 `git stash list` 确认再 pop,勿重复 push。
   注意曾出现 stash pop 后暂存区被清空的现象(原因未明)——pop 后务必
   `git status` 复核暂存区是否符合预期。
