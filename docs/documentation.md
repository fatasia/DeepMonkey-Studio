# 文档写作规范

产品文档帮助用户完成操作，仓库文档帮助贡献者理解和维护项目。修改功能时同步修改对应文章。

## 内容归属

| 内容 | 位置 | 读者 |
| --- | --- | --- |
| 安装、场景、资源、数据、脚本、交付 | `apps/web/src/docs/*.md` | 应用使用者，随构建离线提供 |
| 部署、架构、贡献和维护 | `docs/*.md`、根目录治理文件 | 管理员、开发者和维护者 |
| 设计决策和公开技术说明 | `docs/adr`、本目录下的专题文档 | 相关模块开发者 |
| 当前执行状态 | `docs/active-task-recovery-ledger.md` | 正在接手任务的维护者 |

## 每页回答的问题

1. 这页解决什么问题，开始前需要什么？
2. 从哪个入口开始，按什么顺序操作？
3. 做完后应该看到什么，如何验证？
4. 失败时先检查哪里，完成后读哪一页？

按钮和状态名称与产品保持一致。句子直接说明事实和动作，删除口号、空泛强调、重复提醒和自我解释。功能范围写清条件，不把样例验证推广成所有项目可用。

## 图与文字

配图集中在总体架构、场景交付、引擎和接口等重点文章，每个主题保留一张能说明关系或流程的图。操作指南以步骤和示例为主，不要求每页配图。图中的名称、方向和判断分支必须与正文一致，正文保留可搜索的操作文字，图片提供有意义的替代文本。

配图存入 `apps/web/public/docs-assets`，不得引用开发者个人目录。保留图的来源和制作记录；更新功能时同时检查配图。外部来源需记录再分发权和署名要求。

## Markdown 与链接

应用内解析器支持标题、段落、平铺列表、引用、代码块、链接和图片。不使用表格、嵌套列表、原始 HTML 或依赖外站的嵌入组件。仓库 Markdown 可以使用表格。

站内链接使用 `/docs/文档ID#章节`；修改标题会改变章节锚点，应同步更新引用。代码块写明语言，只保留完成操作所需的命令与参数，不写真实令牌和客户地址。

## 合并前检查

运行 `pnpm gate:repository` 和文档目录测试；在实际 `/docs` 页面检查搜索、章节跳转、代码复制和图片加载。核对双主题、桌面和窄屏的长标题、图片与代码块，确认没有裁切或溢出。

```bash
pnpm --filter @bim-studio/docs-runtime build
pnpm --filter @bim-studio/docs-runtime test
pnpm --filter @bim-studio/web exec vitest run src/docs/docsCatalog.test.ts src/components/DocsCenter.test.tsx
```

仓库治理工作流的 `dependency-licenses` 作业在安装依赖后执行文档构建与目录测试，检查文章注册、站内锚点、图片文件、搜索及正文渲染。新增文章或移动配图时应保持这些检查通过。

应用内文档对应当前构建，默认分支文档可能含未发布变化。提问与复现记录应带应用版本或提交号，发布说明应链接对应版本资料。
