# uni-app X 蒸汽模式：采用建议

结论：可作为未来移动巡检、告警和工单客户端的候选；不迁移当前 React/Three.js 编辑器，不加入本轮开发依赖。

## 已核实

[DCloud 官方说明](https://doc.dcloud.net.cn/uni-app-x/app-vapor.html)将 Vapor 定义为无虚拟 DOM 的 Vue 模式，并在 App 端配套原生渲染系统。官方当前注明：编译到 Web/小程序仍使用 VDOM，不能把 App 原生渲染收益套到本项目 Web 编辑器。兼容性须按[平台与模式表](https://doc.dcloud.net.cn/uni-app-x/tutorial/compatibility.html)逐项核对。

官方性能数字来自特定设备、版本与 UI 创建/长列表实验，不是本站实测，也不是 Three.js/WebGPU 模型渲染基准。App 模式的 CSS 选择器和组件兼容性与 Web 不同，现有 React UI 无法直接开一个配置切换过去。

## 对本项目的价值（判断）

| 用途 | 建议 |
|---|---|
| 移动巡检、告警列表、拍照上传、工单 | 候选；先用一个完整移动工作流验证跨端体验 |
| 当前 2D/3D/脚本 Web 编辑器 | 保持 React/Vite/Three.js，不为原生 UI 跑分重写 |
| URDF 加载、ROS 协议、机器人运动 | 无直接替代作用；既有解析、协议与关节运行态继续复用 |
| 移动 3D 查看 | 另测 WebView/图形能力、桥接和设备资源；不能假定原生 UI 提速等于 3D 提速 |

如启动移动端：复用后端鉴权/工单/素材合同，单独验证冷启动、长列表、上传取消/重试、后台恢复、真机 3D 与耗电。只在同设备、同内容、release 构建对比有收益后采用。本轮仅研究，不新建移动项目。

## 为什么快、我们学什么

官方解释包含两层：编译器生成直接更新视图的代码，减少VNode创建与运行时中间处理；App端另有自研布局/组件、视图拍平和编译为机器码/字节码的原生渲染体系。不能把全部收益归因于“去掉虚拟DOM”，也不能把特定原生UI基准扩成任意应用或WebGPU更快。Web当前仍为VDOM。

对当前React工程的建议（非实测收益）：高频遥测/相机/材质参数直接进入运行时，只有低频状态进入UI；按对象细粒度订阅，避免整棵编辑器重渲染；长目录和日志复用可见行；缓存派生计算；可见性控制后台渲染；解析/压缩走既有Worker。先测React commit、主线程长任务、帧时P95和内存，再改真实热点，不迁移框架或手动绕过React改它管理的DOM。

本轮ROS已使用最新帧单槽+rAF直达Viewer、状态变化才通知UI，这是采用相同“减少无效工作”原则，不是集成Vapor。专项性能仍按用户第6项暂停，不借研究悄悄恢复。
