# 高价值三维格式扩展建议

日期：2026-09-16。状态：**价值分析已完成；点云、3D Tiles、3DM、SolidWorks 四方向已按用户要求写入接入方案，实现待执行**。

四方向的具体模块、合同、系统接线、任务和验收见[四类格式接入方案](./additional-four-formats-integration-plan-2026-09-16.md)。本页保留排序依据；其余候选仍是分析建议。

面向 Deep Monkey Studio 的工业装配、建筑 BIM、实景融合与仿真展示。主线三种格式的接入方案见 [JT、X_T、RVT 内置接入](./jt-xt-rvt-offline-integration-plan-2026-09-16.md)。本建议同样以本地运行、无云转换和无商业 SDK 前置条件为优先。

## 1. 推荐结论

最值得新增的是 **E57/LAS/LAZ 点云、3D Tiles、Rhino 3DM**。工业设备客户占主导时，把 **SolidWorks SLDPRT/SLDASM** 的技术验证提前；需要数值仿真结果展示时，把 **VTK/VTU/VTP** 提前。

同时优先补深已有 **IFC、STEP、glTF/GLB、USD**。成熟支持一种格式的结构、材质、属性、坐标和交付，比再增加十个只能读出网格的扩展名更有价值。

这里的优先级是基于当前产品方向、可复用实现、技术风险和部署负担的工程判断，不是客户需求统计或市场份额调查。

## 2. 先区分现状与新增

本轮读取 `packages/contracts/src/project.ts` 与 `apps/api/src/conversion.ts`：

- 已有格式入口：IFC、STEP/STP、IGES/IGS、glTF/GLB、FBX、OBJ、STL、3MF、DAE、3DS、USD/USDA/USDC/USDZ、URDF，以及 JT/X_T/RVT 等。
- IFC、USD 等已有专用查看链；“已有入口”不等于全部规范能力已经通过。
- 本轮未在通用模型格式合同中发现 E57、LAS、LAZ、COPC、3D Tiles、3DM、SLDPRT/SLDASM、VTU/VTP、PLY/PCD 的正式入口。
- 不能因为 Three.js 或其他依赖带某个 Loader 就标为系统已支持；上传、存储、属性、发布与离线运行还须接通。
- 既有 `modelFormatCatalog.ts` 已声明部分候选，其中 SolidWorks 目前 excluded；本次重新纳入方案，实施时须迁移目录与断言，不能重复注册或直接标记已支持。

## 3. 总体排序

P0 为现有能力深化，P1 为优先新增候选，P2 为需求触发或技术验证候选，P3 为暂缓。排序不会自动改变正在进行的主线任务。

| 优先级 | 格式/能力组 | 核心用户价值 | 无外部服务的路线 | 主要成本 |
| --- | --- | --- | --- | --- |
| P0 | IFC 2x3/4，评估 4.3；IFCZIP | 建筑、结构、机电资产和设施属性 | 复用现有 IFC，按需审计 web-ifc/IfcOpenShell | 实体覆盖、定位、属性、超大模型；IFCZIP 需单独入口 |
| P0 | STEP AP203/AP214/AP242 | 工业供应链、精确几何与装配交换 | 复用 OCCT 导入链，补结构和属性 | 完整 XCAF/PMI 绑定不等于现有 WASM 接口已暴露 |
| P0 | glTF/GLB | Web/Native 最终交付、材质、实例与动画 | 复用现有加载器、优化器和发布编译器 | 扩展矩阵、稳定 ID、压缩、不同引擎一致性 |
| P0/P2 | USD/USDC/USDZ | 大场景、层组合、实例、变体和动画资产互通 | 保留当前查看；复杂组合按需评估本地 OpenUSD | 依赖解析、组合语义、材质翻译及部署体积 |
| P1 | E57 + LAS/LAZ + COPC | 工厂扫描、竣工核查、点云与 BIM 对齐 | libE57Format / PDAL 等本地组件 | 点云运行时、空间索引、坐标、流式加载 |
| P1 | 3D Tiles 1.1，兼容所需旧载荷 | 园区/城市、摄影测量、超大模型流式交付 | 自托管 tileset + 本地开源 Reader | SSE/LOD 调度、坐标、元数据、离线依赖包 |
| P1 | Rhino 3DM | 建筑外形、复杂曲面、设计师模型与设备外观 | rhino3dm/openNURBS，优先保存的显示网格 | 没有显示网格时要补曲面离散，插件对象另验 |
| P1 验证/P2 发布 | SolidWorks SLDPRT/SLDASM | 设备厂家模型、完整工业装配、实例属性 | 独立 Reader 的显示数据/Parasolid 载荷路线 | 配置、保存状态、外部零件、增量数据、版本差异 |
| P2 | VTK/VTU/VTP，按需加时间序列 | 温度、应力、流场等仿真结果叠加 | 本地 VTK 或受限解析适配器 | 标量/向量/单元关联、时序与体数据渲染 |
| P2 | PLY/PCD/XYZ | 扫描与重建工具的简易交换入口 | 受限网格/点云 Reader | 语义弱、单位常缺失、PLY 变体和自定义属性 |
| P2 深化 | URDF、3MF | 机器人设备与增材制造模型 | 复用现有入口 | 关节/惯性/资源关系、3MF 扩展与单位材料 |
| P2/P3 | NX/Creo、CATIA、NWD/NWC、SKP | 特定客户原生工程资料直接导入 | 每类单独验证；本轮没有确认可直接产品化的完整离线 Reader | 高保真、版本、依赖和许可风险 |

## 4. 第一推荐：点云格式组

### 为什么值得

当前三类主线主要解决“设计模型进入系统”。点云补上“真实现场进入系统”，能支撑厂房现状、设备周边净空、改造前后记录和 BIM 对照。它带来的产品增量比单纯再加一种多边形模型更大。

E57 可用本地 C++ `libE57Format` 读写；PDAL 提供 E57、LAS/LAZ 与 COPC 等 Reader。COPC 支持按范围和层级读取，名称里的 Cloud 不代表必须使用云服务。[libE57Format](https://github.com/asmaloney/libE57Format)、[PDAL E57](https://pdal.io/en/latest/stages/readers.e57.html)、[PDAL COPC](https://pdal.io/en/latest/stages/readers.copc.html)

### 最小有价值交付

```text
E57 / LAS / LAZ → 本地预处理 → 空间索引与分块点集
                → 点云显示 + 裁剪 + 强度/RGB/分类切换
                → 与 BIM 共用坐标帧、选择上下文和版本交付
```

首批保留点坐标、RGB、强度、分类、扫描站位及原始单位/坐标信息；字段源中不存在时不补造。点云渲染需要独立点预算、LOD、拾取和流式存储，不能默认把数亿点变成三角面 GLB。

后续价值：对齐、测距、区域差分、可视偏差图。点云与 BIM 自动配准、精度认证、自动重建 BIM 是独立算法任务，不能计入“格式打开”完成条件。

**依赖复用**：坐标帧、任务服务、离线包和质量报告沿用主方案；点云数据合同新增，不能塞进只表示三角网格的字段。

## 5. 第二推荐：3D Tiles

3D Tiles 面向大规模地理三维内容的组织、传输和显示，可承载摄影测量、BIM/CAD、实例和点云。它同时是一种内容组织与流式运行能力，不只是一个文件后缀。[OGC 标准](https://www.ogc.org/standards/3dtiles/)

### 接入目标

- 第一阶段读取本地完整 tileset，保留层级、包围体、变换、几何误差、内容和元数据；明确 1.1 与旧 b3dm/i3dm/pnts 等载荷覆盖差别。
- Three.js 查看链可验证 `3DTilesRendererJS`；此 Renderer 是候选，不意味着 Deep Native 自动具备 3D Tiles 支持。[上游仓库](https://github.com/NASA-AMMOS/3DTilesRendererJS)
- 增加基于屏幕误差的加载调度、显存预算、取消与淘汰；不能完整下载所有 tile 后才开始显示。
- 正式包收集 tileset 的全部依赖并本地化，校验内容哈希；新增外部 URL 模式须显式策略与权限，不作为离线方案默认入口。
- 完整处理地心/地固坐标、局部工程坐标和浮动原点；保留构件 feature ID 到业务实体的映射。

对现有产品的价值是把“单栋/单件模型查看”扩展到“完整园区与实景环境交付”。最大的成本在调度、坐标和身份映射，复用 glTF Loader 只解决其中一段。

## 6. 第三推荐：Rhino 3DM

官方 openNURBS/rhino3dm 提供读取三维几何和渲染资源的本地路径。文件中的 Brep/Extrusion 对象可以带已保存的显示网格，适合先走与 JT 类似的可视数据提取路线。[官方工具](https://www.rhino3d.com/features/developer/rhino3dm/)、[读取显示网格](https://developer.rhino3d.com/guides/opennurbs/reading-render-meshes/)、[读取渲染资源](https://developer.rhino3d.com/en/guides/opennurbs/accessing-rendering-assets/)

交付范围：网格对象、已保存曲面网格、块定义/实例、图层、颜色、材质、单位、名称和对象身份。复杂曲面没有保存网格时，单有 openNURBS 不等于已经有 Rhino 的完整网格生成能力；需要单独验证曲面到 OCCT 的桥或自研离散。

Grasshopper 定义和第三方插件对象不属于普通 3DM 静态导入承诺。未知插件对象即使有代理网格，也要分开记录原始语义缺失。

**推荐原因**：设计端价值明确，官方可读组件可用，能复用现有构件与轻量化链路；通常比从零推进另一种大型私有 CAD 工程格式更容易形成可验证交付。

## 7. 工业客户优先项：SolidWorks 原生格式

SLDPRT/SLDASM 的价值在于直接接受设备厂商工程交付，保留装配实例、零件名称、配置与材料。若客户实际主要交付这两种文件，它可以排到新增候选第一位。

建议技术路线是：容器与保存状态 → 已保存显示数据/内部几何载荷 → 装配依赖及实例 → 规范资产。X_T/JT 的底层经验能复用，但不能推断原生 SolidWorks 文件就是一个 X_T/JT 文件。

当前检索到的 `cadmpeg` 等项目只能列入候选实测清单；后续核对主分支 README 将 SLDPRT 列为 L1 容器级，不能采用搜索结果里更高的旧等级。本轮未完成底层 Reader 的固定提交、依赖许可及真实装配运行验证，不能据项目标题宣称全面支持。[候选项目](https://github.com/cadmpeg/cadmpeg)

技术验证必须包含：装配与零件成套文件、多个配置、压缩/轻化表示、抑制零件、镜像、外部引用、多个保存版本。能读取某一个内部几何分区不等于重建最终保存配置；显示缓存也要检查是否对应当前保存状态。

建议设置独立短期 PoC：至少三个独立来源装配，成功标准是实例数量、变换、配置和几何一致。未过之前不扩大正式格式菜单，也不为原生格式跳过现有 STEP/JT 可靠接入。

## 8. 已有格式里最值得补深的能力

### IFC

加强楼层/构件树、类型与实例属性、属性单位、GlobalId、空间定位、材料层、机电关系、大模型和发布后的查询。IFC 4.3 扩展到道路、铁路等基础设施，只有产品涉及这些领域时优先投入对应实体，不把“Schema 可识别”当作几何已经覆盖。[buildingSMART IFC 4.3](https://standards.buildingsmart.org/IFC/RELEASE/IFC4_3/HTML/content/scope.htm)

IFCZIP 是交付容器便利性，不是新的 BIM 几何内核；支持时单独做有界解压和入口识别。BCF/IDS 属于协作与信息要求，不是三维模型格式；适合作为 IFC 价值扩展，另立需求。

### STEP

现有 STEP 入口重点补真实装配、名称、颜色、层、单位、实例复用、精确几何来源和 AP242 相关属性/PMI；具体能力必须对照当前 OCCT 构建和包装层验证，不能从官方核心库存在某个类型推断现有接口已接通。[OCCT StepAP242 文档](https://dev.opencascade.org/doc/occt-7.7.0/refman/html/package_stepap242.html)

STEP 与 X_T 可以共享后段曲面验证、离散、身份映射和网格优化，适合把新增投入沉淀到共同能力。

### glTF/GLB

优先完善现有三端能力矩阵、压缩扩展、纹理、实例、动画、相机、属性身份和发布差分。它是 JT/X_T/RVT 规范化结果的首期交付载体，基础能力缺失会同时影响多种源格式。

### USD

已有 USD 查看与真正的 Stage 组合能力要分开。References、Payloads、Layers、Variants、实例和时间采样才是复杂场景互通的主要价值，不能把 USDZ 解包与几何加载视为完整 USD 互操作。[OpenUSD 介绍](https://openusd.org/24.08/intro.html)

采用原生 OpenUSD 会增加部署和材质/组合映射成本，先由客户样本证明需求；基础 USD 导入回归留在 P0，完整组合可排 P2。

## 9. 条件性高价值格式

| 方向 | 建议 | 正式立项的触发条件 |
| --- | --- | --- |
| 数值仿真 | VTK/VTU/VTP；按需扩时序/体网格 | 用户需要真实温度/应力/流场数据映射，而不只是播放模型动画 |
| 机器人 | 深化已有 URDF，之后评估 SDF/MJCF | 已有设备关节、碰撞与控制工作流需要模型迁移 |
| 增材制造 | 深化已有 3MF | 用户需要部件、单位、颜色/材料和构建信息，而非只看 STL |
| 原生设计资产 | NX/Creo/CATIA、SKP、NWD/NWC | 有足够高频的真实客户文件和明确可用解析路线 |
| 影视/DCC | Alembic、完整 Blender/FBX 场景 | 已有动画/仿真缓存交付需求；静态模型优先既有 glTF/GLB |
| 实景外观 | 高斯泼溅 PLY/SPZ 等 | 确有照片级浏览需求；需独立渲染、资源和质量合同 |

VTK 的数据模型包含多边形、非结构网格等，必须保留点/单元属性及它们的关联；仅提取外表面会丢掉仿真数据价值。[VTK 格式说明](https://docs.vtk.org/en/latest/vtk_file_formats/index.html)

3MF 有官方规范和开源读写验证库，可作为现有加载路径的验证工具；具体扩展仍应逐项声明。[3MF 规范](https://3mf.io/spec/)、[官方 FAQ](https://3mf.io/resources/faq/)

高斯泼溅的视觉效果不能代替 CAD 几何、真实表面测量或构件语义；相同 `.ply` 后缀可能代表网格、普通点云或 splat 数据，必须看字段和内容。它的投资价值取决于展示场景，本项目默认排在点云与 3D Tiles 后面。

## 10. 组合建议与立项规则

如果新增范围只能选三个方向，建议：

1. **E57/LAS/LAZ/COPC**：把现场扫描带进来。
2. **3D Tiles**：把园区与大规模数据稳定交付出去。
3. **3DM**：连接建筑设计与复杂曲面资产。

上述是资源只够三个方向时的排序建议。用户随后明确要求四个方向均写入方案，因此点云、Tiles、3DM、SolidWorks 均已进入设计范围；其实现先后仍可按客户需求调整。VTK 等其他格式没有自动进入实施范围。

任何候选进入实施前，必须交出一页证据：实际需求与样本来源、固定源码/许可、无源软件断网运行、几何/结构/属性范围、失败原因、安装体积与峰值内存、全链路接入成本。随后才追加主任务表。

## 11. 与主方案复用的边界

所有新增格式复用任务、源文件与依赖存储、权限、哈希、坐标帧、质量报告、版本与离线发布。不同数据保留适合自己的运行时：网格走 GLB/资产包，点云走点集分块，3D Tiles 保留空间层级，仿真数据保留场和时序；不强行全部转成单一 GLB。

本轮核对了项目格式合同与上述官方/上游资料，未安装新的 Reader、未改动产品能力菜单，也未验证候选模型转换。推荐优先级与上游能力声明均不能用作生产支持证明。
