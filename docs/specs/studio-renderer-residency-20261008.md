# 编辑器引擎驻留与切换

切换目标为 3 秒，验收上限为 5 秒。场景资源准备、作者状态同步、画面交接分别计时，首次未准备好的切换也计入验收。

## 现状核查

已检查作者 SceneSnapshot 契约、RenderPacket 与 RuntimePackage 契约、WebGPU/WASM 桥、编译 Worker、Native 场景资源事务、停放与设备丢失测试、现有性能证据。复用现有编译缓存、资源缓存、候选发布与相机同步，不再建立第二套场景状态。

已有：作者指纹排除相机与选择；同一场景编译合并；WebGPU 驻留资源与按需管线；WASM 预解析；两个后台候选；首帧验证后交接。

真实缺口：WebGPU 停放时把普通场景修改当作设备失效；WASM 收到完整场景包时销毁 Renderer；动画资产的纹理解码和姿态计算耦合；完整包数值 JSON 和 RGBA 展开使 6 MB 模型变成约 160 MB 传输；首次场景编译、材质管线编译仍在等待路径。

## 生命周期

| 对象 | 身份 | 更新与释放 |
|---|---|---|
| 作者场景 | 场景 ID + 内容版本 | 唯一编辑状态，切换不重建 |
| 资产内容 | 源内容哈希 + 解码质量配置 | 只在资产改变时重新规范化、解码；受字节预算约束 |
| GPU 设备与管线 | 后端 + 设备代次 + 能力配置 | 普通场景修改不销毁；设备丢失或能力改变时重建 |
| 后端场景 | 资源引用 + 材质 + 实例状态 | 对现有资源进行事务更新，验证后发布 |
| 呈现 | 后端 + 相机 + 编辑覆盖层 | 交接前验证当前版本首帧，成功后记录用户偏好 |

资源是否驻留与场景版本是否最新是两个独立条件。旧版本的隐藏后端可继续保留设备、管线、几何和贴图，但必须更新至当前版本才能显示。仅修改变换、材质或选择不能触发整个设备重建。

完整快照和增量包遵守不同版本规则。编辑器完整包可重新从 revision 1 开始，接收端必须验证几何、贴图内容是否相同，不能仅凭相同 revision 复用。增量包仍严格验证基线、版本递增与资源哈希。

## 当前实现

- WebGPU：普通编辑保留隐藏后端。资源与材质不变的模型变换复用既有实例/姿态更新，只验证新帧；资源变化仍走事务更新。新高级材质、覆盖采样能力、环境或质量配置改变时受控重建。
- WASM：相同渲染配置、相同几何和贴图的完整快照进入已有异步 GPU 更新事务；取消、失败或过期结果不能发布错误场景。
- 资产解码：同内容与质量配置共享规范化字节和纹理像素，动画活体几何与绑定姿态几何分别计算。
- 内部传输：带分段哈希和解码预算的无损二进制包，公共 JSON 格式继续兼容。SMT 实测从 159,919,640 字节降至 4,937,407 字节，六张贴图像素不变。
- 变换编译：固定原始场景基线与坐标原点计算矩阵，不累积增量误差；WebGPU 复用资产资源，WASM 复用压缩数据段，仅修改实例元数据与哈希。动态运行时、烘焙数据等不满足条件时回完整编译。
- 请求所有权：前台交接请求与后台准备独立取消；取消等待者不会终止另一引擎的有效准备，也不会让旧请求晚到发布。
- 首次管线：WebGPU 用作者材质元信息提前启动管线，与资产准备重叠；实际包仍校验全部所需变体。Native/WASM 只为实际批次准备颜色管线，场景更新在事务提交前准备新增变体。
- 编译校验：纯校验复用上传边界的校验规则，不复制随后丢弃的像素和几何。浏览器主线程的大包仍交给 Worker；WASM 编译线程直接校验，避免再启动一个线程往返复制整份场景。上传阶段仍取得独立资源副本。

SMT 的六张 2048² RGBA 贴图共 100,663,296 B（96 MiB）。纯贴图校验实测复制像素 0 B，原准备函数复制 100,663,296 B；这说明移除了每次纯校验的整份副本，不代表显存或 WASM 线性内存已减少同样数值。6 MB 是压缩模型文件大小，不能直接用来估算解码后的贴图驻留量。

网格由亚像素线三角形改成覆盖纹理与完整 mip 链；WebGPU 作者网格只绘制一份。Native 摄影棚纹理背景按 sRGB 解码进入统一曝光/ACES，避免重复预逆色调映射。模型 PNG/JPEG 贴图的缩小采样链仍需补齐；不能把网格修复等同所有锯齿已解决。

## 尚未达标的路径

首次编译仍依赖一次性的 WASM 编译 Worker；编辑后也可能重新遍历和打包未变化资源。WebGPU 首次高级材质管线编译与作者模型准备仍占数秒。下一步应把不可变资产编译产物与实例元数据拆开，让资源准备在资产导入时完成并按内容寻址保存，场景更新只传变更实例与材质。

大场景超出驻留预算时，需要逐资源驱逐与按可见集加载，同时保留设备和管线。当前 WebGPU 384 MiB 停放预算仍可能导致整后端释放，这条路径不能算作任意大场景快速切换已完成。

## 验收

分别测试首次未准备、已准备、编辑后、资源更换、预算驱逐后、设备恢复后；覆盖静态、蒙皮、重复实例、多贴图和大场景。每项记录点击至当前版本首帧、场景准备、编译、上传、内存峰值，不能把准备时间排除后宣称首次达标。

每个后端连续拖动至少 30 秒，记录主线程长任务和呈现帧间隔；相机姿态、滚轮方向、材质、环境和网格同时验收。30 次往返切换检查资源是否持续增长。

正式构建 SMT 30 次已准备往返为 43–547 ms；修改位置后 WebGPU 2.137 s、WASM 91 ms。两后端各连续右键拖动 30 秒，无主线程 longtask；rAF 的 P95 为 7.1 ms（这不是 GPU 帧率）。30 次切换前后资源统计相同：WebGPU 200,242,916 B，WASM 230,424,576 B，解码缓存 129,614,116 B。编辑更新后 WASM 线性内存高水位仍会到 331,481,088 B，需要继续优化所有权。

本轮正式构建复测（smt-validation-final-endurance.json）：30 次已准备切换 45–671 ms，两个后端各连续右键拖动 30 秒，无主线程 longtask，切换前后资源统计相同。WebGPU 200,168,180 B、WASM 230,621,184 B、解码缓存 129,614,116 B。GPU 提交间隔受输入采样和按需绘制影响，不能直接当作帧率。

首次准备仍未通过 5 秒上限：提前准备管线及减少校验副本后，正式构建各轮仍约 6–10 秒，最新完整耐久复测两端约 9.77 秒，波动明显。主要等待资产编译和蒙皮高级材质管线，不能据最快一轮宣称达标。证据包括 smt-early-production.json、smt-validation-production.json 和 smt-validation-final-endurance.json；部分单轮与预压缩构建重叠，仅供阶段定位，最后耐久测试在构建退出后运行。

本轮验证：116 项材质/几何/变形/二进制包/异步校验测试、52 项 Web 场景编译/WASM 桥测试、63 项 WebGPU 候选/提前准备测试通过，Web 类型检查与生产构建通过。Native 颜色管线按需编译的真实 GPU 测试通过，所有 18 个颜色变体编译校验通过。此前的 170 项驻留/编译/网格回归及 Native 背景参考测试证据保留。
