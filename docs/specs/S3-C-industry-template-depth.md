# S3-C 300+ 行业页面与十套深度包

## 0. 元信息

- 状态：规格已完成；实现为本轮待办。
- 批次：S3；依赖 S3-B、现有模板工厂与语义模型。优先建立一套端到端样板，再扩领域。

## 1. 目标与用户故事

用户选择行业业务包，预览实际页面和数据，导入项目后替换数据源，编辑并发布。目标为 ≥300 可编辑业务页面、≥10 行业深度包（每包至少 5–10 个协同页面与匹配 3D 资产）；页面与深度包是两种统计口径，不相互冒充。

## 2. 现状与复用

- `DashboardTemplateCatalog.ts` 已按 12 个 domain ×10 个 view 生成 120 项；`DashboardTemplateCatalog.test.ts` 明确验证 120、9 个可编辑节点与页内边界。
- 复用 `dashboardTemplateDomainPacks.ts`、`dashboardTemplateViews.ts`、`dashboardTemplateLayoutBuilder.ts`，保留原 ID（executive 使用 domainId，其余 domain-view）。
- 现有 120 项并不等于 120 套端到端行业解决方案；禁止简单乘以更多视角宣称交付完成。
- 3D 外部下载已按用户要求停在 164 GLB；本规格不恢复下载，不将“文件存在”计为通过质量审计。

## 3. 合同设计

新增独立 `industryTemplatePackCatalog.ts` 与校验器：

```ts
interface IndustryTemplatePack {
  id: string;
  revision: number;
  title: { zh: string; en: string };
  pageTemplateIds: string[];
  datasetFixtureIds: string[];
  semanticModelFixtureId?: string;
  assetCatalogIds: string[];
  entryPageTemplateId: string;
  workflows: Array<{ from: string; action: string; to: string; requiredFieldIds: string[] }>;
  guideId: string;
}
```

目录引用不直接写入客户数据库。导入经现有应用工作区保存链路生成新 ID，并重绑定页间跳转/组件引用；保留来源包与 revision 作为追溯信息。所有数据明确标“示例”，不得伪装真实设备连接。

## 4. 实现要点

1. 首包选择已有真实示例数据最充分的制造设备运行：总览→设备→告警→明细→维护；不引入新模型/算法。
2. 按电力、水务、化工、汽车、物流等领域依次出业务故事、指标口径、页面流和资产清单，再实现页面。
3. 300 页面以不同业务问题/指标/交互/布局质量共同验收；相同页面改名字颜色不计新增。
4. 模板预览必须来自实际节点配置；导入可取消，失败不留下半个应用，重复导入创建独立副本不覆盖原件。
5. 文档为每包给出“使用哪些数据→如何绑定→如何验证发布”的短操作指南，可从模板详情进入；不新增说明墙。

## 5. 测试计划

- 校验：引用完整、入口存在、跳转可达、字段类型匹配、资源不存在明确阻断、旧模板 ID 兼容。
- 每包至少一个完整浏览器流：导入→改数→切页联动→保存刷新→发布→公开读取；QA 项目隔离。
- 每页截图与节点合法性检查；数据空/错/极值、中文长标题、980 宽窗、双主题。
- 导入失败回滚与重复导入 ID 不冲突测试；缩略图与真页一致；记录页面数而非仅测试脚本数。
- 命令：Web 模板/应用保存聚焦测试、contracts/API 相关测试、typecheck、Web 全量、source-size、真实浏览器门禁。

## 6. 验收标准

- [ ] ≥300 有业务区分的页面、≥10 个完整深度包分别达标。
- [ ] 所有页面可编辑；全部包有绑定/运行/发布证据与来源说明。
- [ ] 不破坏已有 120 模板、用户资产及引用；未审核外部资产不悄悄进入交付包。
- [ ] 文档可直接指导新用户完成首个业务包，不需要解释内部 ID。

## 7. 风险与回滚

主要风险为“数量替代深度”、示例指标口径冲突和多页重绑定遗漏。按包提交，先隐藏有问题的新包；保持已有项目兼容，不执行批量数据库迁移或删除。
