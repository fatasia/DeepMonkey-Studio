# 全量差距分析:完成当前任务后 vs Unity / UE5 / Three.js / Babylon(2026-09-19 深夜)

前提:本分析以"今晚已落地 30 commit + 在途车道(R6-2 细分埋点、E02-IES 着色注入)完成"为基线,以五轴定档(超越 Babylon/Three、对标 Unity)为口径。**每条缺口给:现状证据 → 差距 → 建议 → 归属任务**。分级:🔴 差距大(数量级)、🟡 有差距(可追平)、🟢 已领先或持平。

## 一、性能劣势(按今晚实测)

### 🔴 P-1 多线程 CPU 提交:Unity/UE 有 Job System,我们单线程
- **证据**:今晚基线 cpu-submit 3.35ms / 帧间隔 5.37ms = **62%**,单线程编码;Unity DOTS Job System + Burst、UE TaskGraph 十几年优化,万级 draw 的 CPU 帧时间可压到我们 1/3 以下。
- **建议**:C2 并行 encoder 农场(widget 级并行 encode、主线程按序 submit)是第一刀(3–5 天);配合 R6-1 热点档(wgpu 队列串行化补丁)。**接受现实**:wgpu 内部有序化(#5525)决定了多线程收益有上限,必要时 wgpu-hal 直下。
- **归属**:R6-2-C2、R6-1 热点档。

### 🔴 P-2 无遮挡剔除的生产化 GPU 管线(UE Nanite/两阶段剔除)
- **证据**:R4 已把 HiZ 全链 DCIR 化(26–32% 快于手写)+ 三端逐位认证,但**仅深度缩减内核**;完整两阶段(HiZ 遮挡判定→可见性缓冲→间接绘制)无 compute 消费点,DCIR v0 无 buffer I/O。UE Nanite 是全 GPU 驱动管线;我们 instancing 有但 draw 全部 CPU 提交。
- **建议**:DCIR v1(buffer read/write、storage 纹理)是前置,然后 HiZ 遮挡判定 kernel → 间接 draw。这是把 cpu-submit 3.35ms 里"5000 实例逐实例编码"打掉的根路径。
- **归属**:R2 v1 → R4(已批 G2)。

### 🔴 P-3 几何处理系统:mesh shader / Nanite 级虚拟几何 / LOD 链自动化
- **证据**:meshlet 有研究路径(D06),无自动 LOD 链、无 impostor、无编译期 HLOD(已批 G3 未实施)。UE Nanite 级虚拟几何 = 数年工程,我们诚实不追全量。
- **建议**:编译期路线(我们独有的形态):编译器产 HLOD/impostor/meshlet 预分区(G3),运行时零成本。放弃与 Nanite 比运行时虚拟几何,比"编译到骨头"。
- **归属**:G3 + R8(首帧可交互)。

### 🟡 P-4 着色编译管线:PSO 缓存/管线预热
- **证据**:有 pipelineWarmup(QA 夹具里有统计);Unity 有 PSO 缓存跨启动、UE 有 PSO 预编译+ Driver Cache。
- **建议**:磁盘 PSO 缓存(wgpu 有 shim API)进编译包;首帧卡顿直接进 R8 冷启动账本。
- **归属**:R8 + B05。

### 🟡 P-5 内存/流送:无虚拟内存/streaming 预算系统
- **证据**:有驻留控制器、上传预算(B05);UE 有完整的流送代理/IO 分块异步、Unity 有 Addressables。我们的流送是"包整载",大场景首帧吃亏。
- **建议**:编译期按分区打包 + 运行时分区流送(与 D05 语义分区合流);优先级由相机轨迹前瞻(C4 已在 R6-2 清单)驱动。
- **归属**:D05 + R6-2-C4。

### 🟢 已领先(保持)
- **确定性**:三端逐字节(R2 认证 12 案例/46 级 + R3 状态合同 + ② 动态重放)——四平台无一具备。
- **编译链**:source map/增量构建/原子回滚/版本冻结——四平台无产品化对位。
- **GPU 时间戳微基准方法论**:三端同口径校准。

## 二、效果劣势

### 🔴 E-1 实时 GI 深度:Unity 7 Surface Cache / UE Lumen
- **证据**:探针 clipmap + r14 跨端阈值通过(⑤),但**动态物体间接光、室内外漏光、表面缓存级更新**未达;Unity 7/UE Lumen 的 GI 是"动态全场景"级,我们是"探针卡距"级。
- **建议**:R1 分两步:先补动态更新+复杂几何(超越线全绿——Babylon/Three 无 GI),再表面缓存对位 Unity(对标线)。明确接受"Lumen 级动态 GI 在浏览器端无人做到"的事实,以三端同语义为差异化。
- **归属**:R1 + E03(已排,GI 车道)。

### 🔴 E-2 体积与大气
- **证据**:exp2 高度雾只有;UE 体积雾(VFT)、Nanite 雪地/植被交互是标配级;Babylon 9 volumetric 增强。
- **建议**:G7 光线步进参与介质(已批),与 E05 灯光联动;范围先做"单体积雾 + God rays"不追全天气系统。
- **归属**:G7(已批未排期——**建议提为 Wave 2 首位**,工业氛围感差距最直观)。

### 🔴 E-3 材质模型深度
- **证据**:PBR + 清漆/玻璃语义(C02)在验收中;UE Substrate/Unity StackLit 的分层材质、全新光照模型覆盖(hair/foliage/water)我们无计划——**接受不追**,工业场景优先级低。
- **建议**:维持"高频字段优先"(C04/C05),把分层材质列为远期观察;水面/车漆两个工业高频项单独评估。
- **归属**:C04/C05 已有卡。

### 🟡 E-4 后处理栈完整度
- **证据**:Bloom/ToneMapping/GTAO/雾有;UE 的 SSR 高质量回退链、运动模糊、DoF、自动曝光我们缺项或质量档浅。
- **建议**:SSR(含离屏回退)是 E04 在办;运动模糊/DoF 按工业场景真实需求排,不追游戏全栈。
- **归属**:E04。

### 🟡 E-5 阴影深水区(在途)
- **证据**:CSM/局部阴影/接触阴影在 E05 验收分母;PCSS 可变软阴影、RT 阴影无。
- **建议**:E05 逐格补(PCSS 进分母);RT 阴影走 R6-1 compute 模拟档,不追硬件 ray query 分母。
- **归属**:E05 + R6-1。

### 🟢 已领先
- IES 光域网:量化表+双端 golden 已落地,着色注入在途——Babylon/Three 无内置体系。
- 双端确定性视觉:同输入同像素是工业验收的硬价值。

## 三、能力/生态劣势(不做渲染,但影响"全面超越"判断)

### 🔴 C-1 工具链成熟度:编辑器/调试器/性能分析器
- **证据**:有 RendererDiagnosticsPanel/Profiler(H02/H03)、材质调试(H04);Unity Editor 的 Scene/Inspector/Profiler 帧调试器、UE RenderDoc 集成/Insights 是十年级工具。**这是我们与"平台"定位差距最大的一块。**
- **建议**:不追通用编辑器,追"编译链诊断"差异化:source map 定位 + 帧调试(H02) + 预算账本(H03)三件套做成产品级。RenderDoc 级 GPU 调试借力开源(Mezzanine/playback)不自研。
- **归属**:H02/H03/H04 已有卡,提产品级优先级。

### 🔴 C-2 生态:资产商店/插件/社区/学习资源
- **诚实结论**:无法在短期内超越,也不该追。以"工业垂直资产"(设备库/仪表库/工艺图标,已批 V11 路线)+ 可离线交付为壁垒。
- **建议**:V11 场景搭建素材库按客户需求扩充;不做通用生态。

### 🟡 C-3 物理:UE Chaos/Unity PhysX 内置
- **证据**:F04 PhysicsWorld 宿主接线在办;工业场景需要的是受限刚体/运动学(Kinematic)与约束(F05),不是全功能物理。
- **建议**:F04/F05 完成即对标"工业够用";软体/流体列为远期观察。
- **归属**:F04/F05 已有卡。

### 🟡 C-4 动画系统:重定向/状态机/混合树
- **证据**:F01 正式动画包在办; humanoid 重定向/混合树无计划——工业数字孪生以机械动画为主,角色动画优先级低,**接受**。
- **归属**:F01。

### 🟡 C-5 平台广度:主机/移动原生
- **证据**:我们 Web+Windows Native;Unity/UE 全平台。工业交付以 Web+Windows 为主(内网离线是卖点),Linux/Android 按订单需求评估。
- **建议**:不主动扩;wgpu 后端本身支持,扩展成本主要是测试矩阵。
