# 点云、3D Tiles、3DM、SolidWorks 内置接入方案

日期：2026-09-16。状态：**四个方向均已纳入方案，产品实现待执行**。

本文件落实用户追加的四类格式：实景点云（E57/LAS/LAZ/COPC）、3D Tiles、Rhino 3DM、SolidWorks SLDPRT/SLDASM。与 [JT、X_T、RVT 总方案](./jt-xt-rvt-offline-integration-plan-2026-09-16.md)共同构成七个方向的接入路线；[价值排序](./high-value-3d-formats-2026-09-16.md)解释投入顺序。

## 1. 统一决策

| 方向 | 核心路线 | 正式结果 | 第一阶段边界 |
| --- | --- | --- | --- |
| 实景点云 | 本地 Reader → 点属性/坐标规范化 → 空间索引 | 分块点集 + 扫描/属性/精度信息 | 保真读取、流式显示、裁剪测量与 BIM 对齐 |
| 3D Tiles | 本地依赖闭包 → 标准校验 → 运行时空间调度 | tileset + 本地内容 + 元数据 | 读入与交付现有瓦片集，不同时建设万能制瓦片平台 |
| Rhino 3DM | 官方开源 Reader → 已保存网格或受支持曲面离散 | GLB + 图层/块实例/材质/属性 | 静态模型；保留源对象身份与外观 |
| SolidWorks | 容器/配置 → 有效几何载荷 → 装配关系 | GLB + 装配/配置/属性/来源 | 保存状态的高保真查看，不重建配合求解与可编辑历史 |

依赖条件与主方案一致：不要求用户安装源软件，不依赖商业 SDK、云服务或联网授权；允许经核查的开源库随程序安装。开发期成对参考模型可由文件提供方生成，转换运行期不需要这些参考文件。

不把所有结果强行变成 GLB：点云和 Tiles 需要新的数据与运行合同；3DM、SolidWorks 优先复用网格资产链。四方向的 native 发布能力分别验证，Web 能显示不能推断 Native 已支持。

四方向不把 PDAL、libE57Format、openNURBS 或研究用 Reader 的开发工具链暴露给终端用户；发布包提供预编译 Worker/模块。体量按主方案的 `studio-core`、`pointcloud-pack`、`solidworks-pack` 等离线包拆分，安装时可选。任何依赖在干净断网机无法启动，或需要用户手动安装运行库，均不满足本方案的交付门槛。

## 3. 点云：E57 / LAS / LAZ / COPC

### 3.1 技术选择

候选为 libE57Format + PDAL 的最小受控构建。先验证 PDAL 发行包实际带 E57、LAS/LAZ、COPC Reader；缺少 E57 插件时，以 libE57Format 补齐或构建对应插件，不能仅检测到 `pdal.exe` 就认为全部格式可用。[libE57Format](https://github.com/asmaloney/libE57Format)、[PDAL E57](https://pdal.io/en/latest/stages/readers.e57.html)

LAS/LAZ 是输入交换格式；COPC 在 LAZ 基础上组织空间层级，可按块访问并保留本地部署。现有 COPC 输入优先索引和验证后读取，避免无意义地全量解压再压缩。[COPC 规范](https://copc.io/)、[PDAL COPC Reader](https://pdal.io/en/latest/stages/readers.copc.html)

库及其压缩、XML、投影依赖全部固定版本；不捆绑完整 GIS 桌面应用。投影数据文件也必须包含在离线包中，不自动联网补充。

### 3.2 数据和处理链

```text
上传点云 → 流式检查头部/扫描/坐标 → 原始点解码
        → 有损/无损规则确认 → 分块与空间层级
        → 独立验证点数/属性/坐标 → 发布点云资产
```

拟新增 `PointCloudManifest v1`，至少包含：源哈希、扫描 ID/姿态、点数、属性定义、有效/无效点计数、CRS/单位、源量化尺度与偏移、局部原点、bounds、空间节点、chunk 哈希与字节数、LOD/采样规则、精度报告。

各格式必须保留：

- E57：多扫描、各扫描位姿、有效点标记、RGB/强度与可用图像关联；站点位姿只应用一次。
- LAS/LAZ：坐标 scale/offset、点记录格式、分类、回波、强度、时间及可用附加维度；未实现波形等数据时单独报告。
- COPC：层级页、块范围、点数、节点 bounds 与访问规则；校验偏移溢出、越界和重复节点。
- 所有格式：源缺单位或 CRS 时保留 unknown；允许在导入设置指定已知坐标约定，并记录为用户输入，不推测 EPSG。

转换始终保留原始源文件。无损主点集与显示抽稀派生物分开；非法点、重复点、噪声删除均须有策略和计数，默认不静默清洗。点集完整率基于源有效点数，LOD 采样率不能当作数据丢失率或完整率。

### 3.3 显示与交互

新增点云显示适配器：按视锥/屏幕误差/点预算调度，支持颜色、强度、高程、分类切换；节点卸载释放 CPU/GPU 缓冲。扫描树与模型对象树共用外壳，点云分区不是 BIM 构件，不自动赋予墙/设备语义。

选择结果记录资产版本、扫描/块 ID、源点标识或可信来源映射；LOD 切换不能让标注漂移。测量区分实际采样点和插值/拟合点，展示源精度与采样影响。与 BIM 融合通过共享坐标帧及可持久化配准矩阵，自动配准算法另列任务。

原生侧需要独立 point primitive、预算调度和拾取管线；这属于新增运行时能力。只完成 Web 时能力表标记 Web verified / Native unsupported，发布器阻止无声丢点云。

### 3.4 任务与验收

| ID | 任务 | 验收 |
| --- | --- | --- |
| PC-01 | E57/LAS/LAZ/COPC 固定工具链、属性与坐标探测 | 四类各真实样本；工具缺插件、未知记录格式可解释失败 |
| PC-02 | 点云合同、流式转换、分块和主/派生点集 | 有效点与属性对应，坐标量化误差可计算，无全文件 JSON 展开 |
| PC-03 | Web 显示、预算、拾取、裁剪与保存 | RGB/强度/分类切换真实生效；相机来回移动无持续内存增长 |
| PC-04 | BIM 坐标融合、离线包和 Native 路径 | 控制点对齐、版本标注恢复、断网回放、目标不支持时明确阻断 |

建议首批至少 12 份真实样本，包含多站 E57、不同 LAS 点格式、LAZ 与 COPC、地理大坐标、缺 CRS 和损坏块；规模覆盖百万、千万、亿点，但数据量不是唯一通过条件。无损主集点数与保留属性应精确一致；坐标误差不超过源量化和显式转换的累计预算。实际扫描精度不能由程序虚构。

输入上限不能复用主方案 2 GiB 一刀切：点云建立独立 profile，首期验证到 20 GiB 的流式输入，内存仍有固定上限；该数值为实验规模目标，须根据固定机器实测冻结。

## 4. 3D Tiles

### 4.1 路线与范围

按 OGC 3D Tiles 1.1 建立能力表，优先静态 mesh/glTF 内容；针对客户输入逐项加入旧 b3dm/i3dm/pnts、隐式分块、subtree、多个 contents 和结构化元数据。[OGC 3D Tiles](https://www.ogc.org/standards/3dtiles/)

Web 首选验证 `3DTilesRendererJS` 与当前 Three.js 版本，按实际构建审计扩展支持。采用本地 tileset 入口，不启用其第三方在线地图/云资产插件。[官方仓库](https://github.com/NASA-AMMOS/3DTilesRendererJS)

新增资源类型 `tileset`，入口可以是目录中的 tileset JSON，但不能开放任意 JSON 为模型；必须检查内容结构与 MIME/签名，支持文件名不同但内容符合规范的根清单。根清单不等于所有依赖已获得。

### 4.2 导入与数据合同

拟新增 `TilesetAssetManifest v1`，包含源根路径、版本/扩展需求、全部依赖哈希、tile/subtree 图、CRS 与规范坐标变换、feature 身份规则、内容类型、可用层级、总量/驻留统计和质量报告。

处理顺序：

1. 从用户提供的 SourceBundle 建依赖闭包；递归检查外部 tileset、子树及纹理，拒绝目录越界和循环引用。
2. 依据标准解释 transform 与包围体：box/sphere、region 的地理定义不能套用同一变换公式；glTF Y-up 与地理坐标转换只做一次。
3. 校验 refine 的 ADD/REPLACE 行为、geometricError、层级可用性与内容一致性，不能让父子同时重复显示或切换时大面积空洞。
4. 元数据按 tileset/tile/feature 层级保存；旧 batch ID 和新 feature ID 分别解释，再映射统一业务身份。
5. 输出不可变本地化包，保留合法相对引用；发布前证明当前范围的全部依赖可离线访问。

源含远程 URI 时，默认报告缺依赖并要求提交本地副本；后续网络模式另行授权和实现下载策略，不能通过解析器任意访问地址。

### 4.3 运行时与深度支持

Web 适配器接入现有相机、选择、裁剪、场景状态和资源统计；Renderer 的调度与释放封装在引擎边界，不在 React 每帧 state 中更新瓦片。

Native 分两档：首期允许把已完整获取的小型 mesh tileset 转为规范网格资产，标注“已烘焙静态模型”，保留 feature 来源；大规模 tileset 要实现独立空间调度合同，不能把静态烘焙当成原生流式支持。点云载荷依赖 PC 路径，未实现时报告不支持。

高保真后续包括隐式分块、材质/元数据扩展与 feature 查询，均绑定固定官方测试及真实样本。查看 1.0 b3dm 成功不等于 1.1 全支持。

### 4.4 任务与验收

| ID | 任务 | 验收 |
| --- | --- | --- |
| TILE-01 | 本地 tileset 识别、依赖清单与标准校验 | 缺纹理、断链、循环、越界及未知 required extension 被阻断 |
| TILE-02 | Web 显示、SSE/LOD/缓存与 feature 选择 | ADD/REPLACE 正确；跨层级定位同一 feature，卸载后能重载 |
| TILE-03 | 离线包、坐标融合、属性与发布 | 关闭外网后完整浏览；城市坐标和 BIM 控制点一致 |
| TILE-04 | 1.1 深层能力及 Native 分档接入 | implicit/subtree/multiple contents 独立矩阵，目标差异显式报告 |

建议首批至少 10 个独立 tileset，覆盖建筑、摄影测量、实例和点云；固定相机路径测请求数、字节数、首次可交互、P95 帧时与峰值驻留。离线清单必须无意外远程依赖；原始几何/feature 身份在格式解包和烘焙前后保真，LOD 只改变显示精度。

## 5. Rhino 3DM

### 5.1 Reader 与两条几何路径

优先官方 rhino3dm/openNURBS，按需加载而不是放入首屏 bundle。固定版本核查 3DM 文件版本、原生对象类型、材质读取与 Windows/浏览器构建。官方提供保存网格读取方法，这能覆盖一部分可视场景，不代表具备完整 Rhino 建模内核。[rhino3dm](https://www.rhino3d.com/features/developer/rhino3dm/)、[显示网格读取](https://developer.rhino3d.com/guides/opennurbs/reading-render-meshes/)

```text
3DM 对象 → 网格对象 / 有保存网格的 Brep、Extrusion → 规范网格
         → 无保存网格的受支持曲面 → 3DM-to-OCCT 桥 → 规范网格
         → 未支持几何或插件对象 → 保存来源、逐对象缺失报告
```

3DM-to-OCCT 桥需要独立开发：NURBS 与修剪、参数空间边、周期缝和方向映射复用主方案的验证经验，但 3DM 与 X_T 的对象结构不同，不能直接复用文本解析器。

### 5.2 保真合同

- 保留对象 UUID、图层树、图层/对象可见性、锁定状态、对象名称和用户字符串。
- 区分块定义与块实例，支持嵌套、非均匀缩放与镜像；源中缺定义或外部链接时补齐依赖，不能炸开为无身份散网格后宣称完整。
- 材质继承按对象、图层、父实例等已验证规则解析；PBR、透明、贴图与 UV 分项测试，不以统一默认材质替换。
- 单位和轴向显式转换；曲面边、点、线、注释分别保留适合的数据。零三角面但含合法曲线的文件应返回“曲线型模型”，不能误判文件损坏。
- SubD、挤出、裁剪曲面、插件对象、渲染网格缓存逐类建支持表；Grasshopper 运算、插件执行和源软件历史编辑不进入静态导入承诺。

### 5.3 接入与任务

拟新增 `bim.3dm-builtin`，在本地 Worker 中读取；输出复用 geometry/hierarchy/properties/source-map/quality。已有网格路径先接入，曲面重建属于下一里程碑。旧端没有曲线显示能力时不隐藏该差异，目标能力报告分别说明。

| ID | 任务 | 验收 |
| --- | --- | --- |
| RHINO-01 | 官方 Reader 固定构建、版本与对象清单 | 无 Rhino 机器能读取；未知版本/对象类型有诊断 |
| RHINO-02 | 网格、图层、块、材质、身份规范化 | 嵌套/镜像/单位与 UUID 映射正确 |
| RHINO-03 | 无缓存 Brep 与常见曲面桥 | 有孔/周期/薄片/曲面离散误差符合主方案预算 |
| RHINO-04 | 系统选择、属性、复转与双端发布 | UUID 关联稳定、缺块不放行、旧资产不被失败复转覆盖 |

建议首批至少 15 份真实模型、三个独立来源，覆盖不同已确认格式版本及网格/曲面/块。重点成对测试同一模型“保存网格”和“不保存网格”的差异；如果只前者通过，支持表必须明示该条件。曲面未支持的文件不得用缩略图当三维预览完成。

## 6. SolidWorks SLDPRT / SLDASM

### 6.1 技术选择与当前证据

以独立的原生文件 Reader 为候选，先做版本化容器、保存状态和配置解析，再接显示数据或 Parasolid 载荷。`cadmpeg` 可作为调研入口，但其当前主分支支持矩阵将 SLDPRT 列为 L1（容器与内容识别层）；高于该层的局部能力不能推出通用完整几何或 SLDASM 支持。[上游 README](https://github.com/cadmpeg/cadmpeg)、[能力层级与范围](https://github.com/cadmpeg/cadmpeg/blob/main/docs/format-support.md)

因此本方向包含自研 Reader 扩展和装配关联工程，不能安排成“装一个库后两天接完”。S0 固定真实源码后核对可复用字段、源资料与许可；候选失败时保留可验证基础模块，重估其余工作。

### 6.2 两类输入分开建设

| 输入 | 要恢复什么 | 不能混淆的点 |
| --- | --- | --- |
| SLDPRT | 当前保存状态、配置、body、面/边、外观、属性与稳定身份 | 单独分区不一定是最终模型；存在载荷不等于已解出有效形体 |
| SLDASM | 装配 occurrence、零件引用、配置选择、变换、抑制/可见状态、实例覆盖 | 零件都能打开不等于装配路径、位置与配置正确 |

处理链：

```text
主文件 + 零件依赖包 → 容器/版本/保存状态判定
 → 配置和原型/实例关系 → 有效几何载荷或已验证显示缓存
 → 源几何到规范资产 → 装配位置/外观/属性 → 完整性审计
```

若内部载荷为二进制 Parasolid，必须有对应二进制载荷解析能力；“X_T 已支持”不能直接满足此条件。公共 `.x_b` 产品入口仍可留在范围外，内部载荷 Reader 与公开格式支持分开管理。

### 6.3 高保真关键项

1. 保存状态：记录生效配置、几何分区、增量/重建结果来源和完整性；无法判定时拒绝完整导入。
2. 显示缓存：检查与保存配置的关联；配置修改后的过期缓存不能用作权威几何。无缓存时走真实拓扑路径，不能回退缩略图。
3. 实例：支持同一零件不同配置、嵌套、镜像、重复实例、虚拟/内嵌部件和抑制状态；源中没有的 BOM 分类不自动推造。
4. 引用：SourceBundle 保存逻辑路径、大小写规则和文件哈希；同名不同目录零件不能错误合并，缺引用定位具体 occurrence。
5. 外观：面/体/零件/实例层覆盖、透明与纹理单独解析；保留自定义属性与配置属性的来源。
6. 身份：可用持久 ID 优先，备选来源键附稳定性说明；换配置或复转后的绑定差异由映射报告解释。
7. 工程边界：读取配合/特征记录可作属性，但不执行约束求解、宏或特征重建，不承诺源文件编辑回写。

### 6.4 任务与验收

| ID | 任务 | 验收 |
| --- | --- | --- |
| SW-01 | 候选源码、SLDPRT 容器/配置与保存状态实测 | 至少三来源；明确 source/derived/unknown 与未解码数据 |
| SW-02 | SLDPRT 有效几何、外观和属性 | 常见零件及无显示缓存样本对比；不完整分区不得 ready |
| SW-03 | SLDASM 依赖、实例/配置与内嵌部件 | 装配数量、路径、变换、抑制与 BOM 可比字段一致 |
| SW-04 | 多版本保留集、复转、系统集成和发布 | 未调参独立装配通过；失败/缺依赖保持旧模型版本 |

建议首批 20 个零件、8 套完整装配、至少三独立来源；来源软件版本由可取得的真实样本建立，不先承诺连续年份全部兼容。几何参考用配套 STEP/JT/GLB 和实例清单，参考导出本身也要记录导出配置与隐藏状态。

每个装配至少核对唯一原型数、occurrence 数、被抑制项、配置、外部引用闭包、世界 bounds、特征尺寸、面材质和关键属性。缺失一个小螺栓不能靠总体面积相近通过，版本矩阵里未验证的分支保持 unverified。

## 8. 进度与资源建议

估算按人周，不是日历承诺。下表假定主方案统一任务、坐标、质量和发布基础可复用；否则需要增加 FMT 基础工作量。

| 方向 | 首个系统可用档 | 高保真扩大 |
| --- | --- | --- |
| 点云 | 6–10 人周：四类读取、分块、Web 和基本交互 | Native/更大规模/高质量融合另估 4–8 人周，自动配准单独立项 |
| 3D Tiles | 4–7 人周：本地 mesh tileset、Web 和离线发布 | 1.1 深层特性/旧载荷/Native 流式另估 6–12 人周 |
| 3DM | 3–5 人周：保存网格、图层、块、材质与系统接入 | 无网格曲面桥另估 5–10 人周，依赖 X_T 共用几何验证基础 |
| SolidWorks | 2–3 人周完成能否采用候选的决策实验 | 若载荷/配置证据成立，常见零件与装配初估 10–20 人周；复杂版本/无缓存路径按季度重估 |

实施顺序建议：先完成 FMT/EXT 共用基础；四方向均先做候选验证；随后 3DM 保存网格形成短期切片，点云与 Tiles 建立空间数据能力，SolidWorks 依证据推进解码。各方向拥有独立验收，不因另一个格式难解而阻塞已经可靠的交付。

## 9. 统一验收与交付

每方向都要有：真实保留集、源/结果属性与几何对比、上传到发布全流程、重启恢复、取消、超时、资源上限、路径与输入安全、复转身份、断网干净机安装，以及 Web/Native 分别记录的支持矩阵。

混合场景最少验证：BIM + 点云控制点对齐、JT/X_T 设备嵌入 Tiles 园区、3DM 建筑与 RVT 楼层共存、SolidWorks 多实例绑定设备状态。只检查显示会漏掉同名文件冲突、坐标重复变换、业务身份碰撞和资源释放问题。

UI 遵循主方案的 `design-taste-digitaltwin` 验收：令牌与品牌一致、双主题、相关断点、真实选择/裁剪/属性交互、至少两轮截图修复和十维评分；可视化对标 ThingJS 的定位交互、Unity 的渲染质量及西门子的工程语义。几何真值比较采用固定中性渲染，不靠美化遮掩丢失。

本轮交付是四方向设计与任务拆分；尚未运行候选 Reader 或实现产品 UI，因此无实际兼容率、性能结果和视觉评分。开发开始后将 PC/TILE/RHINO/SW/EXT 清单同步到执行总账，能力只随证据升级。
