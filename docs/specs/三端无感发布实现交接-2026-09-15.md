## 0. 给实现者的摘要(先读这节)

**目标**:用户在 Studio 编辑器里搭建的场景/看板,发布后要在 **web 浏览器、WebView、原生客户端**三端运行,画面与交互一致("无感")。

**一句话原理**:无感 **不是**"同一份代码在三端跑"(那必然滑向 WebView/WASM,本仓已全局禁止),而是 **"同一份 Runtime Package(数据)被三个薄 runtime 解释"**。

**硬约束(不许违反)**:

1. Deep 路径只实现 WebGPU 语义(web 用浏览器 WebGPU,native 用 `wgpu`);**不做 WebGL 回退**。
2. 最终原生客户端**不嵌入 WebView / Chromium / Electron / Tauri 前端 / 浏览器 JS 运行时**。
3. GUI、文字、图表、HUD、节点画布与 3D 视口**全部经同一个 `wgpu::Device` 与帧图输出**。
4. Three.js / React / ECharts / zrender / Monaco **不进入原生运行时依赖,也不进入渲染帧循环**。
5. 发布包内**不得出现** wasm / js / html / css / webgl / webview / chromium / unity 痕迹(门禁已写在 `packagePurity.ts`,自动拦截)。
6. 任何跨端一致性**不靠共享二进制(wasm)**,靠"契约 + 代码生成 + golden 门禁"。
7. 旧项目正式环境行为不变;Deep 包与原生客户端独立演进,达到迁移门禁前不动默认引擎与项目数据。

**现状一句话**:native 侧**已经能装载并执行 Runtime Package**(校验、GPU 前置核对、LKG 恢复俱全);缺的两个跨距是 **①发布侧不产真包(只产素材 ZIP + `conversionRequired` 标记)、②web 侧不读包(只有 API 快照)**。

**要做的三件事(按顺序)**:

1. **发布侧产真包**:D07/D08 的转换器产物**直接定义为 `DeepRuntimePackage`**(不是中间格式),容器里放 `runtime/package.json`。
2. **web 侧补 loader**:用现有执行层(RenderPacket + deep2d display list)加载并执行同一份包,流程顺序与 native 对齐。
3. **2D 共同数据源**:冻结 `DashboardDocument v1`(编辑器保存即产出),web 与 native 都从它渲染。

**完成判据**:同一份容器,web / webview / native 三端打开,布局、文字、图表数值、DPI 一致;唯一允许的差异是能力报告中登记的对象级 degraded/blocked;篡改单字节被拒绝;三端日志携带同一 `packageHash`。

**排期权威**:任务编号沿用 `deep-engine-next-development-tasks-2026-09-15.md` 的 D01–D28,**本文不新增编号**,只对顺序给建议(见 §8)。

## 1. 目标:什么叫"无感"

三个层次,逐层可测:

| 层次 | 定义 | 判据 |
|---|---|---|
| 内容无感 | 同一份发布包,三端画面一致 | 同 fixture 三端截图对照,差异逐项登记 |
| 能力无感 | 不为某端单独改内容 | 能力预检对象级 `supported/degraded/blocked`,降级在包内可见、可回显 |
| 开发无感 | 编辑器所见即发布后所见 | 编辑器渲染源与发布渲染源同源(同一 `DashboardDocument` / 同一包) |

**"无感"允许的差异**:只允许 `capabilityReport` 中登记的对象级降级(如某图表在 native 为 degraded,有原因与替代路径)。不登记的差异 = 缺陷。

## 3. 现状基线(实测,带路径)

### 3.1 包格式已定型(TS 侧)

`packages/deep-engine/src/runtimePackage/`

- **内容真相**(`types.ts`):`DeepRuntimePackageV1/V2` = `renderPacket` + `deep2d-runtime` + `ibl-environment` + `shader-package` 四类资源 + `materialBindings`(v2 显式化可执行材质归属)。
- **校验 fail-closed**(`validation.ts`):资源索引按 id 排序唯一;`payloads` 键与索引**精确一致**;每资源内容 SHA-256 必须匹配;entrypoint 角色唯一且覆盖全部资源;shader 必须过 v2 合同;materialBindings 与 packet 材质一致。
- **预算**(`types.ts`):`inputBytes 256MB / nodes 2M / depth 32 / resources 132 / shaderPackages 128`;deep2d atlas 驻留 64MB(`deep2d.ts`)。
- **预热**(`prewarmTypes.ts` / `prewarmPlan.ts` / `prewarmExecutor.ts`):两类 item(资源 / shader-pipeline)、缓存键去重、估算字节、并发 ≤16、**原子 commit**、携带 `RuntimePackageBakeEvidence`(几何 plan / meshlet / LOD residency)。
- **纯净化审计**(`packagePurity.ts`):禁止 unity / webgl / webview / chromium / electron / cef / browser-runtime / **wasm** / **js / html / css** 痕迹(含路径混淆探测)。
- 配套:`serialization.ts`(序列化/解析)、`hash.ts`(内容与包 SHA-256)、`materialBindings.ts`、`deep2d.ts`(2D 运行时包校验,text/image 必须烘焙进 atlas quads)。

### 3.2 native 侧已能执行包

`packages/deep-engine-native/src/`

- `runtime_package_startup.rs`:`load` / `load_auto`(文件或字节)→ 校验 → `prepare`;`PlayerContent::from_package` 在**创建窗口之前**做执行支持核对(`plan_shader_materials` + `prepare_runtime_content`),不通过即拒绝。
- LKG:primary 被拒 → 恢复 last-known-good,输出结构化诊断 JSON;present 成功后**才** commit 检查点。
- 入口:拖放 Runtime Package JSON、CLI(`--packet` / `recover` / headless / smoke)。
- 已有测试基线:`deep2d_runtime_atlas`、`deep2d_text_contract`、`chart_ir_contract`、`chart_render`、`chart_scales`、`control_render_contract`。
- Deep2D painter 能力(path fill/stroke/dash/clip/atlas text/hit index)与缺口见支持矩阵(动态字体 shaping 未实现,text 依赖 host 预烘焙 glyph)。

### 3.3 发布侧(缺口所在)

`apps/web/src/delivery/sceneClientPackage.ts`

- 产物 = `.bimscene.zip`:`scene.json` / `applications.json` / `project.json` / `runtime.json` / `assets/` + `manifest.json`。
- manifest 的 `nativeRuntime` 只有一句声明:
  `{ kind: "deep-engine.runtime-package", schemaVersion: 1, conversionRequired: true }`
  **包内没有任何 renderPacket / deep2d / ibl / shaderPackage 载荷**。
- `capabilities` 是四个布尔(`twoD/threeD/dataBindings/liveConnections`),不是对象级、不是分目标。
- 资源闭包靠字符串搜索(`serialized.includes(asset.url)`),`modelIds` 为空时打包**所有**模型(D06 待办)。
- 资产有逐文件 sha256,但 `scene.json`/`applications.json` 无 hash,无包级内容 hash 与版本语义(D04 待办)。

### 3.4 web 侧(缺口所在)

- 在线发布 = API JSON 快照 + 只读路由(`PublishedApplicationRoot` / `SceneViewerRoot` 消费 applications/scene JSON)。
- `deep-engine`(TS)有完整**执行能力**(RenderPacket、deep2d display list、shaderPackage),但**没有"DeepRuntimePackage → 运行时"的加载/执行入口**。

### 3.5 外部事实(2026-09-15 核实,供选型参考)

- **taffy**(`DioxusLabs/taffy`,MIT,3.6k stars):CSS Block/Flexbox/Grid 布局算法;**不做文本布局**(需调用方提供 measure 回调)、不渲染、不解析 CSS。使用方:Servo、Blitz、Bevy、Slint、Lapce(经 Floem)、Zed(经 GPUI)。
- **stylo**:Servo 的 CSS 样式引擎(2017 起为 Firefox Quantum CSS 生产引擎)。嵌入需实现整套 DOM trait 并把 style crate 依赖树引入;许可 MPL-2.0(Blitz 中 `stylo_taffy` 按 MPL 三重授权)。
- **vello**(`linebender/vello`):现为**三个渲染器**——`vello_cpu`(多线程+SIMD,当前最成熟)、`vello_gpu`(CPU 预处理 + GPU 光栅化合成,支持 wgpu 与 WebGL2,**不要求 compute shader**)、`research/` 下原 compute-centric 实现(实验性)。共享 Sparse Strips 架构;文本经 glifo。
- **Blitz**(`DioxusLabs/blitz`):**beta 状态**,可渲染 Wikipedia/Old Reddit 等无 JS 站点,有 Windows/macOS/Linux/Android 构建。栈 = html5ever(解析)+ Stylo(样式)+ Taffy(盒布局)+ Parley(文本布局)+ anyrender(绘制抽象)+ vello(光栅化)+ winit/AccessKit/Muda(外壳);`blitz` 封装暂无交互性,`dioxus-native` 提供完整交互。不做全浏览器能力(WebRTC/WebSocket/localStorage 等明确不做)。

## 5. 目标架构

```
┌──────────────────────────────────────────────────────────────┐
│ L1 声明/编辑层(只存在于编辑器,不进入发布产物)                │
│    React 19 + npm 生态 + Three.js 预览                        │
│    职责:开发效率最大化;发布时被"烘焙"掉                        │
└───────────────────────────┬──────────────────────────────────┘
                            │  发布 = 编译(bake)
                            ▼
──────────────────────────────────────────────────────────────┐
│ L2 Runtime Package(内容唯一真相)                              │
│    renderPacket · deep2d-runtime · ibl · shaderPackages       │
│    + materialBindings + 预计算布局/样式/字体子集/图集           │
│    平台中立 / 可序列化 / 可 diff / 版本化 / fail-closed 校验    │
└───────────┬──────────────────────────────────┬───────────────
            ▼                                  ▼
┌───────────────────────────┐      ┌───────────────────────────┐
│ L3a Web/WebView Runtime   │      │ L3b Native Runtime        │
│  TS: deep-engine(WebGPU)  │      │  Rust: wgpu + deep2d      │
│  + deep2d display list    │      │  painter(同一 IR,         │
│  WebView = 同产物 + 宿主桥 │      │  不同解释器)               │
└───────────────────────────┘      └───────────────────────────┘
            └────────── golden 逐像素门禁(CI:同包三端比对)────────┘
```

**三端入口矩阵**:

| 端 | runtime | 消费 | 宿主能力 |
|---|---|---|---|
| Web 浏览器 | TS(deep-engine WebGPU) | 容器(web 目标) | 浏览器 / HostCapabilities(web 适配) |
| WebView(Three 目标) | TS + 现有 SPA | 容器(three-webview 目标) | 宿主桥 |
| Native 客户端 | Rust(wgpu + deep2d) | **同一容器(deep-native 目标)** | HostCapabilities(native 适配) |

**发布时(编译期)烘焙清单**:

1. 布局预计算(taffy 在构建期跑,IR 只存结果,运行时不做布局)
2. 样式固化(继承/级联/令牌展开)
3. 字体子集化 + glyph atlas(文本 shaping 在构建期完成)
4. 纹理/图集预编码(含格式选择)
5. ECharts option → ChartIR → Deep2D 指令(发布时一次性转换)
6. 行为固化(状态机/行为图;脚本沙箱后置)
7. 能力降级决策(support matrix 在发布时算出,写入 `capabilityReport`)

**运行时热路径(性能纪律)**:每帧只做 **IR 遍历 + GPU 提交**。禁止在热路径出现 JSON 解析、正则、字符串拼接、布局计算、文本 shaping。

## 6. 性能 × 生态最优解

**总原则**:生态只活在编辑器(作者环境),性能只看发布运行时;两者的接缝是"**发布 = 编译**",一切能预先算的都烘焙掉。生态与性能不是取舍关系,而是**分层归属**关系 —— 冲突只在"把编辑器技术带进发布产物"时才出现,而那正是要禁止的。

### 6.1 逐维度决策矩阵

| 维度 | 生态候选 | 性能候选 | **最优解** | 依据 |
|---|---|---|---|---|
| 编辑器 UI | React + npm(DOM) | — | 保持 React/DOM,**不进发布产物** | 09-12 决策:保留语义不执行 React |
| 内容描述 | 直接序列化 React/Three 工程 | 自研二进制 IR | **Runtime Package**(JSON + 紧凑载荷 + 预计算) | `packagePurity` 禁止代码进包 |
| 2D 布局 | CSS(DOM 布局) | 运行时布局引擎 | **taffy 发布期预计算**;运行时仅留受限 flex 子集(动态内容) | taffy 被 Servo/Bevy/Slott/GPUI 使用;工具链用法零依赖准入 |
| 2D 样式 | CSS / stylo | 令牌快照 | **设计令牌快照,不读 CSS**;stylo 不引入 | 09-12 决策 + 最小依赖纪律 |
| 2D 光栅化 | Canvas / SVG / ECharts | deep2d / vello | **deep2d 保持**(支持矩阵已冻结);vello 仅做对照基准 | vello_gpu 路线趋同但成熟度落后;deep2d 已覆盖 stroke/dash/hit |
| 2D 文本 | 浏览器 font stack | 预烘焙 glyph atlas | **发布期 shaping + 子集化 + atlas**;动态 shaping(D05)后置 | deep2d text 合同要求 host 预烘焙 bakedGlyphs |
| 图表 | ECharts(JS) | ChartIR + GPU primitives | **EChartsOptionCompat → ChartIR → Deep2D/compute**(已建) | D 线已建;不带 ECharts 运行时 |
| 3D | Three.js | deep-engine(RenderPacket + wgpu) | **RenderPacket 双实现**(TS WebGPU / Rust wgpu)+ golden | 既有资产 |
| 交互/命中 | DOM 事件 | deep2d hit index | **事件 → hitId → command(白名单)** | 4A 决策;hit index 已实现 |
| 输入法 | 浏览器 IME | 原生 composition/caret 矩形 | **原生 IME + 自绘正文**(隐藏原生控件承接 IME) | 09-12 决策;Figma/Chrome 通行做法 |
| 可访问性 | DOM a11y | AccessKit 适配 | **AccessKit 只接平台 adapter**,语义树与绘制树共享 stable id | 09-12 决策 |
| 数据 | fetch / WebSocket | HostCapabilities(sim/HTTP) | **DataConnection 合同**(D17–D19 已冻结) | 已建 |
| 脚本/行为 | JS 执行 | 行为图/状态机 | **状态机 + 数据绑定优先**;沙箱(QuickJS 类)后置且仅白名单 API | Rive 范式 |
| 跨端一致性 | 共享 wasm 内核 | 契约 + 生成代码 + golden | **不共享二进制**;golden 逐像素 + 代码生成 + purity 门禁 | 项目既有机制 |

### 6.2 三条论证

1. **热路径最小化**:性能上限由"每帧做什么"决定,而不是"用什么语言写"。把布局、样式、shaping、图表布局全部前移到发布期后,运行时只剩 IR 遍历 + GPU 提交 —— 这是与引擎同级的性能结构;反过来,任何在热路径调用生态代码的方案(webview 内的 DOM 合成、运行时 ECharts)都有无法消除的中间层。
2. **生态有界兼容**:生态内容分 A/B/C 三档,A 档原生、B 档适配器、C 档 webview-only —— 每一档的降级**可见、可测、可回退**,而不是"静默不一致"。这比"全量复刻浏览器"或"全量截图"都更可维护。
3. **一致性靠证据不靠共享二进制**:共享 wasm 内核会把"跨端一致"变成"跨端同构"(引入第三份实现 + 胶水 + ABI 维护);而 golden 逐像素门禁 + 代码生成(单一定义 → 两端常量)+ purity 审计把一致性变成**可测的契约**,并且不牺牲任一端的技术选型自由。

### 6.3 性能预算(量化门禁,沿用并细化 09-12 §10)

- 静止 UI:invalidation-driven,无动画/无网络变化时不持续 layout/paint/upload。
- UI、chart、3D 共享 device、资源池与帧图;禁止每控件一个 surface、每图表一个线程。
- 分段记录 P50/P95/P99:retained layout、命中、文本 shaping、图表 layout、GPU encode。
- 冻结基准:10 万控件虚拟列表、百万点增量图表、复杂中文编辑、4K 多面板、大 3D 场景。
- 竞品对比(Three/Babylon/Unity/UE/Godot):同资源、同相机、同质量、同交互、同机器;报告 CPU/GPU/显存/加载/包体/长尾。
- 每个新增第三方 crate:记录 feature、传递依赖、release 体积增量、CPU/GPU 影响、替换边界。

## 7. 接口草案

### 7.1 容器 = 一个 ZIP,内含真包

```
scene.bimscene.zip
├─ manifest.json            容器清单 v2(见 7.2)
├─ runtime/package.json     DeepRuntimePackageV2(现有 builder 产出,内容唯一真相)
├─ assets/...               原始资产(供重烘焙与审计)
─ README.txt
```

- `runtime/package.json` 由**发布侧**用现有 `buildDeepRuntimePackage` 生成(输入:D07/D08 转换器产物 + IBL + shaders + materialBindings)。
- **分工**:容器承载交付语义(目标、来源、能力、原始资产);包承载运行语义(资源、哈希、入口)。purity 审计只作用于包。

### 7.2 manifest v2 草案(容器清单)

```jsonc
{
  "kind": "bim-studio-scene-client-package",
  "schemaVersion": 2,
  "target": "web" | "three-webview" | "deep-native",
  "package": { "path": "runtime/package.json", "packageId": "…", "packageVersion": "…", "packageHash": "…" },
  "provenance": { "projectId": "…", "sceneId": "…", "publishedAt": "…", "generatedAt": "…", "builder": "…" },
  "capabilityReport": { /* 见 7.4 */ },
  "files": [ { "path": "…", "bytes": 0, "sha256": "…" } ]
}
```

- 关键新增 `target: "web"`:同一容器同时服务 web(静态托管/本地打开)与 native(下载打开)。
- `deep-native` 目标**不再带 `conversionRequired`**(转换已在发布侧完成)。

### 7.3 Web loader 最小接口

```ts
interface RuntimePackageHost {
  load(source: string | ArrayBuffer, signal?: AbortSignal): Promise<DeepRuntimePackage>;
  // 与 native PlayerContent::from_package 相同的顺序:
  // 校验 → 执行支持核对 → prewarm plan → 原子 commit → 首帧
  open(pkg: DeepRuntimePackage): Promise<{
    prewarm: RuntimePackagePrewarmPlan;
    commit(signal?: AbortSignal): Promise<RuntimePackagePrewarmResult>;
  }>;
}
```

- 顺序必须与 native 一致:`validateDeepRuntimePackage` → 资源预热(`buildRuntimePackagePrewarmPlan` + `RuntimePackagePrewarmExecutor`,原子提交,失败保留旧状态)。
- 渲染直接复用现有执行层:RenderPacket → deep-engine WebGPU;deep2d → display list(TS)。

### 7.4 能力报告格式(对象级、分目标)

```jsonc
"capabilityReport": {
  "targets": ["web", "native"],
  "objects": [
    { "id": "chart-17", "capability": "chart",
      "web": "supported", "native": "degraded",
      "reason": "…", "fallback": "静态矢量图" }
  ],
  "summary": { "web": { "supported": 0, "degraded": 0, "blocked": 0 },
               "native": { "supported": 0, "degraded": 0, "blocked": 0 },
               "webviewOnly": 0 }
}
```

- 规则:未知能力默认 `blocked`(D02);C 档 `webview-only` 在 `deep-native` 目标下必须阻断或明确要求 Three WebView(4A)。
- 写入容器 manifest;web 与 native 打开时回显。

### 7.5 `DashboardDocument v1`(2D 无感源)

- 编辑器**保存时即产出**(不是导出时转换):节点树 + 样式 token + 数据绑定(`dataset → transform → widget property`)+ 命中区域。
- 只保存结构、样式、绑定和事件意图;**不保存** React 状态、函数体、任意脚本或凭据。
- web 渲染源 = 同一份文档;native 渲染源 = 同文档 → Deep2D retained commands。
- 动态内容需要运行时布局时,只允许**受限子集**(flex 子集 + 虚拟列表),超出即进 B/C 档。

### 7.6 事件与命令

- 统一为 `pointer/key → hitId → command`;命令只能更新页面状态、筛选器、相机/选择/剖切等**白名单动作**;禁止组件直接调用宿主任意 API。
- 命中坐标必须考虑 DPI 与缩放(deep2d hit index 已支持 fill/stroke/image/text + 变换 + z-order;clip 约束未实现,列为剩余)。

## 8. 实现顺序(对齐 D01–D28,不新增编号)

**三条关键路径(对既有排期的顺序建议)**:

1. **D07/D08 的产物直接定义为 `DeepRuntimePackage`**(不是中间格式):转换器在 web(发布)侧运行,输出即包;native 只装载不转换。这样 D10"导出产物接正式 Native 启动"自然成立,且同一产物可直接喂给 web loader(G1/G2 同时收敛)。
2. **`DashboardDocument v1` 冻结提前到 M1 之前**(原为 D15 前置):它是 2D 无感的分水岭;越晚冻结,编辑器与 native 的 2D 分叉越深、返工越大。
3. **web loader 与 Browser↔Native 像素对照靠近 M1 结束**(D10 之后):loader 是"三端无感"的证明件(全部复用现有实现,只补入口,成本低);像素对照(D26 的跨端部分)提前,避免差异在 M2 之后一次性爆发。

**依赖主链**(沿用任务清单):`D02 → D03 → D04 → D07 → D08 → D10 → D20 → D21 → D22`;D01 是合并门槛;D09 在真实 BIM 交付前完成;D24 资产盘点在 M0 即开始。

**领取规则**(沿用任务清单 §6):每次领取前重看 `git status`、近期 diff 与并行会话改动;发现已有实现转为复用/验证,不重新建设;共享合同先定版;GPU 基准串行运行。

## 9. 验收与证据要求

**"无感"的可测判据**:

- 同一容器,web / webview / native 打开:布局、文字、图表数值、DPI 一致;唯一允许差异是 `capabilityReport` 中登记的对象级 degraded/blocked。
- 编辑器所见 = 发布后所见(除登记降级)。
- 篡改包内单字节必须被拒绝(fail-closed);容器/包 hash 变更可追溯。
- 三端启动日志携带同一 `packageHash`。

**门禁与命令**(仓库根,脚本以实际存在为准):

```powershell
pnpm quality:source-size
pnpm gate:repository
pnpm gate:deep-engine-editor
pnpm --filter @bim-studio/web test -- --run
pnpm --filter @bim-studio/web build
pnpm gate:deep-p0:native
cargo test --manifest-path packages/deep-engine-native/Cargo.toml --locked --test runtime_package_contract
cargo test --manifest-path packages/deep-engine-native/Cargo.toml --locked --test runtime_package_startup_recovery
```

**证据格式**(每项任务):任务 ID、commit/工作区差异标识、输入 snapshot/package/asset hash、命令与退出码、测试结果及 skipped/ignored、实际设备与计时来源、截图或报告路径、已知限制。产物仅本地留档;禁止提交运行日志、凭据、客户模型与登录截图。

**纪律**:

- 任何 Deep2D 行为变化,**先改支持矩阵再改代码**(`deep2d-support-matrix-2026-09-14.md`)。
- 失败关闭优先:坏包不发布部分画面(painter 任一 issue 即整体 Err)。
- 视觉验收执行 `design-taste-digitaltwin`(Design Read → 令牌 → 实现 → 两轮截图 → 同族排查 → 十维评分,各项 ≥9/10)。

## 10. 待拍板(实现前需用户确认)

1. **web 端 2D 渲染源**:deep2d(与 native 同源,放弃部分 DOM 生态)vs DOM/React(生态最大化,web 与 native 存在布局/文字差异)。
   **推荐**:发布产物走 deep2d;编辑器本体与 C 档页面保留 DOM。
2. **`target: "web"` 的定位**:是把"web 打开同一容器"作为正式交付目标(需要 loader + 静态托管),还是仅作 webview/Three 目标的既有形态。若选前者,G2(web loader)立刻升为 M1/M2 正式任务。
3. **vello 对照基准的优先级**:是否近期用 vello 跑一次极端矢量负载对照(百万曲线填充),验证 deep2d 的 CPU tessellation 是否成为瓶颈。**推荐**:列入 D25 性能接线的子卡,不单独占工期。
4. **Blitz 路线是否列入备选**:Blitz 已 beta(可渲染无 JS 站点),是"吃掉 C 档(原生渲染作者 HTML/CSS)"的唯一现实路径;但与"零旧包袱/最小依赖"纪律冲突(引入第二套 CSS 引擎 + MPL-2.0)。**推荐**:仅记录为未来选项,不影响当期排期。

## 12. 术语与缩写

| 术语 | 含义 |
|---|---|
| **Runtime Package** | `DeepRuntimePackageV1/V2`,发布内容的唯一真相(四类资源 + materialBindings) |
| **容器(bimscene.zip)** | 交付容器,内含包 + 原始资产 + 容器 manifest + 能力报告 |
| **烘焙(bake)** | 发布时把布局/样式/字体/图表等预先算完的过程;发布 = 编译 |
| **LKG** | Last Known Good,原生启动的包级恢复检查点(present 后才提交) |
| **prewarm** | 资源/shader 管线的预热计划(去重、预算、原子提交) |
| **purity** | 包纯净化审计(禁止 wasm/js/html/css/webgl/webview/chromium/unity 痕迹) |
| **A/B/C 档** | 2D 三档策略:原生 Deep2D / 组件适配器 / webview-only |
| **support matrix** | Deep2D 支持的冻结裁决表(支持 / 拒绝 / 校验拒绝,先改表再改码) |
| **capabilityReport** | 对象级、分目标的能力预检结果(supported/degraded/blocked/webview-only) |
