# DeepMonkey Studio：产品、AI 与引擎升级方案

本方案面向 Native 引擎、打包客户端、Web 编辑器和开放世界负载。目标是把已经存在的能力变成可发现、可保存、可发布、可测量的产品能力，再补渲染与内容生产上的真实差距。本文是方案，不是功能完成声明。

用户追加的性能与效果跃升要求，详见[架构专项](performance-quality-architecture-2026-09-21.md)：增量场景编译、统一可见性与预算、几何材质解耦、静态光照缓存与动态差量、时域重建、帧图资源复用。Deep 2D/3D 的最高约束见[Web 对等与超越验收合同](deep-web-parity-contract-2026-09-21.md)，覆盖本方案所有优化策略。

## 2. 上层接入：已经有、还差什么

| 能力 | 当前可追溯入口 | 本轮判断 / 真实缺口 |
|---|---|---|
| 工业围栏 | 场景目录→资源→工业预制体→参数化围栏；`industrialPrefabMachines`、`sceneEditorController` | 入口存在，但插入先创建基础几何并走 prefab proxy；不能把缩略图里的完整围栏当作最终实例。沿线连续铺设、端点连接与真实几何参数更新仍需补齐 |
| 自然围栏、树木、地面 | V11 素材清单、既有平台素材 API | 素材入库与模型导入已有工作；缺四类代表素材从拖放到离线发布的完整产品证据 |
| 道路 | 案例里的 box 道路；V11 场景搭建规格 | 未找到独立道路作者合同或连接点编辑器。需要直路/弯道/路口、宽度/半径、端点吸附与交叉口处理 |
| 拖放资源 | `SceneResourceBrowser` | 当前是“载入场景”，不是鼠标落点放置；`dragend` 回退会直接插入，取消拖拽可能误插入，应改为仅有效 drop 提交 |
| 物理 / 动画状态机 | 物理面板、导演台、动态运行包、Native Player | 已有产品链；继续按对象类型验证保存、重开、发布与跨端执行，不能因底层求解器通过就扩大覆盖范围 |
| IES / 灯光 | 灯光属性→编译环境→Web/Native shader | 已有作者与消费链，按真实灯具与不同曝光验证 |
| SSR / 柔化阴影 | 后处理与聚光灯属性、发布兼容性检查 | 部分后端可用；目标端不支持时保留精确阻断。不能给三个目标共用一个“已支持”标记 |
| DDGI / probe relocation | `pbrRenderer` 创建 `ProbeClipmapPbrController` | 正式 PBR 宿主已存在；旧“仅测试实例化”已过期。缺多场景运动、漏光、失效恢复与收益证据 |
| GPU-driven / meshlet / Hi-Z | 正式 PBR、独立 LOD 资源与 Native GPU 链 | 已有运行链；重点转为万级负载与 CPU 逐实例剩余成本测量 |
| Visibility buffer / 软件光栅 | `pbrRenderer` feature 分支 | 已有可选生产构造路径；默认关闭、全材质/动态/阴影综合覆盖不等于完成 |
| 纹理数组 / bindless | 材质索引合同、Web shader 双轨、Native 镜像 | 索引合同不等于全部 PBR 管线接线；需要真实绑定、驻留、逐出和设备回退证据 |
| HLOD / 世界分区 | bake、世界分区与流送合同 | 产品作者、发布预处理、播放器调度三段需逐项连通；未找到调用方的选项不能算默认优化 |
| 空间检查 / QTO / 诊断 | 工程分析入口、FrameCaptureSourceMapPanel | 已有入口及本轮前序持久化成果，复用而不新造面板；需用实际项目复验定位与保存 |

统一验收链：入口发现→作者参数→撤销→保存→刷新→重新打开→正式发布→目标端运行→错误恢复。每项能力登记目标矩阵与证据，不以功能名字、导出符号、测试夹具数量计完成率。

## 3. 性能设置应该在哪里

| 范围 | 位置 | 保存方式 | 建议项 |
|---|---|---|---|
| 本机偏好 | 设置→性能；编辑器提供快捷入口，复用同一面板 | 当前用户/浏览器设备，不写场景 | 按需渲染、目录虚拟化、选择加速、后台线程偏好、自动策略上限 |
| 当前场景效果 | 编辑器→画质与环境 | 随场景、可撤销 | 灯光、阴影、GI、反射、雾、曝光、后处理及效果预算 |
| 临时预览 | 编辑器视口快捷菜单 | 会话临时覆盖，明确“预览” | 编辑流畅 / 作者画质、诊断叠层、分辨率预览；发布不继承临时降级 |
| 交付目标 | 发布对话框 | 冻结在发布版本 | Three WebView / Deep Native、画质策略、最低设备能力、内存预算与不兼容列表 |
| 服务运行 | 设置→运行维护 | 服务端 | 维护模式、任务并发、缓存配额与清理，不与个人性能偏好混为同一开关组 |

结论：两处都有入口，但只有一个状态源。用户在编辑器调场景效果；管理员在设置管理服务；本机性能偏好可以从编辑器打开。底层剔除、合批通常自动启用，高级排障开关渐进展开。设备不支持时给出实际原因，不能出现勾选了却没有消费者的开关。

## 4. 2D / 3D 图层统一规则

现有差异已核对：2D Shift/Ctrl 都作为追加选择，3D 支持独立 range；2D 拖放单个节点并改变 zIndex/组，3D 拖放支持多对象；2D 组固定展开，3D 可折叠；2D 锁定后禁止目录选取，3D 目录仍存在检查对象的路径。两边虽然已有编组和右键，语义仍不统一。

| 动作 | 统一规则 | 保留的维度差异 |
|---|---|---|
| 单击 / 多选 | 单击替换；Ctrl/Cmd 切换；Shift 选连续可见行；右键未选中行先选中 | 多对象属性只编辑共同字段 |
| 双击 | 定位并适应选中项 | 2D 画布 fit；3D 相机飞行，不修改作者相机 |
| 显隐 | 眼睛按钮不改变选择；父组显示混合态 | 显隐与是否参与碰撞/数据运行分开 |
| 锁定 | 禁止变换、删除与结构拖放，目录允许选中检查/解锁 | 画布点击跳过锁定对象；检查器只读 |
| 编组 | Ctrl/Cmd+G；取消编组保留子项；组可折叠、重命名，混合状态可见 | 先采用组织分组，不擅自改变 3D 父子变换继承 |
| 拖放 | 统一 before / inside / after 指示；多选整体移动；无效位置明确禁止；Esc 取消 | 2D 顺序决定遮盖；3D 顺序仅影响目录，不能伪造空间前后关系 |
| 键盘 | 上下行焦点、左右折叠、F2 重命名、Delete 删除未锁项、Esc 退出 | 输入框和 IME 占用时不触发全局命令 |
| 搜索 | 名称/类型过滤，保留祖先路径和定位当前选中项 | 3D 增加楼层/构件分类；2D 增加组件类型 |
| 撤销 | 一次用户动作对应一个事务，失败恢复原状态 | 复用各自场景/看板命令，不做平行状态仓库 |
| 大目录 | 统一行高、图标位、菜单、焦点与虚拟列表 | 3D 的模型内部构件树保留只读层级边界 |

实现次序：先抽纯选择/拖放意图合同，再共用行组件与菜单，最后用 2D/3D adapter 提交现有命令。禁止直接把两套数据类型合并成巨大通用树。验收要覆盖 1 万行、折叠过滤、多选跨组、锁定混合态、保存恢复与连续撤销。

## 5. AI 助手升级：功能、交互、页面

### 当前基础

已有问答/执行任务、项目与选中对象上下文、流式响应、停止重试、BIM 证据、看板草稿确认、主备模型、模型目录、思考档位与遥测。`AiAssistantPanel` 目前只向请求传最近六轮，界面最多保留十二轮，并在上下文切换时清空；它与服务端 Agent 的预算压缩不是同一条链。模型/深度设置也不能仅因系统页存在就认为输入框已经可操作。

### 页面结构

默认是编辑器右侧可调整宽度的助手栏；提供展开为完整任务页的入口。完整任务页使用“会话列表｜当前任务与消息｜按需展开的证据/变更预览”三栏。窄屏折叠历史和证据，保留输入、停止与当前任务状态。避免十几个无文字图标要求用户猜用途。

输入区只常驻：输入框、上下文选择、模型、思考档位、发送/停止。项目、页面、选中对象以可移除引用展示，默认选当前上下文；工具与高级参数进入二级菜单。系统设置只管供应商、凭据、默认模型、预算和可用工具。

执行状态以“读取场景→生成方案→预览变更→应用→验证”显示可见进展，每步可展开实际工具结果。失败保留输入、部分结果和重试点。展示执行摘要与证据，不展示私有模型推理链。

### 升级切片

| 优先级 | 切片 | 复用 / 新增 | 验收 |
|---|---|---|---|
| P0 | 输入框模型与思考档位 | 复用模型目录/设置 API；新增会话覆盖 | 请求真实带参数；切模型不丢草稿；不支持的档位不可选 |
| P0 | 会话与运行状态持久化 | 新增会话/运行 ID、事件序号；复用现有项目权限 | 刷新恢复、断线续接、停止幂等、迟到结果不污染新会话 |
| P0 | 上下文预算统一 | 复用 `agentContextBudget` 与上下文来源 | 问答/Agent 同一预算策略，按对象 ID 拉取，用户可看到哪些资料参与 |
| P0 | 统一变更预览 | 复用 SceneCommandTransaction、2D 命令和现有确认组件 | 显示受影响对象/前后值；基于 revision 提交；冲突重新预览；一次撤销 |
| P0 | 基础交互修正 | 复用停止/重试；补 IME、自动滚动、复制和消息动作 | 中文选词 Enter 不发送；用户上滚不被抢回底部；首反馈即时 |
| P1 | 场景搭建助手 | 复用已发布资源目录和受支持命令 | “沿此线铺围栏”生成可预览真实实例；不支持道路连接时明确缺能力 |
| P1 | 性能诊断助手 | 复用分段遥测与资源账本 | 给出具体高成本对象/pass/纹理及可撤销建议；建议前后同场景比较 |
| P1 | 页面/数据/脚本任务统一 | 复用现有问数据、脚本草稿、看板生成 | 一次任务跨面板仍保留上下文、事件和权限；危险写入按实际工具权限处理 |
| P1 | 附件与证据检索 | 复用资源权限与格式审计 | 文件内容有来源、对象定位、截断提示；检索不越项目权限 |
| P1 | 评估集与回归 | 新增固定任务语料，不新增 Agent 框架 | 覆盖成功、工具失败、401/429、超时、取消、冲突、恶意文档、恢复；统计成功率与成本 |
| P2 | 可复用任务模板 | 保存经用户确认的步骤与参数 | 模板版本化、权限重验、运行日志可追溯，避免重复造工作流系统 |

至少用 30 个真实产品任务做基线：问场景、定位构件、生成页面、绑定数据、修改对象、解释不支持发布、恢复失败运行等。指标为任务完成率、首反馈/首 token、总时长、工具失败率、人工修改次数；不能只统计聊天接口返回 200。

## 6. 对比四个引擎：不足在哪

比较分层：Three/Babylon 主要比较 Web 渲染与开发生态；Unity/UE 主要比较 Native 渲染、内容生产和完整工具链。DeepMonkey Studio 的业务编辑器与这些引擎的 SDK 不是同一产品层。以下是能力差距，不是跑分排名。

| 对标 | 官方可核验能力 | 我们的主要不足 | 应采取的路线 |
|---|---|---|---|
| Three.js | WebGPURenderer、TSL；GLTFLoader 与压缩纹理解码接线 | 自研后端材质/动画/扩展覆盖、错误诊断和示例生态远未同等成熟；Three WebView 能力不能记成 Deep 自研能力 | 固定高频 glTF 扩展与材质矩阵、资产诊断、兼容桥边界；不复制全生态。依据：[WebGPURenderer](https://threejs.org/docs/pages/WebGPURenderer.html)、[GLTFLoader](https://threejs.org/docs/pages/GLTFLoader.html) |
| Babylon.js | WebGL/WebGPU、Inspector、节点编辑工具、大世界及丰富渲染功能；另有 Native | 我们的能力开关分散、入口发现、调试器、资源制作和部署体验欠完整；不能把 Native 双端当作独有优势 | 建立统一能力矩阵、可定位 profiler、材质/资源预览和可分享复现场景。依据：[规格](https://www.babylonjs.com/specifications/)、[Native](https://www.babylonjs.com/native/) |
| Unity | GPU Resident Drawer、GPU 遮挡及成熟管线；效果取决于具体管线/设置 | 我们虽已有 GPU 链，仍缺大负载整帧证据、完整内容烘焙、稳定资源加载与可观察的质量分档 | 优先生产实例化/驻留/剔除、异步预热、导入烘焙缓存和场景预算。依据：[GPU 优化](https://unity.com/how-to/gpu-optimization)、[GPU 遮挡](https://docs.unity3d.com/cn/6000.0/Manual/urp/gpu-culling.html) |
| Unreal Engine | Nanite、Lumen、虚拟阴影、World Partition 组成综合大型场景系统 | 我们有若干算法件，但缺完整虚拟几何/纹理驻留链、GI/反射综合稳定性、开放世界内容生产与流送工具；小夹具证明不了同级系统 | Native 优先闭合采样/反馈/预算/流送/材质/恢复，逐场景建立证据。依据：[Nanite](https://dev.epicgames.com/documentation/unreal-engine/nanite-in-unreal-engine)、[虚拟阴影](https://dev.epicgames.com/documentation/unreal-engine/virtual-shadow-maps-in-unreal-engine)、[World Partition](https://dev.epicgames.com/documentation/unreal-engine/world-partition-in-unreal-engine) |

不沿用旧文档未经核验的 Unity 7 / UE 6 标签。后续性能复测冻结准确版本、提交、驱动与资产哈希，不拿不同年份版本的功能混为一个基准。

## 7. 一次列全：高收益优化队列

下面“收益”是机制判断，具体幅度待测；不承诺每个场景都有收益。P0 先补测量/交付与明显断点，P1 扩大生产能力，P2 属重投入或条件收益。

| ID / 优先级 | 方案与受益负载 | 当前基础 / 剩余工作 | 验收关键点 |
|---|---|---|---|
| M01 P0 | 统一三端帧遥测，避免优化错误瓶颈 | 有 latencyStats、Native 测试遥测；补正式 Player CPU prepare/encode/submit/GPU/present | 同一采样窗、P50/P95/P99、样本数、跳样率、设备指纹；默认关闭 |
| M02 P0 | 统一相机、DPR、曝光、viewport 与动态时间 | 有截图/对拍工具；修正宿主标记与裁剪 | 几何/材质/文字/阴影分区比较，动态视频时域检查 |
| P01 P0 | 静态场景按需渲染 | 已有偏好与唤醒机制；补覆盖矩阵 | 静止功耗与提交减少；视频、动画、物理、TAA、选择均可唤醒 |
| P02 P0 | 重复实例共享几何/纹理、保留稳定 ID | 已有合批与 GPU-driven；补作者→发布同源映射 | 万级重复对象 CPU/GPU/显存、独立选取与撤销无损 |
| P03 P0 | 启动关键路径：最小首帧包、后台预热 | 已有 lazy import、启动打点；补生产构建首帧分段 | 首内容/可交互分开；无白屏；冷缓存可重现 |
| P04 P0 | 编译、解码、纹理转码移出主线程 | 复用既有 worker 池，补取消/队列预算 | 主线程长任务下降；取消不残留资源；峰值内存不增失控 |
| P05 P0 | 资产派生内容寻址缓存 | 复用哈希/烘焙链；修重复解码与重复上传 | 同源素材多实例不重复派生；版本变更正确失效 |

## 8. 执行顺序与依赖

第一批：修复证据身份、正式遥测、发布复测、大文件职责拆分、资源入口与参数真实性审计。交付能力清单与可复现实测。

第二批：AI P0、图层统一、本机/场景/发布设置分层；道路围栏先交付一个真实的可编辑、可撤销、可发布切片，再扩大素材族。

第三批：按遥测排序实施 P02/P04/P05/P07/P09/P11/P12/P13，逐项 A/B；已有算法只补接线与证据。

第四批：GI/反射/阴影/材质时域质量与目标覆盖；基于 Native 的世界分区、纹理数组、虚拟几何整帧闭合。硬件 RT 在后端能力与真实负载确认后排期。

每个切片必须登记已有入口、剩余缺口、文件边界、验收资产和基线，不再用“已实现合同”代替“产品完成”。未经验证不报百分比或倍数。大世界目标使用单独压力场景，不将小型两对象夹具成绩外推到开放世界。

## 9. 公平性能验收

至少包含空场景、典型园区、复杂室内、万实例、材质密集、动态动画/物理、2D+3D、多分区移动八类负载。每类固定资产哈希、相机轨迹、光照、分辨率、DPR、质量档和动态时刻。

启动测量区分进程冷启动、应用首内容、资源就绪、可交互。运行测量区分 CPU、GPU、present、输入响应；统一预热与采样窗、多轮取分布。记录显存/内存峰值、资源上传、draw/三角量、长帧、后台功耗与退出恢复。生产发布构建用于性能，开发模式只用于排障。

帧间隔 P95=7.1ms 表示95%的采样间隔不超过7.1ms；它不是 GPU 渲染耗时。144 FPS 约为每帧6.94ms且被显示器封顶，无法区分“刚好够快”和“还有很大余量”。只有在画质与工作量对齐后，才讨论哪端更快、在哪类负载更快。

## 10. 范围边界

### 2026-09-21 用户追加：3D 属性面板完整编辑能力

参考 Unity Inspector 的对象与材质组织方式，在现有属性面板扩展，不另建平行编辑器。所有具有用户可配置语义的能力纳入可编辑清单；引擎句柄、派生统计等保持只读。先按现有合同与真实渲染消费者盘点，再补缺失链路，不能仅添加无效控件。

- 对象：变换、显隐、阴影投射/接收，以及对象类型已有的灯光、相机、动画、交互和预制体参数。锁定与权限约束一致。
- 材质：多材质槽选择、基础色/透明、金属度/粗糙度、法线与 AO、自发光、贴图及 UV、面剔除与透明模式；清漆、透射、折射率等随真实后端能力接通。常用参数优先显示，高级项折叠，保留准确范围、单位与重置操作。
- 作用范围：明确编辑共享材质还是当前对象独立副本，避免意外修改所有实例；多选展示混合值，批量变更按单事务撤销。
- 数据链：即时预览、撤销/重做、保存/刷新、Web 与 Native 发布消费一致；不支持项有明确原因及交付缺口，不能静默忽略作者参数。
- 验收：选中实际模型/子网格编辑、多材质与共享实例、贴图替换失败、撤销恢复、重新加载及正式发布效果。视觉与全量验收按用户安排集中最后。

方案列出差距，不自动开启全部重型开发。工业格式继续遵守内置、自研/开源、本地离线；外部商业 SDK 不作为实现或回退依赖。既有明确排除的完整 Three 插件兼容、复杂 Shader Graph、非 Windows 全平台、Gaussian Splat、完整游戏制作套件不会因本次对标自行恢复为必做项。开放世界按后续用户战略保留，分期验收。
