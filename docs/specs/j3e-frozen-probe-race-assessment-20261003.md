# J3-E 冻结 probe 竞态升级评估（remaining-02 观察项，2026-10-03，主线程，零代码改动）

## 标的

冻结基础 probe（`probe.ts`，SHA `f03948b2…`）的**两步捕获**（先 settle 后 hdr 两次读 results）存在 results 替换竞态——triple-epoch 首跑实证：两步间 results 被下一相位替换，产出同常值假差 `0.2132568359375`（帧相位伪差同族，非恢复链缺陷）。

既有处置：派生 `probe-triple.ts` 已改**原子同帧捕获**（同一 results 对象上校验帧号+取字节）后 4/4 全过——修复式已验证；冻结件保持不动记观察项（remaining-02）。

## 影响面判定

- **产品功能零影响**：竞态在测量 harness 的探针，不在渲染器/恢复链产品源码。产品侧恢复语义已由派生件 4/4 与 mixed 双序列独立证明。
- **测量工具可靠性受影响**：冻结 probe 是 J3-E 验收线的权威探针——竞态是相位相关偶发，意味着用它跑长序列时存在假失败概率（首跑已实证一次）。

## 升级收益 / 成本 / 风险

| | 内容 |
|---|---|
| 收益 | 下一「帧时+≥5 成对统计」独占 GPU 批必须用该探针——不升级则统计批存在假失败重跑风险（每次重跑=整批 GPU 时间）；升级后测量工具与派生件同一可靠性 |
| 成本 | 小：把派生件已验证的原子同帧捕获模式**回移植**到基础 probe（修复式 4/4 已证）；SHA 重锚一次（f03948b2→新），历史收据引用链更新 |
| 风险 | 低：历史收据效力不因升级失效（原收据实测时未触发竞态，结果本身有效；升级只是消除未来偶发）；冻结语义由「SHA 不变」转为「SHA 重锚有案」——需在账本显式记录重锚依据 |

## 建议

**升级值得做**，且应作为「最后统一验收」批次的前置项：统计批开跑前先回移植原子捕获+重锚，避免批内假失败。升级本身约 0.5 天（回移植+对拍一轮 triple-epoch 确认 4/4 不回归+SHA 重锚记录）。

## 拍板点

1. 批准回移植（冻结件 SHA 重锚，账本显式记录）；
2. 或维持冻结不动（接受统计批偶发假失败重跑的成本）。

不拍板则默认维持现状（不改动冻结件——既有纪律优先），统计批按原样带风险开跑。
