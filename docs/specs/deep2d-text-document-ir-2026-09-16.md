## 交付范围

`packages/deep-engine-native/src/platform_text/text_document.rs`(696 行)提供
`TextDocumentV1`:文本 + 样式区间 + 段落 + inline object 的版本化表示,带局部失效报告。

复用而非重建:字素簇沿用 `layout::grapheme_clusters`(同一套 UAX #29 简化规则),
编辑语义与 `text_edit`/`ime` 的簇粒度一致,不引入第二套文本模型。

## 关键设计决定

**区间一律用簇索引用字节偏移。** 字节偏移会在组合字符、emoji、ZWJ 序列中间切开,
产生非法簇;簇索引跨语言可复算,是 TS/Rust 共同解释的前提。测试里用 `"a👍b"`
锁定:emoji 是 4 字节但只占 1 簇,区间按簇表达时不会被切开。

**样式用标识而非内联属性**(`TextStyleId(u16)`)。改一处样式定义不影响区间本身,
跨语言比对也稳定;具体属性由样式表解析,文档不维护第二份真源。

**区间不重叠、按序**,查询是二分(`partition_point`)。半开区间 `[start, end)`。

**局部失效**:每次修改返回 `TextChange{previous_revision, revision, start_cluster,
end_cluster, cluster_count_changed}`,只描述真正变化的簇区间。`revision` 单调递增,
被拒绝的修改**不推进** revision(有测试锁定)。

**段落与 inline object 是两类不同东西**:段落覆盖文本,inline object 锚定在簇位置之前
(`at_cluster == cluster_count` 表示追加末尾),使文本索引与渲染顺序一致。

**刻意不含**:字体选择与回退(归 P1-19)、真实 IME 事务(归 P1-20)、bidi 重排
(需要已批准的 shaping 库)。本模块不猜字体——缺字体必须由上层给对象级诊断。

## 对抗式自查发现并修复的两个真实缺陷

初版实现 11 项测试全绿,但我对「多区间边界」路径没有把握,追加了对抗性测试,
**抓到两个初版就存在的真实缺陷**:

### 缺陷 1:删除横跨多条样式区间时产出重叠区间

实测输出 `[{0,3,style1}, {2,3,style2}, {3,4,style4}]` —— 前两条重叠。

根因:逐区间独立映射端点,当删除段同时切到两条相邻区间时,两条都可能延伸到同一编辑点。
重叠会让 `style_at` 的二分给出**矛盾答案**(相邻簇得到互相矛盾的样式)。

修复:映射后规范化——排序,再把每条左端推到上一条右端。不变量「排序且不重叠」恒成立。

### 缺陷 2:段落「每簇必属某段」只在编辑期维护,构造期留空洞

`TextDocumentV1::new("中文abc👍", …, paragraphs=[{0,5}])` 的 6 簇文档中,
簇 5 无归属,`paragraph_at(5)` 返回 `None`。

根因:我把该不变量当成编辑期职责,但构造期只校验不补全,文档**从诞生起就带着空洞**。

修复:抽出 `fill_paragraph_gaps`,**构造期与编辑期共用同一实现**,空洞处沿用相邻段落对齐
(不引入新语义)。同时明确校验/补全的语义分工:重叠/乱序/越界是调用方错误必须**拒绝**;
空洞是允许的输入形态(作者只标了部分段落),**补全**到全覆盖。

### 同族排查

沿「端点独立映射需要规范化」与「构造期不变量必须在编辑期同样成立」两条线索排查,
发现并修复第三处:`shift_inline_objects` 排序后可能产生**重复位置**(多个对象被压到
同一编辑点),而构造期明确禁止重复。修复为按 `object_id` 稳定排序后按位置去重,
使结果与输入顺序无关(可复算)。

## 验证

`text_document_tests.rs` 16 项:

| 类别 | 测试 |
| --- | --- |
| 簇边界 | emoji 多字节簇不被切开;组合序列(基字+组合符)永不被编辑切开 |
| 构造校验 | 越界/乱序/重叠样式拒绝;坏段落与 inline object 拒绝;空文档合法 |
| 查询 | 半开区间与二分正确性;局部查询只返回相交区间;空区间返回空 |
| 编辑平移 | 编辑点前不变、之后平移;插入继承插入点样式;revision 单调 |
| 不变量 | 删除跨多区间后不重叠;连续 6 步编辑后全部不变量保持;段落恒全覆盖 |
| 同族回归 | inline object 去重;构造期补全段落空洞 |

其中 4 项是对抗性/不变量测试,正是它们抓到了上述三个缺陷。

## 诚实边界

- **TS 侧尚未实现同一合同**。P1-18 要求「TS/Rust 共同解释」,本轮只交付 Rust 侧;
  跨语言 golden 与 TS 实现是后续切片(参照 P0-02 的 TS→Native golden 做法)。
- **不含 bidi/fallback/shaping**:`layout` 模块的简化 UAX #29 与断行规则是既有基础,
  完整 shaping 依赖仍需批准,本模块沿用而不冒充完整实现。
- 未接产品路径:文档 IR 目前是独立合同,尚无宿主消费方(接线归 P0/P1 后续)。
- 未跑真实 GPU 与浏览器——本切片纯 CPU 逻辑,无可视化产出。
