# Deep 2D / 3D：Web 对等与超越验收合同

用户要求：自研 Deep 2D、3D 必须完整复刻 Web 中的场景，性能与效果只能提升，不能下降。本合同是交付门槛；不代表当前版本已经通过。

## 参考对象

以冻结的 Web 作者场景及其可回放操作为权威，包含资源哈希、组件版本、数据输入、字体、画布尺寸、DPR、相机、曝光、色彩空间、时间轴与随机种子。对照正式生产包，不能用已启动的开发浏览器与冷启动 EXE 计算倍率。

场景模型是唯一内容来源。Web 的 DOM/CSS 不是 Native 可自动执行的通用绘制指令；Deep 2D 需要明确的布局、文本、裁剪、路径、图像与组件绘制合同，以及绑定、事件和导航合同。无法编译的自定义组件必须保留诊断并阻断相应 Native 发布，不能静默替换为图片、空白或近似组件。

## 必须对齐的四层

| 层级 | 验收内容 | 失败处理 |
|---|---|---|
| 内容与几何 | 对象、层级、变换、材质、灯光、环境、相机、动画、2D 布局、字体字形、图表数值与单位 | 缺失/替代/语义偏移直接失败 |
| 画面 | 色调映射、曝光、阴影、反射、透明排序、裁剪、文字排版、圆角/渐变、图表与覆盖层 | 固定测试条件；定位差异来源后修复 |
| 行为 | 鼠标/键盘、拾取、hover、tooltip、焦点、筛选、钻取、场景跳转、时间轴、异常恢复 | 相同输入回放得到相同语义结果 |
| 非功能 | 冷/热启动、首个正确可交互画面、CPU/GPU 帧时间、输入延迟、内存/显存、加载尖峰 | 画质先通过，再比较成本 |

## 架构落实

1. **共用语义，专用执行**：作者数据编译到版本化中间表示；2D/3D 共用对象 ID、资源引用、数据绑定、时钟和事件顺序。Three、Deep WebGPU、Native 各自执行，不要求共享低层 API。
2. **能力预检前置**：发布前遍历真正使用的组件和效果，产出逐项 supported/unsupported 及具体对象路径。仅声明支持不足以放行，必须有目标端消费者和验收样本。
3. **混合页面统一合成**：2D 覆盖与3D视口按同一目标尺寸、裁剪和色彩约定合成；坐标转换统一处理缩放、DPR 与输入命中。文字图表不能随3D内部动态分辨率一起变糊。
4. **优化不改作者意图**：剔除、缓存、实例化与异步编译必须语义透明。LOD/超分/近似光照只有在对照画质验收通过后进入目标策略；不能因自动极速模式绕过用户要求。
5. **保留对照模式**：“Web 对齐”用于审阅、回归和证明无退化；“Deep 增强”可在此基础上提高阴影、GI、反射与采样质量，并保持场景语义。增强不用于掩盖基础复刻失败。

## 如何验收“完美复刻”

内容和行为要求精确一致。像素层不以一个 SSIM 总分代替判断：分开检查文本/图表区域、3D 主体、透明和阴影，输出差分图、局部放大及动态视频；对象丢失、文字缺字、数值不同即使总体分数很高也失败。

不同图形 API 的采样与浮点差异可能造成像素不逐位相同。它们仍需归因，并在固定验收图集上证明没有可感知退化；不得自行放宽旧阈值。字形、布局、色彩和交互差异不能归入可接受光栅误差。阈值与人工验收准则在基线建立后冻结。

性能按每个支持的设备档位与场景类分别判断，重复测量、记录置信区间和热状态。至少报告首个正确可交互画面、帧时间P50/P95/P99、输入延迟、内存/显存峰值；均值提升不能抵消P99退化。目标是各关键指标不退化并在明确瓶颈上取得可重复提升；达不到则该目标/场景不标记验收通过。

## 页面到正式 Native 的最终硬门禁（用户 2026-09-21 补充）

必须通过实际产品页面发起 Deep Native 打包，不能以 CLI 单独编译、开发 EXE、接口单测或产物文件存在替代。各阶段串联同一个场景版本、发布任务 ID 与产物哈希，保留页面证据、服务端构建结果和运行日志。

1. 在编辑器创建/修改并保存代表性 2D、3D、混合页面，从发布面板选 Deep Native。覆盖新增属性编辑结果，尤其材质槽/贴图/透明、灯光/环境/色彩，以及文字/图片/输入框/选择器/视频/图表/数据绑定/导航。
2. 逐项核对页面能力预检与真实编译器，支持项不得因旧黑名单被拒；不支持项必须精确定位对象和参数并修复本轮范围内能力。清晰阻断只是避免错误产物，不等于兼容性任务通过。
3. 实际执行构建→页面进度→完成下载→验证完整性→新目录解压→正式程序启动，确认产物确为 Deep Native，未被 Three WebView 或工作台替代。
4. 在不依赖开发服务的环境运行：随包资源离线可用；需要外部业务数据/视频的场景按声明的运行依赖验证连接与断线恢复，不能把动态内容冻结冒充对等。检查字体、纹理、视频解码与必要运行依赖随包完整性。
5. 对正式程序回放键鼠、焦点/IME、筛选、页面切换、三维拾取/漫游及保存场景效果；逐区截图/动态画面对拍，再执行同画质性能对比。
6. 覆盖取消/重试、重复点击、服务重启、资源丢失/损坏、路径含中文与空格、旧版本场景、重新发布和离线重开。失败保留上个有效产物，错误可定位且可恢复。

每个测试场景记录页面入口、作者内容哈希、预检、构建、下载、启动、效果与行为结果。任何本轮承诺能力使页面无法打包或运行缺失，都保持未完成；修复后重走对应完整链路。最终报告列出仍未通过项，不以整体通过率掩盖阻断项。
