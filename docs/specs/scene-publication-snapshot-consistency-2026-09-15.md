# 场景发布快照一致性

Studio 与场景管理发布入口现在检查保存后的快照，并将该快照作为发布请求的前置条件。

## 行为

- 单场景引用检查发现断链、重复对象 ID 或无效交互引用时停止发布；其他场景只用于解析跳转目标。
- `POST /api/projects/:projectId/scenes/:sceneId/publish` 接收 `{ expectedSnapshot }`。服务端在停止旧云会话前比较草稿，并在写入事务中再次比较草稿和当前发布版本。
- 发生冲突返回 409，保留新草稿和新发布版本。成功时，草稿发布标记、线上快照、版本号和历史一次持久化；写入失败不暴露半份结果。
- 比较采用 JSON 传输语义：对象键顺序不影响结果，数组顺序和所有持久化字段均影响结果；可选 undefined 属性被忽略。

旧的无请求体调用仍可发布进入路由时读取的快照，并获得事务内冲突保护；它不能证明客户端曾检查过该版本。显式提供无效请求体返回 400。

## 历史恢复原子提交（2026-09-15）

历史恢复在停止旧云会话前捕获草稿、当前发布和指定历史，随后在同一个存储事务中复核三者。任一变化返回 409，场景被删除返回 404。成功后，线上快照、递增版本、历史和草稿发布设置一次写入；草稿内容与编辑时间保留。持久化失败时全部保持原状态。

历史接口仍使用发布时间定位。相同时间对应多个版本时返回 409，且不停止云会话；历史补全不再吞掉同时间不同内容或版本的当前记录。旧记录缺少 version 时，仅在其余 JSON 内容一致时视为已收录。

存储回归覆盖真实队列、单次持久化、失败回滚及重新加载；路由回归覆盖等待云会话期间的保存、发布、删除和并行恢复。该保证适用于既有单 API 写实例，未增加多进程数据库 CAS。

## 撤回与删除的版本条件（2026-09-15）

两条 DELETE 路由先读取指定项目的草稿和当前发布，再停止该发布的云会话。存储事务复核完整草稿和发布；等待期间的新保存、新发布或撤回返回 409，场景已删除返回 404。不会将旧请求应用到新版本。

撤回保留历史和草稿内容，仅清除发布标记；删除一次清除该项目场景、当前发布和历史。旧存储方法复用相同清理逻辑，同 sceneId 的其他项目记录保留。云会话版本冲突保留原 409/错误码，Worker 故障为 502。

Worker 停止和元数据持久化属于两个系统：元数据冲突或写入失败时，原会话可能已停止，不自动重启。发布记录和草稿仍保留，可重新检查后操作。项目级删除的会话清理与跨实例存储协调尚未收口。

## 前端撤回与删除响应（2026-09-15）

撤回只在最新场景上清除原发布标记，不再用请求开始时的完整场景覆盖列表或编辑器。若列表或编辑器已有不同发布时间的版本，则保留其发布标记。目标项目、场景和名称在调用时捕获，传入对象后续变化不会改变请求结果的归属。

离开场景、切项目、打开其他页面或重新打开同一路由后，旧成功结果仍按项目与场景更新列表，但不清空当前编辑器、不导航、不显示旧提示；旧错误也不弹到新场景。当前操作失败正常显示错误。稳定 getter 读取最新路由和列表，状态更新函数执行时再次核对作用范围；存在新发布时抑制旧撤回提示。
