# Deep Engine 核心能力开发执行计划

日期：2026-09-27。状态：开发计划，任务尚未按本文验收。适用：引擎、图形、仿真、工业模型与应用团队。

本计划从《Deep Engine 对 Unity 7 / UE6 全量审计》的 122 项中裁剪用户明确排除的领域，将保留能力落实为 24 个工作包。任务完成以代码、真实消费路径、场景结果和可复现实验证据为准。文中的性能阈值是开发验收目标，不是当前实测结果或对 Unity/UE 的性能承诺。

## 1. 范围与原审计逐项映射

排除：平台适配与交付、通用编辑器与开发工具、媒体、网络与在线、生态、多人。保留：渲染、资产计算与场景运行、动画角色、物理仿真、粒子特效、现有端内 UI/2D、工业格式与语义、性能质量。

边界：保留能力可在现有参数面板或 API 中增加最小配置入口；不建设新的通用图编辑器、IDE、协作编辑器。WebGPU 与已有 Native/WASM 路径按其当前支持范围验证算法，新增操作系统、设备 SDK、安装器、发布系统均不在本计划。渲染算法的静帧参考输出保留，电影/视频制作排除。实时现场网络连接排除，已采集数据的本地解析、绑定与回放保留。

## 3. 统一工程约束

1. 场景稳定 ID、SI 单位、坐标帧、资源 hash、随机种子和 revision 沿用既有合同。格式输入先规范化；渲染数据不得反向覆盖工业真值。
2. 每项按“现状复核 → 黄金/失败样本 → 最小合同增量 → 算法 → 现有消费方 → 测试/性能/视觉证据”实施。完整能力可拆增量，但未覆盖的子项必须保留在任务记录。
3. 既有支持路径需要回归。技术切片可先在一个后端验证，但工作包验收必须核对 Rust 引擎、WASM 构建/导出、TS 桥与合同、编辑器实际消费的完整路径；适用层有缺口即为 partial，并列出同步补齐动作。确实不适用的层写明结构原因，不用空壳适配凑链路。禁止静默删效果后称为等价。
4. 预算以 bytes、ms、对象数量表示；算法必须有上限、取消、资源释放和输入校验。大数组/几何处理优先现有 worker 和 TypedArray，不在逐帧路径触发 React 全局更新。
5. 不预先替换 wgpu、Rapier、Three，不建立第二套资源缓存、物理世界、时间系统或 DES。硬件 RT 是否需要原生后端扩展在 T10 技术验证后决定，能力探测结果不等于渲染可用。
6. 本文的“待验证”不是认定没有代码。开工发现已完成且证据符合验收时，记录链接后关闭对应子项；只实现剩余差异。
7. Rust 共享实现变更若进入 `deep-engine-wasm`，同次构建 WASM 并校验生成的 JS/类型导出；ABI、数据合同或消费语义变化时同步改 TS 桥和编辑器。Native player 专用改动不得冒充 WASM 能力。每包报告附生产调用链、各层状态、端到端正例/失败例和缺口；仅单层单测通过不能标 passed。

## 5. 工作包实施卡

各卡的实施步骤按顺序完成。每卡的验收同时遵守第 6 节共用门槛。

### T00 样本、基准与证据基线

- 复用：现有 benchmark:render-engines、gate:performance-evidence、GPU 测试脚本及历史 test-output。缺口是场景/设备/口径统一和当前 HEAD 证据。
- 实施：登记运行环境与 commit；固定相机/输入/seed；建立第 6 节八类场景；复跑历史对照；按 122 编号登记 retain/partial/exclude 及已完成子项；把新测结果和旧结果分别存档。
- 产物：`docs/reports/deep-core/T00-baseline.md`、`test-output/deep-core/T00/<run-id>/`（实施时创建）；样本清单含来源、SHA-256、授权边界、参数及期待结果。
- 验收：每个保留工作包至少一个可运行正例和失败/边界例；CPU/GPU/输入/内存缺失计为 unmeasured，不填零；至少三次独立运行；环境/采样口径可复现。未来版本基准不作阻塞条件。

### T01 运行时画质预算与诊断

- 复用：renderGraph.ts、renderGraphScheduler.ts、residencyDiagnostics.ts、Native render_graph.rs；先读既有类型和质量配置。
- 实施：列出 pass 依赖和默认值；补质量档/资源预算校验；建立 capability→运行路径映射及明确降级原因；把 pass 时间、资源 bytes、可见实例、上传量接入现有诊断输出。
- 产物：沿用既有 performance/balanced/quality/ultra 四档可序列化配置，必要时对既有合同做最小增量，输出诊断 JSON；不另建三档体系或 Profiler 产品。
- 验收：非法组合可定位拒绝；配置往返不漂移；缺功能不静默吞掉；诊断关闭时同场景 CPU 帧 P95 增幅≤2%，内存不随采样次数增长。

### T02 动态 GI 与烘焙消费

- 复用：probeSurfaceCache、probeRelocationResolver、probeClipmapUpdateScheduler、probeSceneRadianceProducer、lightmapProbeBaker、现有 Native probe grid。
- 实施：追踪源几何/材质/灯光 revision 到脏区域；限定每帧更新预算；验证探针落在墙内、薄壁、开门、移动设备、昼夜；补当前支持运行路径中烘焙数据 hash/版本失配处理；接入现有场景参数。
- 产物：增量失效与收敛策略、烘焙消费修复、漏光/动态场景对照；不重建方向集或探针系统。
- 验收：小场景相对高采样 CPU/参考积分的稳定区域线性辐照度归一化 RMSE≤10%；动态变化 1 秒内达到该容差（固定预算档）；墙内探针不产生明显穿墙亮斑；保存重读引用一致；性能预算不因全场景重算失控。

### T03 反射融合与失效处理

- 复用：rayTracing/ssrRayExtension.ts、现有环境探针和材质粗糙度链。

- 验收：镜面、粗糙金属、屏边和移动物四组序列无黑洞/NaN；静帧参考区域 SSIM≥0.98；不能用增加全屏模糊消除错误；每档记录误命中/回退率和 GPU 成本。

### T04 多灯、缓存阴影与虚拟阴影

- 复用：lighting/worldLights.ts、importanceBudget.ts、已有 shadow allocation/governor 和 Native shadow_map。

- 验收：64/256/1024 灯压力阶梯记录吞吐；光源预算与投影灯数量分别报告；冻结场景阴影无重复全量更新；移动灯/遮挡器不残留旧影；分页内存不越预算。分页路径只有在等画质收益成立时替换默认，未通过则保留实验状态并继续该子项。

### T05 簇几何、LOD 与 GPU 实例剔除

- 验收：CPU 可见性参考集合不被错误漏剔；轮廓屏幕误差≤1px（指定视图）；10,000 重复实例场景 CPU 提交 P95 比 T00 降低≥50%，draw calls 不增加；未达到时提交分阶段数据而非改低基线画质。

- 验收：固定视图终态与全驻留参考 SSIM≥0.99；缺页时有合法低 mip；压力场景预算超出≤5%且≤2帧恢复；往返相机不出现无限换入换出；取消后无在途引用泄漏。

### T07 时域重建与动态分辨率

- 验收：细栅栏、薄管、旋转叶片、移动角色序列保留边缘；切相机一帧内清空旧历史；标准强对比测试残影能量 3 帧内低于源对比度 5%；67%内部分辨率模式同时报告画质与 GPU 节省，禁止只报 FPS。

### T08 材质覆盖与颜色一致性

- 验收：材质球/工业玻璃/拉丝金属黄金场景；参考线性色块误差≤1/255（避开压缩与 tone-map 区）；能量守恒测试无凭空增亮；已有支持路径参数往返一致；Shader Graph 只补求值/节点，不扩通用编辑器。

### T09 天空、云、雾、水与天气

- 复用：fog/volumetricFogPass、已有环境 shader、场景环境合同。

- 验收：昼夜、室内外、入水视角和逆光序列无曝光跳变/体积闪烁；固定 seed 相同；水/雾不破坏剖切和透明排序；对照物理参考与两轮视觉验收；各子系统计时和内存独立报告。

### T10 硬件 RT 与静帧路径追踪

- 复用：rayBackend、现有软件 BVH/射线参考、Native ray_tracing_capability.rs；该能力探测不启用 RT 渲染。
- 实施：技术切片先验证当前 wgpu 路径的真实能力；需要原生扩展时给出最小资源互操作设计与验证；接入 BLAS/TLAS 构建/refit、材质/纹理、阴影/反射；随后路径积分、采样、累积、降噪和静帧参考导出。
- 验收：软件与硬件射线命中三角形/距离符合容差；动态 refit 不漏更新；不支持设备明确使用软件/光栅路径；标准漫反射小场景路径积分误差随样本增加下降；材质变更立即重置累积。电影队列/编码/分布式渲染排除。

### T11 大场景流送、首帧与内存

- 复用：packetResidencyLoader、gpuRenderResidencyRuntime、worldStreamingBridge、既有 packet 编译缓存及性能探针。

### T12 再导入、依赖与几何处理

- 验收：重复导入幂等；修改一个资源只失效相关节点；未修改对象 stableId 与绑定100%保持；删除对象产生明确断链；非流形/退化/负缩放样本无崩溃；简化后的几何误差受给定公差约束。不得强行修补后静默称原始精度保真。

### T13 地形、植被与程序化生成

### 6.2 通用门槛

- 正确性：无NaN/Inf、崩溃、错误引用、静默数据丢失；失败输入返回明确原因。运行和保存重读的参数/资源身份一致。
- 性能：至少3次独立运行，冷/热分开；P50/P95/P99、样本数、CPU/GPU时间、内存峰值、上传量均记录。既有正常场景P95和稳态内存回归>5%必须定位并给出取舍，不能仅用平均FPS通过。
- 画质：确定性同路径回归默认SSIM≥0.99，并检查差异图；算法改进引起合理图像变化时用预先指定参考/区域指标，不强迫与旧错误图像相似。动态场景单测鬼影/闪烁，SSIM不能替代人工判断。
- 预算：功能超预算必须有明确质量/更新频率降级；关键几何、构件身份、物理结果不能作为降级牺牲项。
- 跨实现：验证已支持路径；浮点误差、Rapier版本和设备能力差异必须明示。未支持后端保持partial，禁止为了通过隐藏测试项。
