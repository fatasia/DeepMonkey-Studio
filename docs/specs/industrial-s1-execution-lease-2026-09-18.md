# 转换执行租约与过期恢复

PostgreSQL 转换任务已接入提交前占用、排队/执行续租和带凭据的终态提交。JSON 单进程存储保持原行为。

## 已完成

- 数据库时间控制 30 秒租约，每 10 秒续租；owner 与递增 epoch 共同限定写权限。后台计时器不阻止进程正常退出。
- 任务先持有租约再保存 queued，未保存成功不启动 Worker。失去续租立即中止本地执行，拒绝迟到的产物；任务最终提交仍需数据库校验。
- 结果提交锁定租约行，等待接管事务后重新校验 owner/epoch。仅检查旧快照的 EXISTS 不足以保证此条件，已用真实行锁竞争测试覆盖。
- 服务启动保留其他活跃 Worker；到期任务以新 epoch 接管后标记失败/取消，不在旧 attempt 目录继续写。列表/详情读取刷新持久化状态，并回收已到期中断任务。
- 提交失败释放占用，终态落库后停止续租。旧 owner 的释放、续租和无凭据发布均不能影响新 owner；失败复转保留原 ready 地址。

## 证据

`postgresStore.concurrency.test.ts` 的 10 项真实隔离 PostgreSQL 测试包含 CAS、唯一竞争持有者、过期接管、旧凭据拒绝、行锁等待后的重验，以及两个真实 ConversionTaskService 的活跃重启/过期恢复/迟到结果丢弃。`conversionTasks.lease.test.ts` 的 4 项覆盖续租时序、异主取消不改本地状态、丢租中止、初次持久化失败清理。API 类型检查通过。

全量首轮暴露无租约存储被多加异步等待，破坏原同步 reservation 时序；修复为仅有租约/刷新能力的存储走新增等待。幂等与租约 7 项复测通过。全量结果见恢复总账，未通过前不能引用旧全量快照。

## 跨实例取消更新

取消意图存入租约行，接口立即返回 cancelling。执行器每 10 秒续租及成功提交前检查，触发已有 AbortController 和资源退出机制；数据库成功提交条件同时检查未收到取消请求，避免心跳间隙发布。列表刷新可读到取消意图；执行器崩溃后，新 epoch 恢复为 cancelled。跨项目请求仍拒绝。

新增两项执行服务测试验证异主取消、跨项目拒绝和心跳前完成竞态；新增真实 PostgreSQL 测试验证持久化取消、重复请求、成功发布拒绝及到期接管保留取消意图。相关四文件 23 项通过，API 类型检查通过。10 秒是正常轮询周期，不是进程资源退出耗时保证；最终 cancelled 仍等待原资源退出机制。

14:25 合并后 API 全量：209 文件、1361 测试通过，4 项既有跳过；32.18 秒。仓库治理门禁通过。

## 共用隔离执行入口

`industrialJobExecutor.ts` 复用现有 Windows Job 宿主，JT 已改用此入口。保留进程树退出后才返还发布权、取消后等待退出、超时、清理环境变量和资源退出登记。回执按实际字节计费，默认 16 KiB、硬上限 1 MiB；超预算拒绝，不在 API 累积无界输出。

真实宿主新增成功退出、取消后代和回执超限验证，连同已有宿主/JT/转换共 16 项通过，API 类型检查通过。本次没有修改 Rust 宿主或重编一套隔离程序。
