# AI 模块能力与交互提升计划（AI-UP 批次）

状态：规划 v1（2026-09-04，GLM-5.3 依据用户指令规划：AI 能力提升与交互流程提升纳入任务；预测维护对标先导智能；其余对标市面主流平台）
归属：总账第 14 节 S7 批次的展开与优先级提升。

## 1. 对标基线

### 先导智能（预测维护，用户点名）

先导智能是锂电智能制造装备龙头，其设备智能运维的公开能力口径：设备健康评分、故障预测（剩余寿命 RUL）、维护工单联动、备件与维护周期建议、产线级 OEE 与停机归因。对本平台的有效门槛：

- 预测维护从"异常检测展示"升级为**可执行运维闭环**：健康分 → 剩余寿命/劣化趋势 → 维护建议（窗口/工时/备件）→ 人工确认 → 工单/通知落地 → 维护后回归验证。
- 输出必须带证据链（数据窗口、模型版本、特征贡献），与既有"候选—证据—人工确认"原则一致。

### 市面主流 AI 助手交互基线（帆软 FineChatBI/山海鲸 AI 问答/ThingJS AI/Grafana Sift、Copilot 类）

- **自然语言即操作**：输入自然语言 → 平台翻译为受控操作（查询/看板/脚本/3D 动作）→ 预览差异 → 确认执行 → 可撤销。全链不裸奔。
- **上下文感知**：助手知道当前页面、当前选中对象、当前数据产品，回答与动作默认作用于当前上下文。
- **多轮与澄清**：歧义时给选项让用户选，不猜。
- **流式 + 过程可见**：推理步骤/执行的查询/引用的数据流式展示，可中断。
- **一键落盘**：AI 生成的看板/脚本/查询可一键保存为项目资产并可迭代。

## 2. 现状（复用，不重复造）

- 插件化 Provider/Capability 合同、`studio.ai.invoke`、AskData（规划-校验-执行-指纹）、脚本 AI（草稿/预览/确认/撤销）、BIM 问答（检索真实构件元数据+几何初筛）、看板生成方案、设备维护候选与证据、失败降级——全部已有（ledger §6、数据域摸底 §5）。
- 缺口：交互分散在多个面板、无统一对话入口、无多轮澄清、过程不可见、预测维护缺 RUL/健康分/工单闭环、看板生成不落盘为可迭代资产、脚本 AI 无会话记忆。

## 3. 批次（AI-1 → AI-5，交互与能力并进）

### AI-1 统一 AI 工作台（交互基座）

全站统一的 AI 侧边栏（编辑器/数据中心/管理页同壳层）：

- 单一对话入口，流式响应 + 步骤折叠（思考/查询/动作三段，可展开可中断）。
- 上下文芯片：自动携带"当前页面/选中对象/数据产品/场景"，用户可点掉。
- 澄清交互：歧义时渲染选项卡（按钮式多选一），不做自由文本猜测。
- 能力路由：同一输入按意图分发到 AskData/看板生成/脚本助手/BIM 问答/维护诊断（复用既有 capability 合同，不新造协议）。
- 历史：按项目存会话（本地 + 服务端可选），可回放、可继续。

### AI-2 预测维护对标先导（能力重头）

在既有设备维护候选/证据引擎上扩展：

- **健康评分**：多指标加权（阈值漂移/趋势斜率/波动异常），0-100 分 + 扣分明细。
- **劣化趋势与 RUL**：对连续量做趋势外推，给出预计越限时间窗（保守/名义/激进三档），明确标注"统计外推非物理仿真"。
- **维护建议与工单闭环**：建议（窗口/工时/备件类型）→ 人工确认 → 生成工单记录 + 通知通道（复用 notification-lite：邮件/飞书/企微/钉钉/Webhook）→ 维护完成标记 → 复检对比（维护前后同指标同窗口对比图）。
- **OEE 视角**：可用率/性能/质量三率聚合与停机归因 top N（数据来自数据中心既有连接，不新造采集）。
- 全部输出带证据指纹，进统一 Study。

### AI-3 AI 看板资产化

AI 生成的看板从"一次性方案"升级为项目资产：生成 → 预览 → **保存为看板页（可迭代）**→ 后续可对同一页继续对话修改（diff 预览→确认）。依赖 S1 语义模型时自动按指标口径绑定。

### AI-4 脚本助手会话化 + 全场景生成

- 脚本 AI 带会话上下文（当前脚本/错误栈/挂载对象），支持多轮迭代与"改错重跑"。
- 3D 场景生成：自然语言描述 → 实体/灯光/相机/动画草案（走脚本 API 白名单），预览 diff → 确认执行 → 可撤销。

### AI-5 评测集与门禁

- AskData 评测集扩充（未知字段/歧义/越权/结构漂移，目标 ≥60 例，通过率门禁）。
- 看板生成可用性评测（渲染成功/数据正确/可编辑），脚本 AI 编译通过率门禁。
- 维护诊断用固定工业夹具回归（不冒充客户结论）。

## 4. 执行模型与排序

- 白天出规格（AI-1 壳层先行，规格含文件计划与合同 diff），夜间实现；AI-1 是 AI-2~4 的交互地基，最先做。
- 排序：AI-1 → AI-2（用户点名重头）→ AI-3 → AI-4 → AI-5（贯穿，每批次补对应评测）。
- 与 EX/S1/S3 队列并行插排：AI-1 规格完成后排在 S1-002 之后执行；AI-2 排 AI-1 后立即做（用户点名优先）。
- 红线：写入类操作一律草案→差异预览→确认→撤销→证据；不得把评测结果写成客户承诺；竞品名不进产品。

## 5. 验收标准（每批次 DoD）

- AI-1：三页壳层统一入口可用；流式+中断；澄清选项交互；上下文芯片正确；会话可回放。聚焦测试 + 浏览器截图。
- AI-2：健康分/趋势 RUL/工单闭环/复检对比全链在固定夹具走通并有证据；通知真实可达（本地 Webhook 验证）。数据链路测试 + 浏览器截图。
- AI-3：生成→落盘→再迭代全链可用；保存的页与手工创建页等价（同一配置结构断言）。
- AI-4：多轮改错重跑演示用例通过；3D 生成草案可撤销。
- AI-5：评测集进 CI 门禁，通过率不回退。
