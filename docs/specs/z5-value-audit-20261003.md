# Z5 消费方与价值审计（2026-10-03，主线程）

## 工具与口径

`apps/web/scripts/deepEngineExportConsumptionAudit.mjs`：解析 deep-engine 24 个子路径入口的导出符号（791 个），对每个符号 grep 六个消费域（apps/web、apps/api、scene-sdk、native、templates SDK、contracts）+ 包内提及计数。测试域（含金样/三方对拍）计入消费面。

## 审计结果

- **126/791 符号有产品/SDK 消费**（活跃面）。
- **665 个零产品消费候选**（`test-output/z5-value-audit-20261003/export-consumption.json` 全量明细），构成三层：
  1. **合同/ABI 冻结面**（最大头）：`*_BYTES`/`*_SHA256`/`CANONICAL_JSON`/WGSL 字符串等——价值=三方对拍与 ABI 冻结承诺（material-abi-192b 等能力清单的证据锚），删除即破坏 J4 能力协商合同。
  2. **引擎 SDK 完整能力面**：导出即对外承诺（H-C7 SDK 分发、8 模板、外部 skill 消费者的可寻址面）；引擎产品的导出面天然大于单一产品当前消费子集（Three.js 同型）。
  3. **引擎内测试消费**：域内 *.test.ts 的消费未计外部但真实在用（对拍/回归防线）。

## 裁决建议（按行定义「无收益不继续微优化」）

**保留全部，不删不收缩。** 收缩导出面无性能收益（导出非运行时开销）、破坏 SDK 合同完整性与能力清单证据锚、且触发大范围测试/金样对拍重写——正是"无收益微优化"的反面教材。审计的价值=确认这 665 个符号是**有意为之的合同面**而非遗忘的死代码。

## 附带发现（如实）

- `FixedStepClock`（physics 入口）在 E3 刀补导出前曾零可达——导出面遗漏类问题的既有先例；本审计后该类"想用而导出缺失"风险已由 24 入口对账覆盖。
- 脚本保留在 scripts/ 可随导出演进复跑（门禁化留待用户裁决是否纳入 CI）。
