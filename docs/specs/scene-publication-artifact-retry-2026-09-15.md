# 发布产物重试

重试使用服务器保存的发布历史快照，本地记录任务身份与状态。它不再次保存草稿、发布或恢复线上版本。

## 已核对的接线方案

1. 发布成功后记录项目、场景、发布版本号、发布时间、快照指纹、目标与导出选项。
2. 重试从 `listScenePublications` 精确匹配原记录，再核对快照身份和指纹。缺失、重复或不一致均停止，不退回当前草稿。
3. 刷新后先取得场景执行锁，再将遗留 preparing/building 标为中断；另一标签页仍在执行时拒绝恢复，由用户稍后重新读取。
4. App 级 hook 持有状态、AbortController 与 attemptId，两个发布入口共用；controller 重建不得丢失任务。
5. 发布对话框显示原版本，并提供独立的重试打包与取消操作。

现有 IndexedDB 恢复存储可保存独立任务 key，服务器历史负责保存快照，不另存一份大场景。历史只保留最近 50 项，被清理后任务应明确显示原版本不存在。

## 当前行为与边界

`controllers/scenePublicationArtifactRecord.ts` 已提供任务记录创建、原历史快照精确解析与中断状态恢复的纯函数。执行器已复用这些函数，记录只包含定位信息、导出配置和状态。

发布控制器已补场景身份与加载代次检查：保存完成前切换场景时不继续发布；发布或打包迟到时不覆盖新编辑器、不关闭新对话框。切走再打开相同 ID 也会识别为新加载。

导出器仍读取当前项目资源和应用，因此当前只保证原发布场景快照，整个依赖包尚未冻结。

执行器已实现按任务去重、尝试编号、精确历史读取、导出与取消，并在各状态切换时等待持久化。存储失败向调用方抛错，不返回虚假的 ready。

导出成功返回表示已调用浏览器下载交付，此后取消无效；ready 持久化失败仍报存储错误，不能改称“已取消”。浏览器文件是否实际落盘仍须单独验证。下载前的取消检查已由导出负责人补齐。

恢复适配器已复用现有 IndexedDB 访问层，每项记录按用户/项目/场景命名空间保存。恢复中断任务时先落盘 failed，再交给调用方；终态不会在读取时重复写入。存储层测试使用可控持久化替身；真实浏览器已验证终态刷新恢复，执行中刷新仍待验收。

App 已持有 `useScenePublicationArtifacts`，Studio 与场景管理的共享发布控制器通过 `buildPublicationArtifact` 委托执行。控制器区分 ready、failed、cancelled，取消保留发布版本并反馈结果；历史读取或持久化失败时保留对话框。

两个发布对话框已接入任务加载、状态、原版本重试和取消，较旧记录折叠展示。实际浏览器已验证 v1 记录跨入口、刷新恢复，下载落盘和执行中取消/失败路径仍待验收，见 [界面验收记录](scene-publication-artifact-ui-verification-2026-09-15.md)。D05 保持本轮待办。

## 同源标签页互斥

`scenePublicationArtifactLock.ts` 复用浏览器 [Web Locks](https://www.w3.org/TR/web-locks/)，按用户、项目、场景的 JSON 元组取独占锁。读取恢复、重新读盘、导出和最终状态落盘都受同一把锁保护。同场景不同交付目标也互斥；不同场景可并行。

锁被占用时立即报错，不排队、不抢占。缺少 Web Locks 的浏览器停止执行并提示使用支持该 API 的浏览器及 HTTPS 或 localhost。锁只保护同源且已升级的客户端，不覆盖旧页面代码、其他浏览器配置或服务端写入。

本页并发读取共用进行中的 Promise，完成后再次读取会重新查库。重试取得锁后重新读取记录，从最新尝试编号开始；不会用另一页开始任务前的缓存覆盖持久化状态。取消后等待最终写入结束才释放锁。

验证：锁 helper 18 项、hook 18 项通过。真实 IAB 两个标签页同时点击 v1 的“再次下载”，一页正常完成，另一页显示“该场景已有打包任务正在执行”；点击“重新读取”后错误消失并恢复已生成记录。标签页终止后的锁释放和执行中刷新仍待真实浏览器验收。
