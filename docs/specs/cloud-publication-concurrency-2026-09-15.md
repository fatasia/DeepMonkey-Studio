# 云发布会话并发保护

本批保护控制面中已存在的会话，避免旧发布请求和迟到 Worker 响应改写新状态。

## 已完成

- 开关操作校验活动会话的项目与发布身份。旧发布请求无法停止新会话，旧刷新请求只返回冲突，不再把当前会话标为失败。
- 健康检查前占用场景启动槽，重复启动被拒绝；检查失败后释放。检查期间政策变化时，原启动不再创建 Worker。
- 政策请求使用本地版本号，迟到停用不会覆盖后来的启用；相同会话的并发停止共用一个 Worker 请求。
- 刷新响应返回后复核会话对象及关闭状态，迟到成功或失败均不能改写已关闭会话。
- 注册表写入按状态捕获顺序串行，避免跨场景并发使用同一个临时文件。
- Worker 创建期间收到停止请求时，先等待 Worker 身份，再停止并等待确认；原启动以取消返回。创建失败保留诊断，停止失败保留 Worker ID 供重试。

管理端“停止当前会话”仍允许清理与当前发布不一致的旧 Worker。发布生命周期停用则携带预期发布身份；两者用途不同。

## 验证与边界

新增 10 项并发回归。前四项先复现失败，再验证修复；包括重复启动、健康检查期间停用、迟到刷新、政策覆盖、重复停止、健康失败重试和跨场景持久化。

后续新增 4 项覆盖创建期间禁用/直接停止、创建拒绝与停止失败重试。API 全量 678 项通过。上述取消不处理 Worker 无响应或创建失败但服务端实际已分配且未返回身份的恢复问题。

这些保护作用于单控制面实例。没有活动会话时仍需权威发布记录校验；持久化失败恢复、项目删除的活动会话清理和跨实例协调仍待收口。D03 全部生命周期验收保持待办。

## 完整发布身份（2026-09-15）

控制面用项目、场景、版本、发布时间及完整快照的规范化 SHA-256 绑定会话，身份随注册表持久化。同时间戳的不同版本或内容也会产生冲突；创建、刷新、启停和概览使用同一身份。Worker 现有 scope 协议保持不变，此身份保护控制面会话归属，不证明 Worker 实际加载的每个资源字节。

旧注册表没有完整身份时，发布相关操作返回 `publication_identity_missing`，保留会话供管理员停止；停止后可重新启动并写入新身份。管理端“停止当前会话”仍可清理旧会话。损坏的身份记录拒绝加载，不用当前发布推测旧会话内容。

场景撤回与删除在停止后还会执行存储版本条件检查，见[快照一致性](scene-publication-snapshot-consistency-2026-09-15.md)。原会话已停止但元数据检查失败时，保留发布记录，不自动重启旧任务。
