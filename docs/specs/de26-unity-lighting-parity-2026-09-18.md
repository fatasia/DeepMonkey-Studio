# DE26：Unity 灯光、受光、GI 与阴影对齐

2026-09-18 用户要求：多灯、全局光照、模型受光与投影/接影等直接影响效果的能力对齐 Unity。它们是 DE26 画质主线的完成条件，不再按“基础光照能显示”验收。

## 对齐方法

沿用 A01 冻结的 Unity 版本与渲染管线。若现有目标没有覆盖所需能力，补录对应 Unity 管线/包版本和设置，保留旧证据，不混用 URP/HDRP 数字。URP 的常规工程照明与 HDRP 的面积光、局部反射/间接光能力分别列明参照；不能挑低配置绕过用户要求。功能、实际视觉、性能成本分别判定。

对齐的是可用能力和最终效果，不要求复制 Unity 内部实现。Web 和 Native 分别验收；硬件限制导致降级时明确显示，但降级不计作目标能力已对齐。灯光与工业转换运行链仍为内置、本地离线，Unity 仅是对标对象。

## 必须贯通的能力矩阵

| 领域 | 完成要求 | 归属 |
|---|---|---|
| 多灯 | 多方向光、点光、聚光和真实面积光语义；灯光颜色/色温、强度单位、范围、衰减、锥角、尺寸可编辑；不是只支持第一盏灯 | E02（语义/入包）、E05（运行/阴影） |
| 灯与模型关联 | 每灯影响层、每对象受光层、阴影层可独立定义；开关某盏灯只影响对应对象，不能把所有灯默认作用于所有模型 | E02 + B01/B02 |
| 投影与接影 | 每对象 castShadow/receiveShadow 独立；每灯阴影开关独立；不受该灯照射但允许向其他对象投影的场景有明确规则 | E05；C03 透明参与规则 |
| 阴影质量 | 方向光稳定 CSM、点光六面/等价全向覆盖、聚光阴影、面积光对应软化；接触、bias、法线偏移、薄物体、级联过渡、缓存失效可诊断 | E05 |
| 全局光照 | 静态光照烘焙/缓存、动态物体采样间接光、光照状态更新、遮挡变化、混合直接/间接光；颜色反弹、室内外过渡、漏光与时间收敛真实可见 | E03 |
| 反射与材质 | 环境与局部反射探针、空间混合/盒投影等适用校正、屏幕空间反射及离屏回退；金属/粗糙度/法线/清漆/玻璃随光照一致响应 | E04 + C02/C04/C05 |
| 模型兼容 | 普通、实例化、LOD、镜像/非均匀缩放、动画/变形模型均核对受光与投影；MASK/双面/透明与剖切有显式支持矩阵 | C02/C03 + E05/E08 |
| 作者到交付 | 属性修改→预览→保存→发布→Web/Native 离线重开，灯、对象层、探针、烘焙资源和质量档一致；不丢字段、不隐式换默认灯 | E02/E08 + G03 |

GI 不能用 AmbientLight、Bloom、AO 或自发光表面冒充；反射探针也不等于完整漫反射 GI。烘焙间接光不能冒充动态遮挡更新。面积光不能仅用发亮矩形外观代表真实照明能力。统一记录模型尺度与强度单位，禁止靠每场景任意调曝光掩盖错误能量响应。

## 复用现有基础，补真实缺口

已确认存在：`lighting/clusterGrid.ts`、`lighting/worldLights.ts`、`lighting/pbrSceneLighting.ts`、`webgpu/probeClipmapPbrController.ts`、`webgpu/probeClipmapRuntime.ts`、`shadows/`、`webgpu/localSpotShadowRuntime.ts`、`shaderAuthoring/packageAdapterCsm.ts`、Native `shadow_cache.rs`。

这些代码不等于矩阵已通过。首先检查：作者字段是否保留、世界/视图空间转换是否正确、多灯预算后阴影信息是否丢失、GPU 实际 pass 是否执行、模型标志是否进 shader、GI 是否被真实场景修改驱动、Native 包是否包含相同语义。已有模块扩展或修复，禁止再建立第二套灯光权威、GI控制器、阴影调度器或材质系统。

## 真实场景与负例

| 场景 | 操作与观察 |
|---|---|
| 厂房灯阵 | 点光/聚光按 32/128/256 总灯数分组测量，投影灯数单列；混合开关/移动/改色温，检查灯光分层、cluster溢出、阴影atlas容量与性能 |
| 室内设备间 | 彩色墙面反弹、遮挡物移动、门打开/关闭、设备进入暗区，检查真实间接光、漏光、更新延迟和旧探针失效 |
| 园区与 V11 素材 | 太阳移动、相机近远切换；道路贴地、围栏细条、树木MASK投影、建筑接影、阴影跨级联稳定 |
| 材质台 | 金属/涂层/塑料/玻璃、镜像与非均匀缩放、不同粗糙度；灯移动时高光和反射方向正确，透明参与策略可解释 |
| 灯光层隔离 | A灯照A层、B灯照B层；分别禁用接影和投影，验证指定对象及其他对象的变化；选择/剖切不意外改光照层 |
| 发布/更新恢复 | 修改光照后发新包，旧候选拒绝、坏探针资源拒绝、取消不污染旧帧；设备重建/离线重开保持已发布版本 |

32/128/256 是测试输入规模，不是未经测量的帧率承诺。每格记录可见对象/几何、实际灯数/投影灯数、CPU/GPU P50/P95/P99、上传、显存账本/可测内存、分辨率、抗锯齿和质量档；隐藏内容、关闭灯影、改变相机不能作为同质性能提升。

画质证据必须有静帧和运动轨迹：直接/间接分离视图、每灯与阴影层消融、深度/法线/探针诊断。固定资产/hash、相机、材质、曝光、灯光和参照截图；先冻结逐场景误差及闪烁/拖影预算，再调优。单个感知相似度分数不替代受光、阴影与GI语义验证；数值阈值仍需 A02/E01 建基线，未测不写达标。

## 执行链

1. **E01 + E02**：色彩/单位校准，统一灯与模型受光合同，作者字段到运行包贯通。
2. **E05 + B03/B05**：多灯与每灯/每对象阴影接线，真实执行、资源账本和缓存正确性。
3. **E03 + E04**：GI 与局部反射接生产场景，补静态/动态物体、脏域更新与失败恢复；与第2步可按依赖并行。
4. **C02/C03/C04/C05 + E06**：材质、实例/变形、透明/剖切、细线与时序稳定合流。
5. **E08 + A03/A08**：双端、离线包、真实场景与Unity逐格对拍；未验证项留在矩阵分母中。

E03/E05 提升为 P0，E04/E08 为 P1；这里的优先级不取消原依赖，不把新验收追写成旧证据已完成。B08 自动质量只能在用户允许的档位预算内调节，锁定画质的 Unity 对拍不得偷偷降分辨率、灯数、GI 或阴影。
