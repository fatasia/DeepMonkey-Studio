# C8 接触场景口径 root 裁定(2026-10-02,主线程/root)

> C8 障碍逐子步对拍批交付 A 家族四条登记(交 root 未放门)。本文件=root 裁定。

## 裁定

1. **四条口径全部采纳为接触场景合同**(与 LD-16/17 diagnostic 同模式,不豁免既有门):
   - ①通道行为断言:带/不带 obstacles 的布料状态必须分叉、接触粒子 |dist−r|≤1e-6;
   - ②执行保真断言:GPU vs 同序 f32 镜像 ≤0.05(色桶序合同);
   - ③物理不变量:拉伸 ≤5% 等带内;
   - ④**深接触场景真值参照=色序 f64/同序镜像**——构建序 f64 黄金的 0.1 点对点门仅适用无/浅接触场景(风场景不受影响)。
2. **依据**:纯 f64 反例(同 contacts 仅换约束扫序,tick1 sub0=0.2877→64tick=1.2844,与 GPU 残余逐检查点同值)证明构建序 vs 色桶序在接触-滑动域的分歧是**扫序固有**而非 f32/实现缺陷;f32 同序因素 ≤4.4e-2;1-ULP 扰动 64tick 有界 0.171(非主因)。
3. **pack 槽位错位 bug 修复确认**:halfExtents.xyz 槽 13..15→16..18、槽 19=radius(判别式槽),ABI 逐槽单测锁;通道复活(minSurfDist=5.1e-10)。**该 bug 为主线程布线时引入、定位批抓出修复——如实记录。**
4. **同族两项处置**:①串行核静默忽略 obstacles=合同参照语义(障碍归并行核),登记不修;②WGSL 判别式口径注释已对齐+sync(主线程完成,checksum 18 过)。

## 效力边界

- 本裁定不改变 C8 行主链(材质/灯光数学)任何门;接触场景新合同仅约束 cloth parallel GPU 障碍通道自身。
- 逐子步对拍方法论(8×substeps=1+dt/8 保真分解)沉淀为接触场景标准调试工具(探针已入库 scripts/c8ObstacleSubstepProbe.ts)。
- 深接触场景若需对 f64 构建序黄金的点对点门,须先统一扫序(独立批)。
