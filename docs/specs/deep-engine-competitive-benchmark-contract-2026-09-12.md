# Deep Engine 竞品基准与“90%”声明合同

日期：2026-09-12。状态：已冻结 v1 合同；尚未产生任何竞品胜出或 90% 达标结论。

## 1. 为什么必须拆成两条证据链

浏览器版 Deep WebGPU 与 Three.js、Babylon.js 可以在同一浏览器、相同资源和相同画质设置下串行对照。Unity、UE5、Godot 的成熟产品是原生运行时与完整编辑器，不能把浏览器宿主成本、不同渲染特性或删减后的示例混成一个 FPS 数字。因此：

- “超过 Three/Babylon”使用逐场景的同环境成对性能、画质、资源和可靠性证据；Browser WebGPU 与 native wgpu 分轨报告。
- “接近 Unity/UE5/Godot 90%”分别冻结三份能力矩阵。未实现和未验证一律计 0，不能测完后删分母。
- 性能、画质和能力各有硬门槛。总分不能抵消关键可靠性、用户项目兼容或某个薄弱领域。

可执行合同位于 `packages/deep-engine/src/benchmarkContract.ts`，当前测试覆盖缺轮次、篡改 fixture、非交替顺序、缺失指标、无证据得分和修改权重分母的失败路径。

## 2. Three/Babylon 成对基准

每个 case 在测量前冻结以下 SHA-256：

1. 环境：操作系统、CPU/GPU、驱动、浏览器或 native runtime、供电模式、物理分辨率和构建身份。
2. fixture：资产、相机轨迹、交互脚本、随机种子、可见性与动态状态。
3. settings：光照、阴影、反射、GI、材质、透明、后处理、抗锯齿、LOD 和纹理质量。

至少执行五组成对轮次，Deep/参考引擎轮流先运行。每轮保存 CPU/GPU P95、帧时间 P99、输入延迟、冷启动、设备恢复、主机/GPU 峰值资源和冻结画面的感知相似度。合同以各轮中位数判定；任一指纹、指标或轮次缺失都使结果无效。

关键 case 不得退化超过 5%。被指定为胜出负载的瓶颈指标还必须改善至少 15%，且画质达到冻结下限。当前只实现证据结构和失败关闭逻辑；显著性区间、原始 GPU timestamp、像素/视频采集仍属于基准 runner 待办。

## 3. Unity、UE5、Godot 三份能力矩阵

每个参考引擎单独冻结版本、平台、渲染器、功能项、权重和证据要求。领域权重为：渲染 20、大场景 15、材质与特效 10、动画 10、仿真/媒体/XR 10、编辑器工作流 10、GUI/图表/文字 10、脚本/插件/API 5、原生发布 5、诊断与可靠性 5。

每个能力项只有 `passed / failed / unverified`，`passed` 必须带可追溯证据 ID。达标条件同时满足：

- 总分至少 90/100；
- 每个领域至少 80%；
- 关键项全部通过；
- 领域权重与冻结分母完全一致；
- 对应性能门槛达到参考引擎同画质吞吐的 90%，并通过启动、输入、资源和稳定性预算。

这一分数表示冻结矩阵的覆盖率，不表示复制参考引擎的全部生态、内容库或平台规模。三份矩阵必须分别发布结果，不能取最好的一份代替另外两份。

## 4. 当前结论

目前已有的 RenderPacket CPU 数据、固定 WebGPU Lab 画面和原生 64×64 smoke 都不能进入竞品胜出声明。它们是内核正确性证据。只有完成真实场景、画质冻结、竞品 runner、原始样本留存和独立复跑后，才开始发布逐 case 结果。

四天节点交付可运行增量和证据工具，不改写以上分母，也不提前生成“完成度 90%”。
