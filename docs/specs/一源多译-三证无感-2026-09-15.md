# 一源多译 · 三证无感

**Deep Studio 发布体系的革命性方案:从"打包"到"编译",从"同构"到"证明"**

日期:2026-09-15
定位:在既有已批准路线(零 WebView、Runtime Package、golden 契约)之上,给出终局形态与演进路径。
关系:本文是 [三端无感发布实现交接](三端无感发布实现交接-2026-09-15.md) 的战略层;实现任务仍以 `deep-engine-next-development-tasks-2026-09-15.md`(D01–D28)为准。

---

## 0. 一句话

**把"发布"升级为"编译",把"一致"升级为"可证明等价";一份语义源,编译出每个端最优的产物,再由三层证明机械地保证它们等价。**

现有路线回答的是"怎么让一个包在三端跑";本方案回答的是"**怎么让'三端一致'这件事从感觉变成证据,同时每端都拿到自己的最优解**"。

---

## 1. 它改变了三个问题的答案

| 问题 | 行业常规答案 | 本方案答案 |
|---|---|---|
| 一致性怎么保证? | 同构执行(同一份代码/包到处跑,或靠 webview/wasm 兜底) | **编译 + 证明**:同语义多目标编译,IR 级 bit-exact + 像素级容差 + 行为级回放 |
| 性能从哪来? | 优化运行时(换更快 VM、加缓存) | **消灭运行时该做的事**:布局/样式/shaping/图表/行为全部在编译期固化,热路径只剩 IR 遍历 + GPU 提交 |
| 生态与性能怎么兼得? | 取舍(要么 webview 保生态,要么自绘失生态) | **分层归属 + 逐端特化**:生态只活在编辑器;每端由同一语义编译出各自最优形态 |

**战略推论(真正的革命性所在)**:支持一个新平台从"产品工程"降级为"编译器工程"——新增一个端 = **新增一个 backend lowering + 一套证明套件**,而不是重做一个产品。手机、车机、嵌入式大屏、甚至未来的终端形态,都只是新 target。

## 3. 三个亮点设计

### 3.1 编辑期三端 live 预览:把"预检"变成"常态"

现在的预检是发布时的一次性检查(弹窗告知 blocked/degraded)。本方案把它前移成**编辑期的常态化能力**:

- 编辑器里并排/叠加显示 **web / webview / native 三个 runtime 的实时预览**,来自同一语义文档的增量重编译;
- 差异自动标注为**能力项**而不是 bug(某些差异是设计的:如字体替换策略、纹理格式);
- 发布时不再需要预检弹窗——因为在编辑期已经持续跑了几百帧。

**底层机制**:三端 runtime 订阅同一语义文档的增量(revision),各自增量重编译、增量重渲染。这正是"无感"最强的证明:**作者在写的时候就能看见三端的样子**。

### 3.2 行为编译 + 确定性回放:交互也可证明

- 交互不是脚本,是**状态机图 + 数据绑定**(Rive 范式),编译进 IR:节点、状态、迁移、绑定全是数据;
- 每个发布产物附带**回放契约**:事件序列(pointer/key/IME)+ 数据 revision 序列 → 期望状态轨迹;
- CI 在三端重放同一序列,比较**状态轨迹 + display list hash + 画面**;
- 确定性依赖由 runtime 注入:确定性时钟、固定 seed(项目 `sim:` 数据已是这个范式)、受控网络替身。

这把测试从"人工点点点"和"像素感觉"升级为**机械证明**,并且把"无感"从静态画面扩展到交互行为。

### 3.3 语义级热同步:发布后不是部署,是同步

- 内容寻址 + 对象级 delta + 原子切换:改一个图表数值,只有该对象的编译单元变化;
- 三端同一机制:web 增量拉取、webview 增量拉取、native 增量应用(LKG 事务已有,扩展为 delta);
- 作者的体验从"重新发布/重新部署"变成"**改完即同步**",像协作工具而不是构建流水线。

## 4. 每一件既有资产如何升级(没有一件浪费)

| 既有资产 | 在方案中的新角色 |
|---|---|
| `DeepRuntimePackage` + fail-closed 校验 | 升级为**编译产物**(不再是"唯一字节",而是"某 target 的编译结果 + 语义 hash") |
| `packagePurity` 禁列 | 升级为**编译器后端的准入纪律**(禁 wasm/js 的第二含义:后端只能原生 lowering) |
| golden fixtures / 支持矩阵三态 | 升级为**证一(IR 证)的执行器**:矩阵定义"什么算合法",golden 证明"两端算得一样" |
| `prewarmPlan` / `Executor` | 升级为**编译期资源规划**:预热计划变成编译产物的一部分 |
| LKG / 事务 / present 后提交 | 升级为**热同步的原子性保证** |
| 对象级 SHA-256 身份(geometry/material/instance) | 升级为**全链路内容寻址**的基础(资产→IR→帧输入) |
| `hit index` / 事件白名单命令 | 升级为**行为证的事件通道**(回放契约的执行接口) |
| `ChartIR` / `EChartsOptionCompat` | 升级为**图表后端无关性**的证明样本(同一 option,两端 ChartIR 必须 bit-exact) |
| `editorOverlayPass`(编辑器覆盖层已用 deep-engine 自绘) | 升级为"**编辑所见 = 发布所见**"的同源起点,继续扩大自绘范围 |
| HostCapabilities / DataConnection 合同 | 升级为**跨端能力单一权威**:编译期用它做特化决策,运行期用它做数据接入 |
| 4A 三档(A/B/C) | 升级为**逐端特化策略**:A 档多端原生,B 档适配器编译,C 档 webview 兼容层 |

## 5. 落地路径(三阶段,对齐 D01–D28)

### P1 同包三端跑 + 证一(现在 ~ M1/M2)
- 完成交接文档的三个跨距(产真包 / web loader / DashboardDocument v1);
- **新增:IR 证先行**——三端对同一 fixture 计算 display list,逐字节 hash 对比。这是最便宜且最强的证明(CPU 侧无浮点歧义),应当在像素对照之前建立;
- 出口:同一包三端跑通,IR 证在 CI 常绿。

### P2 多目标特化 + 编辑期预览 + 行为证(M2 ~ M3)
- 引入 per-target lowering(纹理格式、字体表示、shader 变体按端特化;特化只允许**可逆优化**);
- 编辑期三端 live 预览(先"静态快照对比",再"live 增量");
- 行为回放契约(状态机 IR + 事件序列重放)进入 CI;
- 出口:三端特化产物等价性由三证共同保证;作者可在编辑期看到三端差异。

### P3 语义级热同步 + 全量证明门禁(M4 之后)
- 对象级 delta 包 + 三端增量应用;
- 三证(含语义证)全量进发布门禁:任一端证明失败即阻断发布;
- 出口:改一处、三端秒同步、证明全绿。

## 6. 风险与诚实

| 风险 | 缓解 |
|---|---|
| 多目标特化削弱"同一份字节"的简单性 | 特化只允许可逆 pass;语义 hash 是主键,特化产物必须能由语义 hash + target 标识完全重建 |
| IR bit-exact 在 GPU 侧不可达 | 分层:IR 层(CPU)严格 bit-exact;像素层用容差 + 差异分类 + 阈值冻结,不追求全局 bit-exact |
| 编辑期 live 预览成本高 | 先做静态快照对比,再逐步 live;native 预览可先用离线渲染帧序列 |
| 行为回放的确定性依赖(时钟/随机/网络) | runtime 强制注入确定性时钟与 seed(项目已有 sim: 范式);网络用替身 |
| 特化导致"某端行为漂移但不被察觉" | 证一/证三覆盖行为与结构;漂移必须落在登记的能力项内,否则视为缺陷 |
| 新平台接入的 compiler 工程量被低估 | 每个新 target 必须自带证明套件才算完成;"能跑"不等于"已接入" |

**明确的非目标**:本方案不追求"任意 web 页面原生化"(那是 Blitz/C 档的事);不追求 GPU 像素级 bit-exact;不追求让编辑器本身跑在原生(编辑在 web/Studio,运行在任意端)。

## 8. 一页总结(可单独转发)

> **一源多译·三证无感**
> 一份语义(编辑器保存的内容文档)→ 多层 IR 编译(结构→布局→绘制→GPU)→ 多端特化产物(web/webview/native 各自最优)
> 一致性不靠同构执行,靠三张证明:**IR 逐字节 hash**、**像素容差对照**、**行为确定性回放**。
> 生态留在编辑器,性能来自"把该在编译期做的事全部做完",热路径只剩 IR 遍历 + GPU 提交。
> 收益:每端最优 + 一致性可证 + **新增平台 = 新增编译器后端**,而不是重做一个产品。
