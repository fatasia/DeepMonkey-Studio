# 引擎差距对照:Bevy ECS / Godot 2D / UE 光追·Lumen·Nanite·VSM·MegaLights·物理·超分·Play·编辑器(2026-10-03)

> 口径:延续 [deep-engine-gap-vs-unity-ue-2026-09-27](deep-engine-gap-vs-unity-ue-2026-09-27.md) 的配对红线——
> **vs Unity/UE 零基准禁定量**(只能定性+引擎内绝对数字),vs three/Babylon 有配对基准可定量。
> 每项给:现状(带代码证据)→ 差距等级(已达标 / 路线重叠 / 部分 / 缺失)→ 可执行路线(自研/开源内置口径,禁商业运行依赖)→ 建议。

## 1. Bevy:ECS 并行调度内核

- **现状**:Deep 不是 ECS。对象图是 three 兼容场景树 + 命令层(批 0-5 切片、submit 2.2ms)+ `FrameScheduler`/`RenderGraphBuilder`/`executeParallelGroups`(renderGraphScheduler.ts,并行组调度)+ native 侧 cargo 多线程(711 测试)。
- **差距等级:部分(调度有、ECS 无)**。我们有"任务图并行"(渲染图并行组、并行布料 XPBD 色桶、T24 订阅 328k msg/s),但没有 Bevy 式**数据导向内核**:组件线性存储、按组件位自动求并行序、change-detection、确定性系统调度。
- **可执行路线**:不必整体换 ECS(生态绑定 three 兼容面是产品优势)。可选增量:把 native 物理/仿真步进的"系统表"改为**组件存储 + 显式并行批**(复用 cloth XPBD 的色桶并行先例);TS 侧已有 `executeParallelGroups` 可承载系统级 DAG。**建议:暂缓整体 ECS;在仿真域(物理/机构/粒子)引入系统批调度,收益可测(帧内 CPU 并行度)。**
- 对标证据:Bevy 调度器为第三方引擎标杆;零基准,不做定量。

## 2. Godot:2D 全家桶

- **现状**:无 2D 引擎内核。产品有"二维工作区/看板"(dashboard 图表、设备布局底图 Polygon、DashboardMapPreview 制图),那是**应用层 2D(SVG/Canvas)**,不是 Godot 级 2D(2D 渲染器+2D 物理光源粒子+TileMap+2D 骨骼动画+2D 编辑器)。
- **差距等级:缺失(域外)**。工业数字孪生主场景是 3D+看板,2D 引擎内核不在产品域。
- **建议:不做。** 看板诉求已有 dashboard 体系覆盖;若未来出现"厂区平面图实时联动"需求,用现有 2D 看板 + 3D 双向投影(已有雏形)即可,不引入 2D 物理内核。

## 3. UE:硬件光追

- **现状**:WebGPU 平台**无硬件 RT API**(平台限制,非自研缺口);native(Rust/wgpu)侧 wgpu 同样未暴露 RT。现有:SSR 物理化(C11,split-sum 同源)、探针 GI、CPU/WebGPU 计算 shader **路径追踪**(T10/C8,多 Worker 并行、PNG+sha256 回执)。
- **差距等级:缺失(受平台约束)**。路径追踪是离线出图口径,非实时 HW RT。
- **建议:维持"计算着色器光追"路线**(平台可达性最高);native 侧等 wgpu RT 特性落定再评估。禁把 DXR 设为运行依赖。

## 4. UE:Lumen 全动态 GI

- **现状**:探针 GI 体积(probeClipmap,16/32 方向档,G3 门控)+ F5 镜面方向可见度门(L1 SH,白炉 gate≡1 逐位负控)+ C11 SSR。**无距离场(DF/GS)GI、无动态天光/Lumen 级屏幕空间+硬件混合。**
- **差距等级:部分(探针 GI 在、Lumen 级动态性缺)**。
- **可执行路线**:①补 **2D 距离场遮蔽**(SDF 已有:sdfCollisionQuery/A2 SDF 资产线——复用场景 SDF 做静态遮蔽 AO/GI,开源口径);②动态天光(大气天空已有 atmosphereSky)接 GI 体积的时域更新。**建议:A2 SDF 线完成后评估"静态遮蔽 + 动态探针"混合 GI,这是 WebGPU 平台最接近 Lumen 观感的可达路线。**

## 5. UE:Nanite 虚拟化微多边形

- **现状**:路线重叠——T26 HLOD(10k→242 代理,97.6% 削减)、G1 微多边形(meshlet 剪影 0px、draw 10.86×)、T11 冷管线 -74%、簇级决策引擎(G3)。
- **差距等级:路线重叠(方向一致,规模差一个量级)**。Nanite=逐三角形 LOD+流式虚拟化+可见性驱动的软件光栅;我们是**簇/meshlet 级 LOD+代理**,没有逐三角形虚拟化与流式页调度。
- **可执行路线**:meshlet 批次已是掩码/描边/剔除的执行单元(G1/T26),下一步把 **meshlet LOD 贴到 F3 虚拟纹理同一套页调度**(虚拟纹理管线已列剩余大头),即可获得"类 Nanite 的流式细分"。**建议:列为长线;短期 HLOD 已覆盖工业装配规模(10k 对象)。**

## 6. UE:VSM 虚拟阴影

- **现状**:CSM 级联(T04 分页阴影+级联修复,manifest `shadow-cascades`)+ 局部聚光阴影(`shadow-local`/`local-shadow-abi-16`)+ 接触阴影(C10)。
- **差距等级:部分(级联成熟、无全场景虚拟阴影图)**。VSM 收益=任意规模场景单pass全分辨率阴影;我们 4 级联+分页在工业装配规模已达标(j3 shadow-visibility 门 85 点零差异)。
- **建议:暂缓。** VSM 的缓存失效成本在动态场景(数字孪生设备常动)会吃掉收益;按需再评估。

## 7. UE:MegaLights 万灯

- **现状**:Forward+ 簇光源(clusterLighting/ies/ltc)+ **矩形/带纹理面积光上限 8 盏**(`DEEP_AREA_LIGHT_MAX=8`)+ 主太阳光高级 lobe 直射。T19 的"万人代理 146µs"是**代理对象**不是光源。
- **差距等级:缺失(万级动态灯光随机采样)**。
- **可执行路线**:WebGPU 可达路线 = compute 的**灯光随机采样着色**(ReSTIR 简化版:重要性采样 + 时空复用),开源文献口径自研。**建议:暂缓;先把 8 盏面积光上限按需求扩到 32(数据结构常数改动,LUT 常量已参数化)再观察。**

## 8. 物理广度

- **现状**:T17 核心完成(机构跨端 ≤1.354mm、Rapier 0.35、CAD→collider 端到端)、N10 EPA 穿透、T20 布料 XPBD/流体烟、软体投影;FixedStepClock 60Hz 确定性。
- **差距(底稿 3.2)**:①物理可视化调试器(录制/回放/跨端位姿比对)——**部分**(rapierPhysicsDebugView 有运行可视化,无录制回放);②认证级 MBS——缺失(按需);③通用 GPU 物理——缺失(T20 是有边界切片)。
- **建议:优先补 ①**(复用 T17 黄金案例数据,工业虚拟调试可信度刚需,自研口径)。

## 9. 超分 / 神经图形

- **现状**:T07 自有时域重建(残影 2.93%)、T32 ONNX WebGPU EP 实测;DLSS/FSR/XeSS 未集成;神经升尺度缺失(底稿 3.1:开源 FSR 固定版本可评估,DLSS 闭源不纳入运行依赖)。
- **差距等级:部分(自有 TSR 在、厂商生态与神经图形缺)**。
- **建议:按底稿口径做 **AMD FSR 开源实现固定版本评估**(内置交付、不引运行依赖);神经图形继续暂缓(T32 的 ONNX EP 已为将来留了执行通道)。

## 10. UE:Play 迭代速度

- **现状**:Web 形态天然热刷新(Vite HMR + 场景快照 + T30 播放 + T27 事务 + 离线检查点);桌面(Tauri)形态的 PIE 级迭代(秒进播放、状态热恢复)未专项测量。
- **差距等级:部分(Web 侧天然优势、桌面未量化)**。
- **建议:补一个"编辑→播放恢复"秒表门(gate 脚本量 play 进入时间与场景恢复时间),作为可证伪指标;Web 形态大概率已优于 UE PIE 冷启动,先量再优化。**

## 11. UE/Unity:全套编辑器

- **现状**:场景对象/材质(含高级材质 lobe 作者入口,P1-1 复核完成)/行为图(G2)/参数化建模工作台(OpenCascade WASM)/脚本(Monaco)/数据绑定/发布流水线/机器人 FK-IK/互锁;T25 面板 3 轮视觉闭环。
- **底稿 3.7 六项缺口**是工作流深度(资产商店级生态、协作、版本化场景差异等),不是"有没有编辑器"。
- **建议:维持自研渐进路线;协作与场景差异(D3)已在 P3 对标批次。**

## 12. 总结表

| 维度 | 等级 | 最短可达路线 | 建议 |
|---|---|---|---|
| Bevy ECS 内核 | 部分 | 仿真域系统批调度(复用 executeParallelGroups/色桶先例) | 暂缓整体 ECS |
| Godot 2D | 缺失(域外) | — | 不做 |
| UE 硬件光追 | 缺失(平台限) | 计算着色器光追(已有) | 维持现路线 |
| Lumen GI | 部分 | 静态 SDF 遮蔽+动态探针(A2 复用) | A2 完成后评估 |
| Nanite | 路线重叠 | meshlet LOD + F3 页调度 | 长线 |
| VSM | 部分 | — | 暂缓 |
| MegaLights | 缺失 | 面积光 8→32 → ReSTIR 简化 | 先扩 32,再观察 |
| 物理广度 | 部分 | 物理调试器录制回放(复用 T17 数据) | **优先补** |
| 超分/神经 | 部分 | FSR 开源固定版本评估 | 短线可做 |
| Play 迭代 | 部分 | 秒表门先量化 Web/桌面 | 先量再优 |
| 全套编辑器 | 部分 | 3.7 六项渐进(协作/差异在 P3) | 维持现路线 |

**横切纪律**:所有"补"一律自研/开源内置、固定版本、可复现构建(工作区硬门槛);vs UE/Unity 不做无基准定量,补一个维度先立**自家绝对指标门**(帧时/首帧/RMSE),再谈对标。
