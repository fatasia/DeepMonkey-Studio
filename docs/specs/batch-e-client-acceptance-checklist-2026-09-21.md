# 批次 E 双客户端验收核对清单（2026-09-21，固化历史失败与验收语义）

> 波次6 批次 E 的执行规格。来源：交接文档/总账历史失败记录 + 用户完整验收指令
> （"所有新增功能从页面发布打包 Deep Native、Three WebView 等客户端无问题；客户端与
> Web 端效果一致或更好；鼠标键盘操作交互相同；性能优化到极致"）。

## A. 历史失败重放（每一项都必须在本轮验收中显式重验并留证）

| # | 历史失败 | 重验方法 | 通过判据 |
|---|---|---|---|
| A1 | 缺 EXE（WebView 曾只出 JSON/assets） | 解压发布产物→核对 EXE 存在→无参启动 | EXE 直接启动出完整页面 |
| A2 | 长时间无反馈 | 启动计时（打点）| 启动超时有明确进度/错误反馈，无 30s 静默 |
| A3 | 云 Worker/token 误依赖 | 断网（或停 API）启动+操作 | 离线功能完整，无网络请求报错冒泡 |
| A4 | 悬空 dashboard 引用 | 打开含 dashboard 的多页面项目 | 页面路由/跳转无悬空引用报错 |
| A5 | 多余控制台窗口 | 启动 EXE 观察进程窗口 | 无附属控制台 |
| A6 | 重复创建窗口崩溃/双标题栏 | 重复打开/关闭场景 | 稳定、单标题栏 |
| A7 | canvas 溢出裁切 | 980×700 与 1200×800 两窗+连续缩放 | 主体/标签/工具栏完整 |
| A8 | 页面/脚本依赖诊断缺失 | 制造缺失依赖场景 | 精确缺失原因提示（非静默白屏） |

## B. 完整功能覆盖（真实多页面项目逐项操作）

3D（旋转/缩放/平移、拾取/选择、属性、显隐、剖切、测量、相机）、Dashboard（图表事件、
数据绑定、脚本）、路由/导航、环境/灯光/后处理、动画、物理——**每项记录操作步骤+截图**。

## C. 双端一致性

同场景/相机/分辨率/DPR/质量档：Deep Native vs Three WebView vs Web 端——SSIM（GI on/off）
+ 交互响应一致性 + 功能集一致；Web 端**不得**靠降画质证明性能。

## D. 性能极致证据

复用 `perf/latencyStats.ts` 统一口径：CPU/GPU P50/P95/P99、长帧计数（阈值 100ms）、
冷/热启动、包体/打包时间、内存/显存——脚本化采集存 JSON。
