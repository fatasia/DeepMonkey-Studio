# World API v1：确定性、可验证的 AI 世界接口（2026-10-03）

> 来源：`upgrade-plan-ai-native-world-20261003.md` §1.3（缺失 `reset/step/observe` 世界接口、确定性物理快照/恢复）与阶段 2 第 1 条。
> 范围决策（用户）：只做 **MCP / HTTP / JS-TS SDK** 三路暴露；**不做 Python SDK / 客户端 / Gymnasium**。
> 接口：`reset(seed, scene)` · `step(action, dt)` · `observe(channels, sensors)` · `snapshot()` · `restore(snapshot)`（+ `close`）。

### 1.2 看起来相关但**不是**可复用物

- `ai/simulationHypothesis*` / `simulationStudy*` / `plant-lite-simulation`：针对 `t23-conveyor-sensor-agv` 等**注册校准场景的 DES 指标假设**，场景白名单固定，与"任意场景的物理世界步进"不同域。World API 不改它们。
- `ProvenanceLedgerStore`：节点族是 假设→内核运行→判定→报告（+ 本体行动链），文档级整文件存储，不是通用 step 轨迹存储。世界轨迹先落**审计链 + traceHash 链**（§4.3），接入账本留作后续。
- `SceneBehaviorScheduler`：行为脚本时钟（毫秒、`timeScale`、丢帧），语义不是整数 tick；`fog-fixedstep-wiring-20261003.md` 已记录"跨环统一 tick 属 World API `step()` 前置，单独立项"——本任务内 `step()` 以整数 tick 为唯一时间轴，行为脚本接入 tick 留作后续。
- `apps/web/.../rapierPhysicsCollisionEvents.ts`：句柄→归属解析是纯函数但在 `apps/web`，`packages/*` 不能反向依赖应用；运行时内重写约 15 行等价逻辑（`recordContact`）。
- `cloud-render-worker` / `deep-engine-native`：批量渲染与 Rust 物理对拍；与本任务无关（批量 rollout 已移出范围）。

### 1.3 真实缺口

1. 没有 `reset/step/observe/snapshot/restore` 世界接口，也没有 WorldState/Action/Observation/Snapshot 合同。
2. Rapier `takeSnapshot/restoreSnapshot` 全仓**零使用**，快照→恢复→续跑的确定性从未被证明（本任务补证据）。
3. Viewer 的物理宿主绑 three 对象与 DOM，无法在 Node 无头运行；缺一个"只依赖 SceneSnapshot"的无头世界。
4. 无会话资源治理（并发/内存/空闲回收），无世界归属隔离。
5. 无 JS/TS SDK 封装。

### 1.4 放哪里：是否新建 package

评估三个落点：

| 落点 | 结论 |
|---|---|
| `scene-sdk` | ✗ 浏览器 Worker/Tauri 也会依赖它；塞进 Rapier（~2 MB 内嵌 wasm）与 `node:crypto` 会污染其体积与可移植性 |
| `studio-core` | ✗ 同上，且职责是应用文档，不是物理 |
| `apps/api` 内 | ✗ API 之外的脚本（评测、CI）要无头跑世界也得起 API，运行时无法被其它 Node 进程直接复用 |
| **新建 `packages/world-runtime`** | ✓ **仅此一个新包**：源码 ~870 行（含 4 个小模块），依赖 = contracts + scene-sdk + 已锁定的 rapier 0.19.3（**零新下载、零新增版本**）；Node 无头，不碰 DOM/WebGPU |

### 1.5 为什么不依赖 `deep-engine`

`@bim-studio/deep-engine/physics` 的 barrel 同时导出 WGSL/GPU 派发等模块，仅为一个整数 tick 计数器引入它会把 GPU 代码拖进无头运行时与包依赖图。`FixedStepClock.advanceTicks(n)` 等价于整数加法；单一事实源改为 `contracts` 的 `WORLD_FIXED_HZ = 60`（与 `PhysicsWorldHost` 的 60Hz 同值）。

## 2. 设计

### 2.1 确定性约定

- 时间只用**整数 tick**，固定 60Hz。`step` 接受 `dt`（秒）或 `ticks`（整数）**二选一**；`dt × 60` 必须落在整数 ±1e-6，否则抛 `WorldApiContractError`（`dt` 字段路径 + "必须是 1/60 s 的正整数倍"），**绝不静默取整**。
- action 在本次 step 窗口**第一个 tick 之前**原子生效：先整体校验（影子表追踪窗口内的创建/删除/刚体类型变化），任何一项非法 → 整条拒绝，世界状态与 tick 均不变。顺序固定：命令 → 物理动作 → 事件，各自按数组顺序。
- 速度设定值（`set-linear-velocity`）持续到被改写；冲量（`apply-impulse`）一次性。
- `seed`（uint32）驱动内置 `mulberry32`（纯 32 位整数运算，状态即 uint32、入快照）。v1 中 seed 的可观测作用是 `options.initialPositionJitter`（动态刚体初始位置 ±jitter，仅用于让 seed 对 reset 结果可观测，**不是域随机化框架**，域随机化已移出范围）；Rapier 求解本身无随机性，`jitter=0` 时不同 seed 物理结果相同（单测钉死）。若认为该选项也超出范围，可整体删除（contracts + 运行时 + 对应单测，影响面小）。
- `stateHash` = sha256(canonical 对象表 + tick + seed + rng ‖ 全部刚体位姿/速度的 **float64 原始位**)：位级一致 ⇔ 哈希一致，`-0` 与 `0` 也区分。
- `traceHash` 链：`sha256(prev ‖ tickBefore ‖ ticks ‖ canonical(action) ‖ stateHash)`，初值 `sha256(sceneHash, seed)`。它记录"调用序列"，因此**调用拆分不同则链不同**（这是设计：链是审计，不是物理状态）；物理状态一致性由 `stateHash` 证明。

### 2.2 对象模型（无头世界没有网格）

- 来源：`SceneSnapshot.primitives`（box/sphere/cylinder/cone/capsule/torus/plane，基础尺寸与 `primitiveGeometry.ts` 同；torus/plane 取包围盒近似）+ `models`（**必须**声明 `physics.collider.kind = "primitive"` 才能挂刚体；否则 `invalid-scene` fail-closed，不猜包围盒）。
- 径向非均匀缩放取径向最大值（保守包围近似；Viewer 一律用世界包围盒 cuboid）。`type = none` 的对象只有位姿，不参与物理。
- 固定地面（`options.ground`，默认 true）与 Viewer 一致：顶面 y=0、摩擦 0.9；接触里 id 为 `@ground`（保留前缀 `@`，物体 id 不得以 `@` 开头）。
- 场景命令支持面：`object.create-primitive`（创建后 `type=none`，用 `set-body` 赋刚体）、`object.delete-primitive`、`object.set-visibility`、`object.set-transform`（位置/欧拉角弧度 XYZ；dynamic 瞬移并清零速度、kinematic 走 `setNextKinematic*`；**已有刚体不支持改缩放**）。`material/selection/camera/lighting/environment/animation/data/component/unity.*` 合法但对物理无效果 → `status: "noop"` 如实标注；`object.set-parent`、scene/mesh 级目标、跨 sceneId → 拒绝。

### 2.3 快照

`WorldSnapshot` = seed、tick、sceneId、sceneHash（物理相关语义投影的 sha256）、traceHash、rngState、重力、对象注册表（含 Rapier 句柄）、**Rapier `takeSnapshot()` 字节（base64 + byteLength + sha256）**、`snapshotHash`（其余全部字段的 sha256）。`restore` 先校验形状 → 字节长度/sha256 → `snapshotHash` → 解码 → **句柄与世界内真实刚体集合逐一比对**（Rapier 的 `getRigidBody` 对无效句柄也返回包装对象，必须比对集合，已有单测覆盖"自洽哈希但指向不存在刚体"的伪造快照）。

### 2.4 观测

`WorldObservation{tick, timeSeconds, seed, stateHash, bodies?, contacts?, events?, truncated?, sensors?}`。

- `bodies`：位置、四元数、线/角速度、sleeping、可见性。
- `contacts`：**最近一次 step 调用**内逐 tick 的接触开始/结束对；`events`：同一事实的行为层视图（每个接收对象一条 `object.event`）+ 动作注入的 `business.event`。每次 step 上限 1024 条，超出置 `truncated`，不静默丢。
- `sensors`（**仅 schema 扩展点，不实现**）：`observe` 只实现位姿 + 接触 + 事件 + 时间。`camera-rgb/depth/normal/segmentation/lidar` 种类仅作为合同里的保留枚举，请求时返回 `{status:"unsupported", reason:"not-implemented"}`，未知种类被合同拒绝；没有任何采样代码。

### 3.2 接口表

| 操作 | MCP 工具（`tools/call`，参数 `{projectId, input}`） | HTTP（`/api/projects/:projectId/worlds…`） | JS/TS SDK | 权限 |
|---|---|---|---|---|
| reset | `industrial.world.reset` `{seed, scene, options?}` | `POST /worlds` → 201 | `WorldClient.reset()` → `WorldHandle` | 非 viewer |
| step | `industrial.world.step` `{worldId, action?, dt｜ticks}` | `POST /worlds/:id/step` | `handle.step()` | 非 viewer |
| observe | `industrial.world.observe` `{worldId, channels?, sensors?}`（只读注解） | `POST /worlds/:id/observe` | `handle.observe()` | viewer 可 |
| snapshot | `industrial.world.snapshot` `{worldId}`（只读注解） | `POST /worlds/:id/snapshot` | `handle.snapshot()` | viewer 可 |
| restore | `industrial.world.restore` `{snapshot, worldId?}` | `POST /worlds/restore` | `handle.restore()` / `client.restore()` | 非 viewer |
| close | `industrial.world.close` `{worldId}` | `DELETE /worlds/:id` | `handle.close()` | 非 viewer |
| 列表 | — | `GET /worlds`（含当前配额） | `client.list()` / `client.attach(id)` | viewer 可 |

- MCP 与 HTTP **同一份能力实现**：schema 校验、权限（`isReadOnly` 规则：kind=query + `*.read`）、30 s 超时、证据信封都来自 `PluginRegistry`；HTTP 路由只做鉴权（项目存在 404 → 项目访问权 403 → viewer 写 403）与参数搬运。
- 世界归属主体 = `项目 + 用户 id`：MCP 传 `username:id`、通用能力路由/AI 网关传纯 `id`，`normalizeWorldPrincipal` 统一取最后一个冒号之后的 id，**同一用户经 MCP 创建的世界可由 HTTP 继续驱动**（单测）；别人拿到 worldId 也与"不存在"一视同仁（不泄露存在性）。
- HTTP 状态码：非整倍 dt/非法动作 → 422（body 为能力信封，`warnings[0]` 是可操作原因）；世界不存在/已回收 → 404；会话配额 → 429。
- 每个成功的 Capability 结果带 `evidence[0].fingerprint = stateHash`（`kind: "simulation"`），Agent 网关/调用方可直接引用。

### 3.3 确定性证据（均为单测，`packages/world-runtime/src/headlessWorld.test.ts`）

- **同 seed + 同 action 序列 → 逐位一致**：两次独立运行 48 次 step 的全部 observation 与 traceHash `toEqual`；且 stateHash 序列有 >10 个不同值（排除"恒定哈希"的假通过）。
- **变帧率调用拆分不影响结果**：同一 60 tick、同一 action（tick 0 与 12 注入）分别用 `[12,48]`、`60×1 tick`、`[1,2,3,6,7,11,13,17]`、`[6,6,20,28]` 推进，最终 `stateHash` 与 `bodies` 完全相等。
- **snapshot→restore 续跑 = 不中断运行**：tick 40 快照（含 JSON 往返），原世界继续 120 tick 与恢复世界继续 120 tick 的逐 step observation 全等，且最终 traceHash 相同；恢复后立即 `stateHash` 与快照时刻相同，再次快照的物理 sha256 与 `snapshotHash` 与原快照相同；恢复后执行"创建/摆位/赋刚体"变更与不中断运行一致。
- **失败路径**：非整倍 dt 报错且世界不前进；action 后项非法 → 前项不生效（stateHash 与 tick 不变）；篡改物理字节 / 对象表 / 伪造哈希一致但句柄无效的快照 → `snapshot-corrupt`。
- 端到端（`apps/api/src/worldApi.test.ts`）：MCP 全周期、HTTP 全周期、SDK→真实 `ServerClient`→路由闭环均验证"restore 后继续 = 不中断"。
- 诚实边界：证明的是**同一 Rapier wasm 构建、同一 Node/V8 上**的位级确定性；跨机器/跨 Node 版本未验证（Rapier compat 为非 SIMD wasm，理论上与宿主无关，但本任务没有第二台机器的证据；`sin/cos` 来自 V8）。若需跨平台逐位保证，后续评估 `rapier3d-deterministic-compat`。

### 3.4 资源上限（`WORLD_LIMITS` 与 `DEFAULT_WORLD_SESSION_LIMITS`）

| 项 | 默认值 | 说明 |
|---|---|---|
| 全服务并发世界数 | 8 | 创建期占坑，并发 create 不会同时通过检查而超额（单测） |
| 同一用户世界数（跨项目合计） | 4 | 按稳定用户 id 计（审查修复 #3）；原"项目内同主体"口径可被 principal 格式差异绕过 |
| 单世界内存估算上限 | 4 MiB | 估算 = 256 KiB + 4 KiB/物体；物体上限 256 → 最大 ≈1.3 MiB |
| 总内存预算 | 32 MiB | |
| 绝对存活期 | 60 min | 无论是否持续访问（审查修复 #3） |
| 空闲超时 | 10 min | `get` 刷新；每次 create 顺带回收 + 后台 `unref` 定时器；`onClose` 全量释放 |
| 单世界物体数 | 256 | 含 `type=none` 对象 |
| 单次 step | ≤600 tick（10 s）**且墙钟预算 1 s** | 正常 256 个动态刚体 × 600 tick ≈ 0.5 s；**病态重叠场景（256 个最大缩放物体互相重叠）实测 3.3–6.5 s，靠墙钟预算中止并作废世界**，不再靠"≤600 tick"兜底（审查修复 #1/#2）；单次 `step(1)` ≈ 2.5 ms |
| 世界累计 tick | 216 000（1 h 仿真） | 防无限续跑 |
| 单次 action | 64 命令 / 128 物理动作 / 32 事件 | 命令上限对齐 `SCENE_COMMAND_TRANSACTION_MAX_COMMANDS` |
| 每次 step 接触/事件 | 1 024 | 超出置 `truncated` |
| 快照物理字节 | 16 MiB（解码后） | 256 刚体实测 ≈ 400 KB（JSON ≈ 600 KB）；Capability `maxInputBytes` 24 MiB |

上限为代码常量（会话上限可经 `WorldSessionManager` 构造参数覆盖），**未做环境变量/管理端配置**——有真实调参需求时再加。

### 3.5 审计 / 溯源

- `reset/step/restore/close` 逐次写 `AuditLogRecord`（`action = world.<op>`，`method = WORLD`）；`step` 的 detail 含 `worldId、tickBefore/After、traceHash、stateHash、actionFingerprint、commandTypes`，**不含场景/动作原文**。MCP 路径本身没有通用审计，因此审计放在 Provider 内，MCP 与 HTTP 都覆盖；HTTP 路由直接调 `host.invoke`（不再套 `invokeReliableHttpCapability`），避免同一次调用双写审计。
- 审计存储失败不推翻 step，但以 `warnings` 如实暴露"证据不完整"（单测）。
- 只读的 `observe/snapshot` 不写审计（不改变世界状态）；被拒绝（blocked）的调用不落审计；`close` 未命中（不存在/非本人）不落审计。

### 3.7 范围外与遗留

**范围外**（2026-10-03 用户决策，不再作为待办跟踪）：传感器与 GT 通道实现、批量 rollout / 并行 env、数据集导出、域随机化、OpenUSD、科学数据格式与体渲染、3DGS、Python SDK / Gymnasium。World API v1 的 `observe` 因此只含 位姿 + 接触 + 事件 + 时间；`sensors` 只是合同里的占位枚举。

**v1 已知限制**（非阶段规划，仅如实记录）：

1. **同步执行**：单进程内同步步进，600 tick × 256 体 ≈ 0.5 s 阻塞事件循环，靠单次 step ≤600 tick 与物体数上限兜底。

### 4.2 与"建议修法"的分歧

- **#1/#7 HMAC 签名未采用**：快照要能跨进程/重启、跨用户分享（"客户端持有，restore 新建"是既定设计），HMAC 需要持久密钥管理并绑定 principal，反而破坏可移植性。改用"结构化深度校验"：合同层逐项校验对象表（数量、数值范围、id/句柄唯一、碰撞体尺寸），运行时在 Rapier 反序列化后核对 刚体数 = 碰撞体数 = 对象表数、无关节、每个碰撞体形状/摩擦/恢复/质量/分组、每个刚体类型/阻尼/CCD/附加迭代/重力缩放、位姿速度有限且量级健康，并用新建世界的默认值覆盖积分参数。这样快照里**不可能**夹带 reset 造不出来的重负载（e2b 的 2500/20000 碰撞体、关节、放大的碰撞体、伪造的求解迭代数均有用例）。残余风险：Rapier 内部不可校验的数据（窄相接触缓存、岛管理器）仍来自客户端；它们不能增加刚体/碰撞体/关节数量，最坏是让求解行为异常或触发 wasm 异常——前者由墙钟预算兜底，后者异常被当作 `snapshot-corrupt`/世界作废处理。如果产品后续要求"只允许 restore 本服务签发的快照"，再引入服务端密钥签名即可叠加在现有校验之上。
- **#2 不采用"await setImmediate 分段"或 worker thread**：分段让出事件循环不影响确定性，但需要把 `step` 改成异步并处理"让出期间别的调用操作同一世界"的重入；worker thread 则是此前明确列为后续的重构。当前选择：**墙钟预算（默认 1 s）+ tick 粒度中止 + 世界作废**。中止点之后世界状态是半推进的，所以必须作废而不是回滚（回滚需要每次 step 前先快照，对高频 `step(1)` 是 3~4 倍开销）；预算只在失败时介入，成功路径的逐位确定性不受墙钟影响（测试：带预算与不带预算的最终 `stateHash` 相同）。作废的世界拒绝一切操作，会话层在下一次访问时回收并提示用快照 restore 重建。
- **#5 "step 后非有限则整步回滚"改为"世界作废"**：同上，回滚代价高；有了范围上限后该情形已极难出现（极小质量 + 最大冲量才触发）。
- **#3 per-user 全局世界数 + 绝对 TTL 采用**；"AI 网关 principal"通过取最后一个冒号后的 id 统一，未改 `mcpCapabilityAdapter` 与通用路由（不属于本任务文件）。通用路由透传 `dryRun/expectedRevision` 的问题只在 world 能力内处理（拒绝 dryRun），`expectedRevision` 对 world 能力无意义、被忽略；通用路由对同一次调用另写一条审计（`capability.invoke.*`），与能力内审计并存，属已知重复，未改通用路由。

### 4.3 诚实说明与新增限制

- **viewer 实际上仍用不到 HTTP observe/snapshot**：世界归属是创建者，而 viewer 不能创建/restore 世界，因此 viewer 的 observe/snapshot 只会得到 404（测试按此断言）。修复 #6 解除的是"全局钩子拦截"这一层漂移，使权限模型与 SDK 契约一致；真正让 viewer 观看他人的世界需要"世界共享/只读授权"，属新功能，未做。
- **"每用户 4 个"是跨项目合计**；总池 8 个仍可被两个用户占满，这是共享池的固有限制，不是绕过。
- **新增合同上限**（`WORLD_LIMITS`）：`maxAbsPosition 1e4`、`minScale 0.01 / maxScale 20`、`maxAbsGravity 1e3`、`maxAbsVelocity 1e3`、`maxAbsImpulse 1e7`、`maxColliderExtent 500`、`minMass 1e-3 / maxMass 1e6`、`maxFriction 10`、`maxNameLength 128`、`maxEventData{Depth 8, Nodes 256, Bytes 4096}`、`maxStateMagnitude 1e9`（restore 体检与 step 后体检）。
- **作废世界的语义**：一次 step 若因超时中止，tick 已推进一部分，世界被标记作废，后续 `step/observe/snapshot` 一律报错，只能关闭；这与"校验类错误不改变世界"的原子性分开说明：原子性保证覆盖合同/动作校验，不覆盖"求解中途超时"。
- **Rapier 句柄不是整数**：它是把 (index, generation) 位编码进 f64 的不透明数（如 `5e-324`），合同据此只校验"有限且非负"。这是写快照对象表校验时发现的，之前注释里的"整数句柄"表述不准确。
- **重场景请分批 step**：病态重叠场景下 600 tick 可能超过 1 s 预算而被作废；调用方应把大步长拆成较小的 step（不影响结果，见 §3.3 的拆分不变性）。
