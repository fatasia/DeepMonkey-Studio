# DE26 高价值最小范围（2026-09-17）

主原则（2026-09-18 用户确认）：**效果提升先抓光照、材质和稳定性；Three/Babylon 直接对照工程实现，Unity/UE 借鉴系统设计和视觉目标。**

多灯、全局光照、模型受光及投影/接影按 [Unity 能力对齐方案](de26-unity-lighting-parity-2026-09-18.md) 增强 E01–E08 原卡，不另起灯光系统；E03/E05 提为 P0，E04/E08 提为 P1。功能、画质、运动稳定和运行成本分别验收，旧有基础证据不自动关闭增强要求。

DE26 保留独立验收分母。2026-09-18 用户要求继续主流程，并把引擎版图报告中的高收益项整合进 DE26：与当前收尾共用的实现和证据立即复用，其余按依赖排期，不把新增计划计入已完成。

最新取舍与定位见 [DE26 收益排序与 Reality Compiler 定位](de26-reality-compiler-priorities-2026-09-18.md)。本次不受研究稿的“只能比较渲染后端”等结论约束；按实际产品层、编译链和运行时分别判断。

2026-09-18 用户已确认：V1–V7 做扎实，V8 小而强，V9/V10/V11/V13 按真实场景补齐，V12 不做。V11 并入 C07 场景子切片，V13 并入 G06 场景子切片；只补现有参数化、预制件、标注和数据链的缺口。V8 使用现有命令与权限通道，不新建总线。既有工业点云/Tiles任务保持原范围，不夹带新增扫描对照/Splat方向。

## 对标边界

- 只保留 Three.js、Babylon.js、Unity。
- 删除 A05–A07 和 V01–V05，不再建设 Godot、Unreal Engine 原生基准，也不保留单独的项目级后验收卡。
- A01 的既有五平台证据仅作为历史输入；DE26 的判定分母只计算上述三引擎。
