# 实现规格模板（<批次>-<任务编号> <任务名>）

> 复制本模板到 `docs/specs/S<N>-<任务编号>-<slug>.md` 后填写。规格由白天模型（GLM-5.3/GPT-5.6）编写，夜间 GLM-5.3-Flash 照规格实现。规格外的发现只记录不展开。

## 0. 元信息

- 所属批次：S<x>（引用 `docs/platform-surpass-development-plan-2026-09-04.md` 对应节）
- 优先级/依赖：依赖哪些规格或既有能力
- 预估夜间时段：≤2h / ≤4h / 一整晚
- 触碰域：数据中心 / 2D / 3D / 脚本 / API / contracts

## 1. 目标与用户故事

一段话说明完成后用户能做什么（以完整任务流表述，不罗列功能点）。

## 2. 现状与复用

现有代码里已有什么（文件路径 + 关键类型/函数），本规格复用什么、扩展什么。**禁止重复造轮子：此处必须核对过既有实现。**

## 3. 合同设计

新增/修改的类型定义（字段、枚举、校验规则），持久化位置与迁移方式，API 路由与语义。类型先行的部分夜间直接照抄。

## 4. 实现要点

按文件列出要改/新增的内容与边界；标注哪些是规格内必须、哪些可选。超大文件（>500 行）只减不增；新文件目标 ≤300 行。

## 5. 测试计划

- 单元/组件测试：测什么、断言什么、放哪个文件。
- 浏览器验收：走什么流程、截什么图、记录什么数字。
- 需要跑的门禁命令清单。

## 6. 验收标准（可勾选）

- [ ] 具体、可执行的验收项，每项能被测试或浏览器证据证实
- [ ] 失败/边界路径覆盖（空态、错误、冲突、权限）

## 7. 风险与回滚

可能踩的坑（既有约束、兼容性、性能），以及出问题时的回滚点（提交粒度）。

## 8. 完成回填（夜间执行后）

- 实际改动文件 / 新增测试 / 门禁结果 / 遗留问题 → 汇总进总账对应节。
