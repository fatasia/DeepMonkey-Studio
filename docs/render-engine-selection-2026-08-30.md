# Three.js 单引擎路线决策（2026-08-30）

## 决策

产品正式放弃 Babylon.js，不建设双引擎，不保留候选适配器、基准依赖或未来晋级条件。主渲染路线固定为 Three.js：WebGL 2 继续承担生产兼容后端，WebGPU 按画质等价和发布门禁逐步晋级。Unity Release Player 只作为外部工业能力与性能对标，不进入 Web 主编辑器运行时。

## 原因

- 产品已有场景、BIM、拾取、标签、脚本、时间线、资源释放和故障恢复均建立在 Three.js 上。
- 双引擎会让材质、灯光、后处理、剖切、动画、物理同步和视觉回归形成永久双份维护面。
- 隔离夹具不能证明另一引擎在本项目真实工业负载中具有稳定、足以覆盖迁移成本的收益。
- 当前最高价值是补齐 Three WebGPU 渲染管线、2D/3D/脚本体验和工业工作流，而不是扩展底层引擎数量。

## 执行约束

1. 仓库不得新增 `@babylonjs/*` 依赖或 Babylon 运行时适配器。
2. `benchmark:render-engines` 只比较 Three WebGL/WebGPU 的同场景性能、画质和稳定性。
3. WebGPU 自动发布必须保留作者画质；后处理、真实轮廓等能力未等价时继续使用 WebGL。
4. 高级渲染优先采用 Three TSL、RenderPipeline、MRT、Compute 和节点后处理实现。
5. 物理与虚拟调试继续使用引擎中立的 Rapier 与确定性调试内核。

该决策用于减少无价值维护面。若未来更换主渲染引擎，必须作为新的产品级架构迁移重新立项，不能以“增加可选后端”的方式绕过评审。
