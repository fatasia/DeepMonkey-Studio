## 最小修复路径

1. 新增纯拖放意图模块，输入当前可见顺序、移动集合、目标类型 / ID、纵向比例、锁定集合；输出 before / inside / after 或带原因的拒绝。共享合同只描述意图，2D zIndex 与 3D 组织状态分别适配。
2. 2D 从可见顺序选取全部移动项并保留相对次序；跨组同时更新 groupId / groupName 与 zIndex，提交一个 states 命令。不要直接按 Ctrl 点击顺序搬运。目标在移动集合内、目标失效与无实际差异都不产生历史项。
3. 3D补根对象目录顺序的作者状态，纳入快照、保存、恢复和历史；不更改对象空间变换。组内及根目录用同一意图提交逻辑。若该状态尚未接通，UI 应明确禁止根节点前后排序，不能显示成功却只脱组。
4. 两端使用同一拖放会话生命周期：开始时冻结实体 ID / 来源，移动时计算有效目标，提交时再次验证当前实体和锁定状态；Esc、dragend、失焦、页面切换清状态。非法外部 text/plain 不应被当作内部图层拖动。
5. 3D离散组织命令建立明确事务边界，连续两次拖放必须能撤销两次；保留连续变换手势原有合并机制。不要简单去掉整个历史系统的 debounce。

建议文件职责：`layerDropIntent.ts` / `.test.ts` 承担纯合同；2D adapter 从大控制器抽出；3D adapter 复用组织命令。行交互模块只负责命中区域、提示、会话和提交，不再另建数据仓库。

3D 使用 Set 替代两次逐项 includes，复杂度从 O(n×m) 降为 O(n+m)。2D 缓存只复用预览原因和落点对象，每次仍以 O(n+m) 校验 id、zIndex、锁定、组归属和选择列表；这些字段即使原地变化也会失效重新计算。实际 drop 仍经控制器重新构造并校验命令。重复相同预览复用同一对象，也避免无变化的 React 状态更新。

三项专项测试验证顺序一致、同数组锁定 / 排序 / 分组 / 选择变动失效及缓存对象复用。上述数值是本机纯逻辑样本，不代表页面帧率或端到端拖放耗时；万行实际滚动 / 拖放仍待浏览器验收。
