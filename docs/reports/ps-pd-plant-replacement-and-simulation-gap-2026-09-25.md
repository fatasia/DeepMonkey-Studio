# 面向 PS/PD/Plant 平替的能力缺口分析（2026-09-25）

## 结论

Deep Monkey Studio 已经具备 3D 场景、工业对象、场景绑定、轻量离散事件仿真、工位/机器人验证、虚拟调试入口、PPR/BOP 与统一 Study 的基础。它现在更像“数字孪生编辑器 + Plant Lite 仿真纵向切片”，还不是西门子 PS/PD/Plant 的全面替代品。

西门子对应的是三条相互连接的产品主线：

- **Plant Simulation**：工厂/物流离散事件建模、实验设计、优化和统计分析；官方页面明确包含瓶颈、吞吐、资源/缓冲利用率、能耗、成本、Sankey、甘特图和实验/遗传算法优化。[Plant Simulation](https://www.siemens.com/en-us/products/tecnomatix/plant-simulation-software/)
- **Process Simulate（PS）**：机器人与工位级 3D 过程验证、运动规划、碰撞、节拍、OLP、PLC/虚拟调试和多机器人同步。[Process Simulate X](https://www.siemens.com/en-gb/products/tecnomatix/offerings/process-simulate-x-standard/)
- **Process Designer / Teamcenter Manufacturing（PD）**：MBOM、BOP、BOE、工艺顺序、资源分配、工时/线平衡、变更影响和电子作业指导书。[Teamcenter Manufacturing](https://www.siemens.com/en-gb/products/teamcenter/solutions/manufacturing-process-planning-data-management/)

因此“全面平替”不能按功能清单逐项堆页面，必须完成 **同一产品/工艺/资源数据贯通 → 可运行仿真 → 3D/机器人验证 → 变更管理 → 证据与发布** 的闭环。

## 现状核查

### 已有（不重建）

1. `@bim-studio/factory-flow-plugin`：Source/Process/Buffer/AGV/Sink 的轻量确定性 DES，运行/暂停/倍速/复位，吞吐、周期、WIP、利用率、瓶颈。
2. `@bim-studio/plant-lite-simulation`：多品种、生产订单、班次、故障/维修、换型、资源池、队列/阻塞/饥饿、预热、重复实验、95% 置信区间、质量、能耗、校准、轨迹和取消限制。
3. 场景仿真面板和场景绑定：仿真实体随场景保存，稳定 ID 引用，断链诊断，场景内运行与 Study 记录，已有轨迹/时间线桥接。
4. 工位/机器人、虚拟调试、物理运行时、AGV 运动、PPR/BOP/Operations 和工业 Study 体系已有代码、合同或测试证据。
5. 工业格式和资产链路已有统一转换任务、质量报告、源文件哈希、坐标帧、GLB/点云/Tiles 产物审计，以及 JT/X_T/RVT/点云/3D Tiles/3DM/SolidWorks 的分阶段计划。

### 真实缺口

现有文档已经明确：场景内物流闭环仍缺连续 AGV、多车调度、完整空间热力；SIM-1b/c/d（工位深度、虚拟调试深度、What-if/PPR 入口）未整体完成；`factory-flow-plugin` 明确不包含 PLC/MQTT、排产优化、碰撞/物理、置信区间和 Plant Simulation 全量对象库。上述内容不能重复建设，但必须作为缺口继续补齐。

## “具备仿真能力”必须拆成四层

1. **几何仿真**：碰撞、运动学、关节、连续路径、动力学近似、人员/机器人安全；服务于 PS/虚拟调试。
2. **过程仿真**：离散事件、物流、班次、故障、质量、能耗、成本、订单和资源；服务于 Plant Simulation。
3. **控制仿真**：PLC/机器人程序、IO、状态机、通信、故障注入、时序回放；服务于虚拟调试。
4. **决策仿真**：方案实验、优化、敏感性、统计置信和数字线程；服务于 PD/管理决策。

当前第 2 层已有可用内核，第 1 层有基础，第 3/4 层有入口和局部合同；要形成产品级替代，必须把四层统一到同一时钟、稳定对象 ID、版本化 Study 和证据报告。

## 建议的交付顺序

### P0：先形成可卖的“生产线仿真闭环”

- 冻结统一 `Product / Process / Resource / Scene / Study / Result` 合同。
- 把 Plant Lite 接入 Worker/服务端批量运行，补模型校验、资源限制、恢复和黄金样例。
- 完成多 AGV、输送/缓存/资源预约、死锁与跨域事件交接。
- 完成实验矩阵、方案对比、置信区间、瓶颈/队列/能耗/成本报告。
- 让仿真结果能回写场景对象、时间线、告警和 Study 证据。

### P1：补齐 PS/虚拟调试的工程价值

- 统一机器人运动学、碰撞对、轨迹/节拍、工具和坐标系。
- 接入控制器/PLC 仿真协议，先支持 OPC UA、虚拟 IO 和确定性时序回放。
- 做工位安装验证、信号故障注入、碰撞/可达性/安全区报告。
- OLP 先以少数机器人品牌和可审计后处理 profile 试点，不能先宣称通用。

### P2：补齐 PD/PPR 和企业级数字线程

- EBOM/MBOM/BOP/BOE 关联、变更影响、配置/变型和线平衡。
- 工时标准、作业指导书、版本审批、发布到执行端。
- 统一权限、审计、项目复用、结果签名和跨团队协作。

### P3：做“替代优势”而不是盲目复制

- 浏览器/桌面一体化、场景内快速建模、AI 辅助生成和解释、开放 API、离线运行、轻量部署。
- 以真实产线基准证明建模时间、实验时间、发布时间和问题发现率优势。
- 不把完整 CAD 内核、所有机器人品牌、所有行业库和认证级动力学同时列为首期承诺。

## 不能用来宣布“全面平替”的证据

- 有一个 3D 播放动画；
- 有吞吐/WIP 卡片但没有重复实验、置信区间和可复现输入；
- 有碰撞检测但没有运动学、轨迹、控制器时序和证据；
- 有 BOP 表格但没有 EBOM/MBOM/BOE 关联和变更传播；
- 文件能显示但只是 preview/inspect，缺少几何、结构、属性和交互质量证据。

## 最小可行的“平替版本”定义

首个可对外承诺的版本应限定为：**离散制造和物流场景的 3D 生产线仿真 + 多 AGV/资源调度 + 工位碰撞/节拍验证 + 基础 PLC 虚拟调试 + MBOM/BOP 轻量关联 + 可复现实验报告**。先把这条链做成真实客户可用、可审计、可恢复的闭环，再扩展到全行业对象库、通用 OLP 和完整 PLM。
