## F-1 真缺陷与根因修正

### R1 请求重试

**已完成：限定只读恢复、管理目录持久错误与手动重试；不做无差别自动重试。**

审计基线的 `packages/server-sdk/src/serverClient.ts` 没有 502 / 503 全局重试；401 已有独立会话复核，多个页面已有显式重试。因此并非从零建设全局容错：新增 SDK 默认关闭的 `retryRead` 白名单，Web 仅为明确编辑入口的目录和快照读取开启。JSON/local 客户端与只读交付运行时不自动开启此策略。

- 仅 GET / HEAD、无请求体时允许一次自动重试；条件是 502 / 503 / 504 或 fetch 网络 TypeError。默认等待 500ms，Retry-After 最多 2000ms；更长让既有错误/手动恢复接管，不违背服务器等待建议。
- 401 / 403 / 404 / 409 / 429 / 500、业务错误、成功响应后 JSON 解析失败不重放。写入/发布/恢复/导入从不自动重放；Abort/超时停止，令牌或服务 Origin 改变不再向旧身份继续请求。
- 保留 HTTP status/body，非法错误正文 null / array / number 也得到可靠 HTTP 错误；快照 RequestInit 防止等待期间调用者把 GET 改成写入。取消计时器和失败响应流，不无限循环。
- `api.ts` 的原二次401编排提取到 `authenticationRecheck.ts` 并注入统一传输，避免新增能力后突破800行；同token明确二次401才过期，网络/5xx仍保留会话，不新增认证端点或存储。
- 真实截图进一步检出原最终失败只显示5秒toast、页面却宣称“还没有场景”。管理项目/场景/应用三条目录现统一区分 loading / ready / error，最终错误持续显示 HTTP 状态和“重新读取”，不出现假空态或创建引导；响应按身份/项目/请求代次接收，取消迟到读取，显式重复重试合并。新建项目显式重试清旧错误并防双写，成功不再残留旧失败。

报告“统一 502 / 503 静默重试”不能原样落地：创建、发布、恢复、模型导入等写操作可能服务端已经生效，自动重复会引入重复对象 / 版本。若继续，应限定幂等 GET / HEAD、有限次数、取消信号、请求身份 / 项目切换与恢复反馈；写操作先明确结果查询或幂等合同。502 并不能证明“服务重启中”，文案应基于可证实状态，避免假诊断。
