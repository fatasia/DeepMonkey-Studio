## 已完成：真实性复核与根因

- 测试对象为本机已审核的平行机械夹爪 GLB（Sketchfab `71df42c5d5964d2ea149c5513bbc061b`），不使用放大替代品；导入前后核对原文件 SHA-256，场景缩放始终为 1。

- 放大后发现第二个真问题：默认方向光 target proxy 的 0.4 m 尺寸下限产生覆盖整个视口的蓝环。清除模型选择仍存在，排除了 TransformControls。修复后标记恢复为小尺寸；近景固定米级网格淡出，模型尺寸与物理网格步长不变。
- 第一批新相机截图中另发现亮色资产树白底浅字、顶部深浅混搭；已反馈同族样式修复，不将相机数值通过当作页面审美通过。

## 已完成：门禁测试设计校正

新增入口：`node apps/web/scripts/gate-camera-framing.mjs`。独立临时项目、独立 API/端口/浏览器，正常 UI 登录，不读取浏览器凭据，不访问或修改正常业务项目。

测试过程中发现并修正的是门禁脚本自身的问题，不计入产品缺陷：

1. 刷新默认恢复场景层级模式，脚本必须通过真实按钮切回模型列表，不能等待不存在的模型列表按钮。
2. 工具栏“选择”只切换导航模式，不等于“清除选择”；改用场景树已有明确操作。
3. 公开应用合同是 `publication.document`，不是 `application`。
4. 动画姿态的当前包围盒不等于 GLB 静态 rest pose。通过真实 UI 暂停模型动画后，用可见/隐藏截图差分断言实际轮廓，静态源包围盒投影只保留为参考。
5. 显示/隐藏是实际场景编辑；检查后恢复可见并再次保存，断言相机及模型状态与检查前完全一致，防止测试自己制造未保存草稿。

作者取景断言保持不变：实际轮廓最长边占视口 **25–95%**，距四边至少 2 px，可见差分像素占比大于 0.5%。覆盖显式导入、双击聚焦、适应全部、六视图、保存及刷新。

公开页验收遵守当前合同：相机及模型快照精确保留、原模型包围盒完整可见、真实夹爪红/绿/蓝机械件都有像素证据、匿名零写请求、原 GLB 哈希不变。**不隐式 fit，也不把跨比例后的 20.36% 占屏说成达到 95% 视觉水位。**

## 本轮待办：当前合同之外的明确缺口

- **跨宽高比保持构图**：470×948 作者视口的相机原样用于 16:9 公开画布，模型相对画面会变小。需要显式的“保留镜头/保持构图/自动适配”产品策略，不能为了门禁擅自覆盖作者相机。
- 聚焦飞行曲线、reduced-motion、侧视照明观感及交互时延专项继续属于主线待办，不因取景门禁通过而自动关闭。
- 当前验证通过 UI 暂停动画，仅验证该稳定姿态；不代表全部动画姿态包络均已验收。
- 不以本批固定模型证据替代所有格式、所有尺度、设备性能及完整渲染管线的全局验收。
