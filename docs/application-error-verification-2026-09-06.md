# R2 页面异常兜底：限定验收

状态：已完成本批 React 树渲染 / 应用模块启动错误的手动恢复路径；不代表全部网络、异步错误或全站验收完成。

## 真实性与实现

原 `main.tsx` 只有异步 bootstrap.catch；React 树在 render 内抛错并不进入该 catch。已有 CodeEditorBoundary 只保护代码编辑器，不是根边界。GLM R2 对根渲染错误的建议属真实缺口；Vite 模块失效的历史具体触发原因未独立重演，不能全部归因于 React。

新增 ApplicationErrorBoundary，统一作者工作台、公开应用、只读交付入口的根包装。启动失败使用同样的安全提示。只提供用户主动“刷新当前页面”，保留 URL 路径 / query / hash，不自动刷新、不清理本地副本 / 项目，不将原始异常内容透传给页面。明确提示未保存修改可能不能恢复，不承诺错误前内存内容已经保存。

依据 [React 官方错误边界](https://react.dev/reference/react/Component#catching-rendering-errors-with-an-error-boundary)：捕获渲染与 lazy 组件失败，不捕获任意事件回调、异步定时器、未加载的根 JS bundle。没有为匿名页增加管理入口或权限。

## 证据

- 3 项聚焦单测：健康子树原样、恢复文案 / 无外部导航、启动与渲染错误分型。
- 首轮真实 Chrome：`application-error-3nNjez`，故障注入实际返回兜底；浅色品牌小字 4.43:1 未过，亲审后改为 text 令牌。另修公共硬编码 focus 圈泄露以及小号说明字。
- 第二轮 `application-error-TJfd5x`，12 组合全过：暗1440 / 亮980 / 双主题480，各测试作者 React render、模块启动、公开应用 render；0 业务写，键盘 Tab + Enter 手动刷新同一 URL，错误详情不透出；最低文字暗 8.785 / 亮 7.319。
- 第三轮 `application-error-c98mDB`，新增英文980/480，共 **18 组合通过**；人工复核最终暗1440、亮980、双主题480与英文480布局。故障注入错误日志保留并标 expected，公开缺失 fixture 404 单列，不称“真实故障没有控制台错误”。
- 浏览器脚本 `apps/web/scripts/gate-application-error.mjs`，隔离 API / Chrome / 临时数据；没有读浏览器 token 或触碰正常项目。

## Design Read 与十维自检

design-taste-digitaltwin 影响：沿 base.css 令牌、克制的单一恢复动作；不展示原始异常墙，修浅色对比度与品牌焦点；完成 ≥2 轮截图反馈。布局参考现有工业工作台的信息层级，错误机制采用 React 官方方案，不用竞品全功能完成作比较。

| 维度 | 本批评价 | 依据 / 边界 |
|---|---:|---|
| 布局构图 | 9 | 480–1440 视口内单焦点、无裁切 |
| 令牌一致性 | 9 | 暗亮文字、表面、品牌焦点均来自令牌 |
| 排版 | 9 | 中英标题 / 正文 / 诊断分层，英文窄窗可折行 |
| 交互状态 | 9 | 仅限定错误恢复态；错误保持、键盘可达、手动刷新 |
| 动效质量 | 不适用 | 错误即刻呈现，无装饰动画或自动倒计时 |
| 3D 渲染 | 不适用 | 本组件不是 3D 场景 |
| 信息设计 | 9 | 一个主操作与一个可反馈编号 |
| 反馈即时性 | 未量化 | 已验证异常后自动出现；未做 ≤100ms 精确时序测量，不虚报 9 分 |
| 响应式与主题 | 9 | 双主题及480窄窗 / 980 / 1440；英文额外复测 |
| 语义文案 | 9 | 不保证未保存内容、不透传秘密、不跳到管理页 |

自评只描述本组件，不证明“达到 Kimi 的 95%”或超过竞品；未量化维度仍应在统一交互时序验收中补证。
