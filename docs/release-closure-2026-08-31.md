# 产品体验与发布闭环报告（2026-08-31）

## 结论

本轮冻结的软件范围已经形成可重复的产品闭环：用户可在同一项目上下文完成 2D、3D、脚本、拓扑、数据接入、AI 问数、设备诊断、物流仿真、轻量工位验证、虚拟调试、保存恢复、预览和发布；WebGL、WebGPU 优先且自动回退、云渲染和只读 Windows 场景客户端使用同一发布模型。

当前版本可以进入公司内部项目替换验证。更准确的表述是：**已覆盖并自动验收的高频数字孪生交付工作流具备替换封闭平台的产品基础**，不是已经证明在全部行业模块、超大真实项目、素材生态或多年现场可靠性上全面超过所有对标产品。性能数据来自固定工业夹具与当前机器，客户模型、现场数据和目标硬件仍需项目级签署。

## 本轮关闭的产品问题

- 2D、3D 与脚本切换回到同一横向任务上下文；脚本草稿在工作区切换和刷新恢复中不丢失，错误可定位、恢复并重新执行。
- 2D 超宽画布按主要业务内容自动聚焦，不再被孤立越界元素或装饰背景压成缩略图；仍保留完整画布检查入口。
- 脚本编辑器优先呈现代码和运行结果，设置、辅助信息与日志渐进展开；AI 草稿遵循预览、检查、确认和撤销边界。
- 3D 标签支持对象跟随、点击、关闭、会话恢复、碰撞避让与视口边缘裁切；选中标签在拥挤时保留。阴影和精灵透明写深度规则已统一，避免遮挡和重影污染。
- 拓扑闭环覆盖节点创建、连线、属性、保存、刷新恢复和插入看板；2D、3D、脚本、拓扑都进入真实浏览器回归。
- Plant Lite、What-if、工位验证、物流仿真和虚拟调试归入统一 Study：保存权威输入、场景/模型引用、版本、基线谱系、结果指纹、复现入口和 3D 定位。场景存在歧义时不猜测绑定，避免生成伪谱系。
- AskData 已使用真实连接器和数据集走通查询规划、执行、分组聚合、结果表与证据指纹；未知字段、歧义和越权仍由确定性规则阻断。
- 资源治理采用“定义—版本—依赖—实例覆盖—废弃”轻量模型；环境、材质、模型资源可检索、预览、应用、保存和刷新恢复。
- 本地与生产部署均不使用 Docker；本地脚本可一键启动服务和客户端，生产脚本可检查 PostgreSQL 与 MinIO、备份、沙箱恢复和轮换密钥。只读场景客户端的正常浏览不依赖 Python、Node、PostgreSQL 或 MinIO。

## 发布与部署结论

四种交付路径已经使用同一项目发布模型：

1. WebGL：兼容发布。
2. WebGPU 优先：先真实请求适配器，不支持或初始化失败时稳定回退 WebGL。
3. 云渲染：保留独立交付选项和故障提示。
4. Windows 场景客户端：只包含发布后的浏览场景，可从配置文件修改服务 IP/接口；资源可内置，不要求始终在线加载编辑器。

生产环境使用 PostgreSQL 与 MinIO；本地离线开发使用本地存储和可选同步。弱网重试、断线状态、恢复与冲突不能静默覆盖。已生成服务账号和轮换后的密钥文件，但当前已运行的旧开发 API 进程只有重启后才会读取新凭据；重启后应再次执行 `pnpm deploy:cloud:check`，再停用旧基础设施账号。密钥内容不得进入日志或文档。

## 已接受的 Windows 验收边界

当前宿主未启用 Windows Sandbox，执行进程也没有管理员权限；MSI/NSIS 是 per-machine 包，因此无法在本机真实完成“干净安装→同升级码覆盖升级→配置保留→卸载→故障恢复”。本轮完成了安装包构建、管理镜像解包、包内程序启动、升级元数据与原生配置/恢复自动测试，但没有把这些等同于干净机器生命周期。

仓库仍保留以下可选验收脚本，后续具备环境时可以执行：

```powershell
apps/desktop/scripts/verify-windows-install-lifecycle.ps1
```

脚本要求两个不同版本 MSI，拒绝在已存在产品安装的污染机器上运行，并输出安装、启动、升级、配置保留和卸载证据。2026-08-31 用户明确决定略过该项，因此它不再是本轮发布资格或目标完成条件；报告继续保留“未执行”事实，避免把构建、解包或包内启动冒充为真实安装生命周期。

真实客户资产、客户数据源、现场网络和目标硬件的演练属于具体项目上线资格，也不能用固定夹具冒充。JT、X_T/X_B 等工业格式的真实转换验收、电池模型正式上线以及 PINO/PINN/TwinMoE 生产证据已由用户明确排除，不列为本轮缺口；现有路由和安全阻断保持不退化。
