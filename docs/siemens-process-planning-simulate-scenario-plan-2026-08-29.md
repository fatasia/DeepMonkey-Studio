# 西门子 Process Designer / Process Simulate 高价值场景取舍

评估日期：2026-08-29  
评估对象：当前工业数字孪生、虚拟调试、2D/3D 与插件式 AI 底座  
产品原则：绝对易用、结果可信、能力轻量；不建设通用机器人离线编程平台或完整 PLM。

## 1. 结论

西门子 PSPD（本文按 Process Designer + Process Simulate 理解）最值得借鉴的不是功能数量，而是把以下对象放进一条可追溯的制造 Study：

```text
工程对象 → 工艺/动作序列 → 空间与时序校验 → 虚拟调试
       → 失败定位与优化 → 评审/版本/证据 → 变更后复验
```

当前项目已经具备 2D/3D 对象、稳定标识、脚本、确定性虚拟调试、预测维护、AI 能力注册和证据合同，因此可以低成本形成有竞争力的子集。首版只做三项：

1. **AI 工位体检**：自动盘点设备、工具、动作和绑定关系，生成必要碰撞对、可达性/间隙检查计划，并把问题定位到 3D 对象。
2. **虚拟调试测试生成与解释**：从信号、脚本、动作和故障假设生成黄金测试；失败后定位首个异常信号、对象和脚本行，并给出可执行修复草案。
3. **轻量验证任务卡**：只保存验证对象、目标、验收条件、来源证据、最近结果和指纹，让诊断、3D 定位和虚拟调试可以刷新恢复并复验。

工程变更影响、2D/GeoJSON 布局校验继续增强现有功能，但不并入首版任务卡。机器人作为轻量工位验证插件列入计划，只覆盖机器人/工具识别、关节链、可达域、目标点可达性、必要碰撞对、简单路径预览和粗略节拍；人体工效保持实验插件。所有能力只作为 3D、脚本和虚拟调试的上下文操作，不增加一级导航。

事实依据来自西门子官方公开资料：Process Simulate 覆盖装配、机器人、虚拟调试、连续制造和人体仿真；2026 年 AI Copilot 已公开机器人/工具盘点、碰撞对、可达性、错误诊断和节拍优化；Tecnomatix 2606 进一步公开 AI 工具目录、2D 草图到 3D 布局、自动路径、资产库和协作改进。Process Designer 的公开资料较旧，只用于理解过程规划方法，不把旧页面当作当前版本承诺。

## 3. 推荐产品形态

### 3.1 一张验证任务卡，而不是 Study 平台

新增轻量 `IndustrialValidationStudy`，本质是一张可以恢复和复验的任务卡：

| 字段组 | 最小内容 |
| --- | --- |
| 对象 | 项目、场景和设备对象引用 |
| 目标 | 一句话验证目标和验收条件 |
| 来源 | 维护评估、AI 诊断或人工创建的引用 |
| 结果 | 待运行、通过或失败；最近证据指纹和完成时间 |

不建立工艺树、任务层级、通用本体、审批流、甘特图或独立 Study 管理中心。后续需要方案对比时，也只比较两张任务卡的确定性结果。

### 3.2 零学习成本入口

- 在 3D 选择工位/设备后显示“检查此工位”，AI 自动预填范围和检查项。
- 在脚本诊断、预测维护和发布校验结果中显示“创建验证”，沿用当前对象和证据，不要求重复选择。
- 在 AI 助手首页提供三个情境快捷动作：`检查当前工位`、`为故障生成测试`、`分析本次变更影响`。
- 结果直接叠加在 3D：红色表示确定失败，琥珀色表示风险，灰色表示数据不足；点击 finding 返回对象、信号或脚本行。
- 应用 AI 建议前只展示一次“变更摘要 + 校验结果 + 应用/取消”，应用后进入现有撤销栈。
- 低频的人体工效、路径规划和专用工艺放入 Study 的“更多分析”折叠区或插件中心。

### 3.3 插件式能力边界

首批只保留三个稳定能力，不把算法写入页面：

```text
manufacturing.collision.plan
commissioning.test.generate
commissioning.failure.explain
```

AI 负责把自然语言和当前上下文转换为上述能力的结构化输入，并解释确定性结果。碰撞、可达性、时序、信号断言和版本差异由程序计算；数据不足时必须返回缺失项，不能由大模型补造结论。

## 4. 分期方案与验收证据

### P0：直接增强现有工作流

1. 建立 `IndustrialValidationStudy` 最小合同和持久化，只保存对象、目标、条件、来源与最近结果。
2. 把当前维护诊断 → 虚拟调试草案升级为可保存、可复验的任务卡。
3. 实现 AI 工位体检：对象/动作/信号清单、断链和必要碰撞对建议。
4. 实现调试黄金测试生成、首故障定位和结果回写 3D/脚本。
5. 变更影响与 GeoJSON 布局校验分别增强现有发布校验和设备布局，不耦合进任务卡。

P0 验收必须有一条真实浏览器流程：选择工位 → 一键检查 → 3D 定位问题 → 生成验证 → 运行/失败解释 → 修复并复验 → 导出证据。刷新后上下文、版本和结果仍可恢复。

### P1：形成可量化优化能力

1. 工艺操作序列与前置关系；计算关键路径、等待、资源冲突和瓶颈。
2. 轻量机器人插件：识别机器人与工具，配置品牌无关的基础关节链，计算可达域、目标点可达性、必要碰撞对、简单路径预览和粗略节拍。
3. 基于确定性约束的布局/序列候选生成与 A/B Study 对比。
4. Study 批注、问题责任人、方案版本和轻量评审状态。
5. Unity 商业插件适配层承接高精度 CAD、机器人或专用物理结果，并回传统一 Study 证据。

P1 的“优化”必须给出基线、候选、约束、改善量和退化项；没有可复算指标时只称建议，不称优化结果。

### P2：按客户证据启用

- 人体姿态与工效风险筛查。
- 焊接、喷涂、涂胶、柔性电缆和视觉抓取等行业插件。
- 商业控制器、机器人品牌 OLP、PLC/HIL 适配。
- 成本、报价和复杂工艺变体；仅在确有客户需求时建设，不扩张为 PLM。

## 5. 明确不做

- 不复制西门子完整机器人品牌、控制器和离线程序下载矩阵。
- 轻量机器人插件不生成可直接下发的控制器程序，不宣称替代 OLP，也不连接真实机器人。
- 不宣称替代 Process Simulate、SIMIT、Teamcenter 或认证级工业仿真。
- 不因“AI 能生成”而绕过几何、物理、时序和信号验证。
- 不新增复杂目录树；设备、工具、区域、标签、动作仍在单层场景对象中，通过类型筛选。
- 不把 BIM 做成编辑器；BIM 继续作为工程资产、空间、属性和证据定位底座。
- 不降低模型视觉质量；分析代理几何与展示模型分离，用户看到的模型保持原始效果。
