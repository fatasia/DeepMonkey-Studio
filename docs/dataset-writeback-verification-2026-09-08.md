## 已完成

### 合同与实现边界

- `packages/contracts/src/dataWriteback.ts` 定义字段、配置、快照及校验。支持字符串、数字、布尔、日期，必填、数值上下限、长度及选项；服务端拒绝未知字段及非法值。
- `apps/api/src/dataWritebackService.ts` / `dataWritebackRoutes.ts` 复用已保存的数据集、HTTP 连接、服务端凭据和受控出站请求。浏览器不提供临时目标 URL 或凭据。
- 记录接口为 `GET/PATCH /api/projects/:projectId/datasets/:datasetId/records/:recordId`。上游必须返回直接 JSON 对象、强 ETag，并原子执行 `If-Match` 条件更新；缺少这些能力不伪报成功。
- `PATCH` 携带 `expectedVersion`；冲突返回 409。发出写请求后的断线、超时或不可确认响应标记 `outcome: unknown`、`retryable: false`，不自动重放。读回由用户确认采用或重新核对后提交，避免已落库的请求重复执行。
- 项目权限、viewer 禁写、管理员配置权限在后端执行；未修改配置的保存请求省略 `writeback`，显式关闭才传 `null`，避免普通编辑误删配置。
- `DatasetWritebackConfigFields` 负责配置，`DatasetWritebackPanel` / session / draft cache 负责记录编辑和恢复。刷新后恢复草稿仍须核对服务器版本，不把旧缓存当最新记录。

### 真实链路断言

门禁通过真实页面配置 HTTP 连接和数据集，不直接注入填报配置。隔离 HTTP 服务实际保存记录并维护 ETag / PATCH 次数；不是拦截浏览器请求后返回虚构成功。

1. 管理员从数据中心配置记录路径、数字字段与 0–100 范围，保存后 API 配置一致。
2. 读取值 7；输入 101 拒绝提交、上游写入次数为 0；输入 12、检查并确认后真实落库，再 GET 为 12。
3. 刷新后配置及记录仍在；未提交草稿 25 刷新恢复，并要求先重新核对。
4. 上游并发修改为 30；旧版本提交返回 409，草稿 25 保留，比较区展示 25 / 30，写入次数不增加。明确保留修改并重新确认后才写为 25。
5. 上游收到 40 后落库并断开连接；页面标记未知结果、禁止直接重发。刷新仍保留待核对状态；重新读取并采用 40，全程上游写入次数保持 3，没有自动重放。
6. 第一轮深色另走 viewer 登录、读取与禁用操作；直接 PATCH 返回 403，记录保持不变。跨项目与配置越权由 API 聚焦测试覆盖，不冒充四组都执行完整权限浏览器矩阵。

四组均无页面异常或意外控制台错误。每组各有一条**预期故障注入**的 409 和 502 网络错误，原样记录于 `expectedNetworkErrors`，不称控制台绝对无错误。
