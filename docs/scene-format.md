# 场景文件

Industrial Studio 支持两种可重新编辑的场景交换方式，二者都使用 `schemaVersion: 1`；另提供面向交付的 GLB 几何导出。

## 零散文件：`.scene.json`

JSON 只保存场景编排状态：模型引用与来源标识、整模和内部图层变换、锁定、显隐、用户明确设置的颜色覆盖、透明度、场景级删除、碰撞开关、爆炸模式、剖切盒/剖切面、相机与漫游模式、小人显隐、相机/模型关键帧、测量、标签标记、基础元素和当前选择。模型自身的多材质不会被首个材质颜色覆盖；旧版 `color` 字段仅兼容读取而不再作为整模覆盖色，新的整模覆盖保存为 `colorOverride`。

模型几何、纹理和原始 RVT/IFC/FBX 等文件不写入 JSON。导入时优先按模型 ID 绑定；ID 不存在时按“源文件名 + 源格式”绑定。因此它体积小，适合同一资源库内备份、版本管理和共享配置，但不是完全可移植文件。

## 单文件：`.bimscene`

`.bimscene` 是 ZIP 容器，包含：

```text
package.json
scene.json
models/
  001-model.glb
  002-structure.ifc
```

导出时打包当前场景用到的“可浏览几何资源”，而不是强制塞入原始 RVT。导入时会解包并把缺失资源上传到目标项目，然后重建模型 ID 映射和场景状态。它适合离线交付、跨项目迁移和归档。

外部 `.bin`、贴图依赖不确定的零散 `.gltf` 不允许打包；请先转成自包含的 `.glb`。当前包内不包含 RVT 原始文件、转换日志或模型历史版本。

## 几何单文件：`.glb`

“GLB 单文件”会把当前已加载且可见的模型和基础元素合并到一个标准 GLB，保留对象名称、层级和当前变换，隐藏或已删除的对象不会导出。普通 GLTF/GLB/FBX 模型保留可导出的材质；IFC Fragments 会先重建完整网格再导出为中性材质，避免只导出约 1 KB 的空根节点。它便于交付给其他 Three.js、Unity 或通用 glTF 工具。

GLB 只承载三维几何与材质，不保存 Industrial Studio 的相机、标尺、标签、碰撞开关、剖切配置、场景资源引用等编辑状态；需要继续完整编辑时应使用 `.scene.json` 或 `.bimscene`。

## 浏览与发布

任何已保存场景都可通过 `/view/:sceneId` 直接只读浏览当前保存版本，不需要先发布。“发布”会复制一份独立场景快照供交付浏览，编辑器中的后续修改不会自动改变发布版；重新发布才会更新 `/published/:sceneId`，撤回发布不会删除编辑场景。场景管理中心显示发布状态和发布时间，并提供当前版浏览、发布版浏览、重新发布及撤回操作。

## 路由

管理中心为 `/manager`，编辑器为 `/studio/:sceneId`，当前版浏览为 `/view/:sceneId`，发布版浏览为 `/published/:sceneId`，模型优化器为 `/optimizer`。开发服务器已支持直接访问；生产 Web 服务器需要把这些前端路径回退到 `index.html`，API 和 `/assets/` 路径仍按原路径转发。
