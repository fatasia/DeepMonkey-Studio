# 生产 AI 数据接入能力矩阵

## 文档状态

- 日期：2026-08-31
- 范围：视觉、电池、设备预测维护、问数、仿真/虚拟调试、机器人工位、参数化 AI、工业诊断
- 判定原则：只把代码中已存在且有真实调用链的能力标为“已支持”；连接器存在但业务能力没有绑定时标为“未闭环”
- 目标：生产数据只接一次，经统一数据集、字段映射、质量门禁和证据合同供多个 AI 插件复用；模型插件不自行持有数据库、消息队列或现场协议凭据

## 一、结论

当前数据接入底座的覆盖面已经较广，但生产闭环并不均衡：

- **已形成统一数据集闭环**：自然语言问数、电池 SOC/SOH/RUL、设备预测维护评估。
- **已有专用生产入口**：视觉图片/视频上传、实时流接入、预览和视频抽帧推理。
- **已有轻量运行策略**：统一 AI 数据绑定已持久化，预测维护已按绑定状态、周期、窗口、质量门禁和失败退避运行。
- **只消费上游结构化结果**：设备证据诊断、告警根因分析。它们能稳定推理，但尚未自动从统一数据集编排告警、异常和维护历史。
- **当前以设计态数据为主**：虚拟调试、机器人工位、参数化 AI。已有场景/信号/字段引用，但缺少统一的运行取数、触发、回放和结果回写闭环。
- **连接器覆盖不等于实时运行时**：Kafka、MQTT、WebSocket 等当前采用有界采样读取；OPC UA 等现场协议当前采用按需读取。尚不能宣称具备持久消费、断点续传、订阅恢复和长期特征窗口能力。

因此，下一步不应继续为每个模型单独增加驱动，而应补一条轻量统一链路：

```text
连接器 / 专用媒体入口
        ↓
统一数据集 + 字段/实体映射 + 质量状态
        ↓
AI 数据绑定（窗口、触发、特征映射、运行版本）
        ↓
插件能力（模型只接收有界快照或媒体帧）
        ↓
证据、结果、建议动作
        ↓
平台记录 / 数据产品 / 经确认的设备命令
```

## 二、统一数据底座的实际覆盖

### 2.1 已有读取适配器

以下 32 类来源已进入 `BUILT_IN_DATA_CONNECTORS`，并可通过数据集预览合同返回最多 100 行有界快照：

| 类别 | 已实现来源 | 当前读取方式 | 生产口径 |
| --- | --- | --- | --- |
| 关系型与分析数据库 | PostgreSQL、MySQL、MariaDB、TiDB、Doris、StarRocks、SQL Server、Oracle、TDengine、ClickHouse | 只读查询 | 适合按需推理和短窗口取数；不是批量训练或数仓任务 |
| 文档、检索与时序 | MongoDB、Elasticsearch、InfluxDB、Prometheus | 集合/索引/Flux/PromQL 查询 | 可作为设备、事件和监控指标来源；当前统一截断为有界快照 |
| 文件 | CSV、Excel | 从配置的 HTTP(S) 文件地址读取 | 可预览；尚无原生对象存储目录选择、版本锁定和增量摄取 |
| API 与消息 | HTTP、WebSocket、MQTT、Kafka、AMQP | HTTP 拉取或短时订阅/采样 | 已能连通和取样；尚不是常驻流处理任务 |
| 现场与网络协议 | OPC UA、Modbus、BACnet、S7、EtherNet/IP、SNMP、TCP、UDP、串口、CoAP | 点位读取、寄存器读取或短时采样 | 适合调试、预览和按需模型运行；持续订阅与边缘缓存未闭环 |
| 仿真 | Simulation | 可复现模拟数据 | 适合开发、回归和故障注入，不得冒充生产实测数据 |

事实依据：`packages/contracts/src/data.ts`、`apps/api/src/dataIntegration.ts`、`apps/api/src/dataIntegrationPreviewAdapters.ts`。

### 2.2 已有统一 AI 快照合同

`readAiDataset` 已实现以下边界：

- 按项目和数据集校验连接存在且已启用；
- 模型只收到标量记录和数值记录，不收到连接配置或凭据；
- 结果携带数据集、连接类型、行数、字段、采样时间和耗时证据；
- 空数据或没有可用标量字段时明确失败，不用模拟值补齐；
- 请求取消可传递到数据读取过程。

这条合同已经被电池和预测维护复用，也与问数的数据集读取边界一致，是后续所有表格/时序类 AI 的唯一推荐入口。

### 2.3 当前可靠性边界

当前已有重试、指数退避、抖动、超时和连接诊断计数，但仍需准确限定：

- 单次统一快照最多 100 行，不足以覆盖长周期特征窗口或大批量离线评估；
- Kafka、MQTT、WebSocket、TCP、UDP、AMQP 读取后即断开，没有持久消费者、偏移提交、重放游标和本地积压队列；
- MQTT 当前以 QoS 0 订阅采样，不能作为关键告警唯一来源；
- OPC UA、Modbus 等是按需点读，不是持续订阅、变化通知或本地历史库；
- CSV/Excel 数据源是 URL 拉取，不是对象存储中的受管数据版本；
- 字段类型主要来自已保存 Schema 或首行推断，缺少跨批次 Schema 漂移门禁；
- 连接诊断存在于进程内状态，尚未形成持久的运行历史与服务等级统计。

## 三、八类 AI 的当前入口与缺口

状态定义：

- **闭环**：页面入口、真实数据读取、能力执行、证据返回已连通。
- **部分闭环**：有真实入口或稳定能力，但自动绑定、调度、回放或回写仍缺失。
- **设计态**：当前主要消费用户编辑的结构化输入或场景快照，不能宣称已接生产实时数据。

| 能力 | 当前实际输入 | 可经统一数据集接入 | 当前状态 | 尚未闭环 |
| --- | --- | --- | --- | --- |
| 视觉 | 图片/视频上传；RTSP/RTMP/SRT/HLS/WebRTC/WHEP 实时源；服务端抽帧 | 视觉不走表格数据集；视觉事件可作为项目上下文 | 部分闭环 | 实时流需要 FFmpeg 与媒体网关；尚未形成摄像头凭据引用、ONVIF/GB28181 管理、长期流健康、事件推送与 Kafka 事件桥 |
| 电池 SOC/SOH/RUL | CSV/TSV/TXT；统一数据集记录；额定容量、化学体系和阈值参数 | 是，已复用所有统一数据集读取适配器 | 闭环 | 已有实体/时间字段、滑动窗口、手动/周期触发、质量门禁、正式插件路由和轻量运行历史；仍缺 BMS 字段模板、循环结束事件触发、持久流窗口与告警回写 |
| 电池多物理短时仿真 | 结构化孪生状态、工况段和路由参数 | 否，当前无数据集入口 | 部分闭环 | 需要把 BMS 状态/工况数据集映射为短时仿真输入，并把正式路由、专家分歧和提交状态写入证据记录 |
| 设备预测维护 | 请求体数值行；统一数据集的数值窗口；已部署模型制品 | 是，已复用所有统一数据集读取适配器 | 闭环 | 已有统一绑定、手动/周期触发、窗口、最少样本、缺失率、新鲜度和失败退避；成功评估保留来源证据。仍缺按设备过滤/分组、迟到与重复数据策略、持久调度游标及重启补偿；消息连接器的单次读取仍是短时采样，不是持久消费者 |
| 自然语言问数 | 项目数据集目录与字段；执行阶段读取所选统一数据集 | 是，已支持全部统一数据集来源 | 闭环 | 当前读取仍受 100 行预览限制；没有跨数据集关系、受控联接、时间范围下推和真实业务语义配置。轻量语义只做字段候选，不应宣传为完整本体 |
| 设备证据诊断 | 已完成的维护评估、模型信息、可选场景资产映射 | 间接，先由预测维护读取数据集 | 部分闭环 | 没有“一份部署绑定 → 评估 → 诊断 → 场景定位 → Case”自动编排；诊断本身不读取原始监控、工单或告警源 |
| 告警根因分析 | 资产、主告警、时间窗事件、测量异常、维护历史的结构化请求 | 否，当前由调用方组装 | 部分闭环 | 没有从告警流、监控数据集、维修/工单系统自动建立时间窗；没有实体主键映射、时间对齐、数据质量门禁和工单草稿持久化 |
| 虚拟调试 | 用户配置的初始信号、命令、故障、断言、场景对象映射 | 否 | 设计态 | 运行是确定性回放，不读取 PLC/消息流/历史数据集；缺少真实 I/O 快照导入、历史回放、录制为黄金用例、结果 Case 回写。不得直接把生产 PLC 在线信号接入测试写路径 |
| 机器人工位 | 场景对象、关节、目标、包围盒、速度和节拍参数 | 否 | 设计态 | 当前是静态包围盒、可达包络和节拍预算，不读取控制器状态、程序轨迹、关节遥测、安全 I/O 或质量结果；也不生成或下发控制器程序 |
| 参数化 AI | 用户自然语言；受限参数化 DSL；人工选择的数据集字段/设备点/仿真信号引用 | 仅保存引用 | 部分闭环 | AI 草案不读取生产数据；语义绑定能校验引用有效性，但运行时没有读取字段、缩放/单位转换、质量检查、刷新策略和参数重建触发 |
| 通用助手 | 项目运营模型、评估、Case、视觉模型/源/任务/事件、连接和数据集目录；当前场景/选择对象/脚本/仿真快照 | 问数模式可执行统一数据集读取 | 部分闭环 | 大部分来源是客户端上下文快照而非服务器执行证据；助手不能把上下文描述冒充实时数据或能力结果 |

## 四、面向生产的统一绑定合同

### 4.1 一份绑定描述所有表格、时序和消息来源

已实现轻量 `AiDataBinding`，没有新增独立数据平台：

```ts
interface AiDataBinding {
  id: string;
  projectId: string;
  capabilityId: string;
  datasetId: string;
  parameters?: Record<string, string | number | boolean>;
  status: "draft" | "active" | "paused" | "invalid";
  entity?: { keyField: string; selectedKeys?: string[] };
  time?: { field: string; order: "asc" | "desc"; timezone?: string };
  features: Array<{
    modelField: string;
    sourceField: string;
    unit?: string;
    scale?: number;
    offset?: number;
    required: boolean;
  }>;
  window: { rows?: number; durationSeconds?: number };
  trigger: AiTriggerPolicy;
  quality: AiQualityPolicy;
  quality: { minimumSamples: number; maxAgeSeconds: number; maximumMissingRate: number };
  retry: { maxAttempts: number; backoffSeconds: number };
  output: AiOutputPolicy;
  revision: number;
}
```

核心约束：

- `capabilityId` 绑定插件能力，而不是某个页面组件；同一合同可被 Web、客户端和云服务复用。
- 特征映射显式保存源字段、模型字段、单位和换算，禁止模型按字段名猜测关键输入。
- 每次更新绑定都递增 revision；后续补齐 Schema/模型版本变更时的强制重新验证。
- 推理请求记录绑定 revision、模型版本、数据证据和结果指纹，能够复现“哪批数据产生哪次结论”。
- 项目只维护一份设备/电芯/摄像头到场景对象的轻量实体映射，不建设复杂本体平台。

### 4.2 视觉使用专用媒体绑定

视觉不应强行塞入行式数据集，建议使用 `VisionSourceBinding`：

- 来源：上传图片、RTSP/RTSPS、HTTP(S) 视频/HLS（以实际 FFmpeg 探测结果为准）；
- 凭据：只保存服务端凭据引用，不把账号密码嵌入 URL；
- 运行：抽帧率、最大分辨率、超时、重连、退避、连续失败熔断；
- 绑定：摄像头/区域/场景对象、模型版本、阈值、去重窗口；
- 输出：检测事件、截图/短视频制品、场景定位和证据指纹；
- 后续适配器：ONVIF/GB28181 只在真实项目需要时作为插件加入，不进入默认核心依赖。

## 五、统一调度策略

| 触发模式 | 适用能力 | 推荐实现 | 必须具备的保护 |
| --- | --- | --- | --- |
| 用户请求 | 问数、参数化草案、临时电池分析、机器人工位审计 | 当前 Capability 调用 | 取消、超时、输入合同、只读权限、结果证据 |
| 固定周期 | 电池健康、设备预测维护、监控指标分析 | API 服务内轻量调度记录；按绑定 revision 运行 | 单实例租约、幂等键、错过任务补偿、并发上限、退避 |
| 消息事件 | 告警根因、关键设备异常、电池越限 | 消息接入先落有界事件缓冲，再触发能力 | 去重、偏移/游标、事件时间、迟到容忍、积压上限、死信记录 |
| 视觉帧 | 视频检测 | 视觉运行器独立抽帧节流 | 单源并发 1、丢帧而非堆帧、健康探测、重连、熔断 |
| 历史回放 | 虚拟调试、回归验证、机器人轨迹验证 | 从受管快照读取并使用虚拟时钟 | 不写生产设备、固定输入版本、确定性顺序、证据指纹 |

不建议把 Kafka/MQTT 的常驻消费循环塞进一次 `previewDataset`。推荐保持现有连接器为调试/即时读取，同时新增一个轻量“采集任务”边界，把持久流压缩为带游标和保留策略的受管数据快照，再交给 AI 插件。

## 六、结果与回写策略

### 6.1 默认回写

所有 AI 结果默认只写平台内部记录：

- PostgreSQL：运行记录、绑定 revision、模型版本、结构化结果、状态、告警/Case 关联和审计；
- MinIO：输入快照、视觉图片/短视频、模型制品、批量结果和可下载证据；
- 数据产品：只暴露经过 Schema 校验的结果字段，供 2D、3D、拓扑和后续问数复用。

不得把完整媒体、大数组或模型制品塞入 PostgreSQL；也不得只把关键结论存在浏览器本地存储。

### 6.2 外部系统与设备回写

当前底层写适配器只有 BACnet、S7、EtherNet/IP、串口和 Simulation。即使底层可写，AI 插件也不应直接调用写连接器：

1. AI 输出 `suggestedAction`，包含目标、值、理由、证据指纹、风险级别和幂等键；
2. 服务端根据项目角色、设备白名单、值域、速率、运行模式和双人/单人确认策略校验；
3. 用户明确确认后，由独立命令执行器调用受支持写适配器；
4. 执行前后读取点位核验，并记录请求、响应、时间、操作者和失败原因；
5. 断网、超时或状态不一致时进入“未知/待核验”，禁止自动重复危险命令。

HTTP Webhook、Kafka 结果主题、MQTT 结果主题、工单/维护系统 API 应作为后续输出适配器，不与模型推理代码耦合。

## 七、生产闭环优先级

### P0：把已有价值变成可持续运行

1. 电池和预测维护均已复用统一 `AiDataBinding`、周期执行器及轻量运行历史；后续补 BMS 字段模板、设备分组、迟到与去重策略、持久调度游标和重启补偿。
2. 增加运行记录与结果数据产品；输入/输出均携带数据证据、绑定 revision 和模型版本。
3. 为 Kafka、MQTT、WebSocket 增加持久采集任务、游标/偏移、重连、去重、积压上限和死信记录；保留现有预览器用于连接测试。
4. 为 OPC UA 和关键现场点位增加订阅/轮询任务及最后有效值、质量码、断线状态；不在 AI 模型内直接持有协议客户端。
5. 将告警根因的主告警、事件、异常和维护历史绑定到统一数据集，形成可重复的时间窗装配器。

### P1：补齐专用入口

1. 视觉源改为凭据引用，增加流健康、重连、帧节流、事件去重和场景对象绑定；视觉事件可选择写入 Kafka/MQTT/HTTP 输出适配器。
2. 虚拟调试支持从数据集导入信号轨迹、录制黄金用例和写回验证 Case，但默认保持只读生产设备。
3. 参数化绑定增加运行取值、单位换算、质量门禁和显式“重新生成”确认；数据变化不得静默重建几何。
4. 机器人工位支持导入历史关节轨迹、I/O 和节拍记录用于回放；正式控制器连接和程序下发仍保持独立、人工确认的专业扩展。

### P2：在真实项目需求出现后插件化扩展

- 受管对象存储中的 CSV/Excel/JSON/Parquet 数据集；
- 企业维护、制造执行、能源管理和时序历史系统的字段模板；
- 摄像头发现与国标视频接入；
- HTTP Webhook、Kafka、MQTT 和企业工单系统结果回写；
- 大窗口特征计算和离线评估任务。

P2 不应为了“数量”进入默认安装；只有能复用统一绑定、证据、调度和回写合同的适配器才允许加入。

## 八、验收门槛

每个 AI 能力只有同时满足以下条件，才可以在产品中标为“生产数据已接入”：

- 用户能从能力页面直接选择数据源/数据集、实体、字段映射、窗口和触发方式；
- 页面能预览真实字段与样例，并明确显示空数据、断线、无权限、字段漂移和单位不兼容；
- 运行过程支持取消、超时、重试、限流和部分失败，不阻塞编辑器；
- Kafka/MQTT 等流式来源通过常驻采集任务提供游标、重连、去重和积压边界；
- 输出包含模型版本、绑定 revision、来源证据、质量结论、限制和证据指纹；
- 结果可在平台历史中追溯，并能绑定到场景对象、Case 或数据产品；
- 任何外部回写均经过权限、值域、幂等和确认门禁；
- 断网恢复、Schema 漂移、重复消息、迟到消息、空窗口、坏字段、模型超时和存储不可用均有自动化测试；
- Web、本地客户端和云服务使用同一数据与能力合同，不能出现页面各自直连数据源的分叉实现。
