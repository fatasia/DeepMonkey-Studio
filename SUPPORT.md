# Support

Use GitHub Issues for reproducible defects and feature proposals. Use Discussions, when enabled, for setup questions, design exploration, and community help.

Before asking for help, check [README.md](README.md), existing Issues, and the relevant document under `docs/`. Include the product version or commit, operating system, Node and pnpm versions, deployment mode, expected behavior, actual behavior, and a minimal reproduction.

Remove credentials, private URLs, production data, customer models, and personal information from logs and screenshots. Security vulnerabilities belong in the private process described by [SECURITY.md](SECURITY.md).

Community support is best-effort. A response, workaround, roadmap mention, or accepted Issue is not a promise of delivery or a service-level agreement.
